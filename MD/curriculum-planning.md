# 커리큘럼 기획 가이드

새 과목이나 일차별 커리큘럼(txt)을 기획할 때 참고하는 기준입니다.
강사와 논의하며 확정한 요구 사항과, 기획하면서 중요하다고 판단한 원칙을 모았습니다.
웹페이지(HTML) 제작 규칙은 `MD/skill.md`를 따릅니다. 이 파일은 그 전 단계인 "수업 내용 기획"용입니다.
과목별 도구·계정·운영 방식은 `MD/skill.md`의 2절과 그 과목의 `MD/skills/<폴더>.md`를 기준으로 합니다. 이 가이드의 공통 예시를 다른 과목에 일괄 적용하지 않습니다. 사용자가 새로 확정한 사항이 있으면 두 문서의 관련 규칙도 함께 맞춥니다.

---

## 1. 작업 방식

- **기획 먼저, 제작은 나중에.** 새 과목은 `참고자료/<과목명> 자료/` 폴더에 txt로 먼저 만듭니다.
  - 전체 개요 1개: `<과목명> 1-8일차 커리큘럼.txt`
  - 일차별 1개씩: `<과목명> N일차 커리큘럼.txt`
- **이야기 먼저, 수정은 확인 후.** 구조를 크게 바꿀 때는 문제점과 방향을 먼저 설명하고, 강사가 정하면 고칩니다.
- **강사가 정한 "고정 요소"는 그대로 지킵니다.** 그 위에 살을 붙입니다.
- 추천안이 있으면 선택지를 나열하지 말고 하나를 추천합니다.
- **회의 먼저, 수정은 나중.** 개편은 문제 진단 → 방향 회의 → 기획 txt 초안 → 강사 확인 → HTML 제작 순서로 합니다. 강사가 "아직 코딩하지 마"라고 하면 txt·MD도 확인 전에는 고치지 않습니다.
- **판 단위로 바꿀 때는 이전 판을 보존합니다.** 새 판은 `dayNNv3`처럼 새 폴더로 만들고, 기획 txt는 `참고자료/<과목> 자료/v3/` 하위 폴더에 따로 둡니다.
- 다른 AI(GPT 등)와 회의한 결과를 받으면 그대로 반영하지 않고, 받아들일 것 / 고칠 것 / 반대할 것(고정 원칙과 부딪히는 것)으로 나눠 이유와 함께 보고합니다. 기능·서비스에 관한 주장은 공식 자료로 확인합니다.

## 2. 수강생과 수업 환경

- **대상:** 비전공 성인 초보자. 전문 용어는 쉬운 우리말로 쓰고, 처음 나올 때 한 줄로 풀어 줍니다.
- **수업 시간:** 1교시 50분 + 휴식 10분 + 2교시 50분.
  - **AI 오피스실무 v3(24시간 개편)부터는 1일 3교시**: 50분 수업 + 10분 휴식 반복, 실수업 150분. 기획서에는 "1일 3교시(교시당 50분), 총 24교시"로 적습니다.
- **학원 구조:** 수강생은 각자 자기 자리에서 개인 실습을 합니다.
  - 레크리에이션식 수업은 넣지 않습니다. (카드 뽑기, 조별 대결, 프롬프트 배틀, 투표, 반 전체가 서로 설문에 응답하기 등)
  - 발표 수업도 따로 두지 않습니다. 마무리는 과목별로 정합니다.
  - **AI 오피스실무는 과목 전체에서 평가·채점·발표·제출·강사 심사를 하지 않습니다** (사용자 확정, 항상 동일). 점수·등급·순위·진행률 숫자(예: "0/4 완료")도 표시하지 않습니다. 다른 AI가 평가 기준·배점을 제안해도 넣지 않습니다.
- **결석생도 따라올 수 있어야 합니다.** (아래 4번)

## 3. 시간과 분량

- **부족하면 안 되고, 넘치는 것은 괜찮습니다.**
- 섹션마다 예상 시간(예: `(15분)`)을 적고, 교시마다 50분이 차는지 직접 더해 봅니다.
- 초보자 기준으로 계산합니다. 메뉴 따라 하기, 붙여넣기, 권한 허용, 기다리는 시간(Deep Research 등)은 생각보다 오래 걸립니다.
- **기능 하나로 하루를 채우지 않습니다.** (예: 스킬(옛 Gem) 하나 배우는 데 2시간은 이상함 → 20분 꼭지로)
  - 하루 = 여러 개의 실제 업무 + 결과물. 기능은 업무를 처리하다 필요할 때 배웁니다.
- **한 가지 내용을 질질 끌어 시간을 늘리지 않습니다.** 시간은 다양한 꼭지를 더 넣어서 채웁니다.
- **"하루 = 주제 하나"로 딱 자르지 않습니다.** 주제는 분량에 맞게 일차를 걸쳐도 되고, 짧은 주제는 다른 주제와 한 날에 섞습니다. (예: 노래 만들기는 금방 끝나므로 하루짜리가 아님)
- 빨리 끝나는 사람을 위해 "선택 과제" / "더 해 보기"를 둡니다.
- 뒤처지는 사람을 위해 줄여서 진행하는 방법(생략 가능한 단계)을 강사용으로 적어 둡니다.
- **수업 시간이 늘어날 때** 기존 내용을 늘려 붙이지 않습니다. 반복을 먼저 걷어 내고, 실제 업무에서 빠져 있던 일로 밀도를 높입니다. 하루 분량은 150분(또는 그 과목 시간) 안에 초보자가 실제로 소화할 수 있는지로 판단하고, 독립된 흐름을 가진 큰 기능(예: 설문지 제작)은 핵심을 흐리면 시연이나 "더 해 보기"로 돌립니다.

### 반복 없이 쌓아 올리기 (빌드업) — 사용자 요구, 2026-11-18
- **이미 나온 내용을 다음 날 다시 설명하지 않습니다.** 같은 개념·기능은 과정 전체에서 **한 곳에서만 본격적으로** 가르치고, 뒤에서는 설명 없이 적용만 합니다. (예: 대상별 작성은 메일 날 한 번, 피벗·차트는 시트 날 한 번)
- 기획할 때 일차별 목차를 나란히 놓고 겹치는 개념·실습·문구를 표로 점검합니다. 같은 교훈(예: 확정·미정 구분)이 날마다 다른 옷만 입고 나오는 것도 반복입니다.
- **같은 소재를 여러 날 반복하지 않습니다.** 서로 다른 역량을 배우더라도 수강생에게는 "또 그 얘기"로 느껴집니다. (예: FAQ·회의실 예약이 여러 날 나오면 한쪽 소재를 바꿈)
- **빌드업 사슬은 설계 원칙입니다:** "어제 방법의 한계 = 오늘 배우는 이유". 수강생이 왜 이걸 배우는지 납득하게 합니다. 단, 결석 대비 규칙(4번)은 그대로 — 한계는 그날 안의 상황으로 보여 줍니다.
- 매일 같은 형식의 도입(예: 매번 "시작 상황 5분")을 공식처럼 쓰지 않습니다. 질문, 받은 메일, 틀린 결과물, 완성 예시, 업무 요청서 등으로 날마다 시작 방식을 바꿉니다.
- **검증 원칙은 한 번만 본격적으로.** "AI는 그럴듯하게 틀린다"는 한 날에 제대로 가르치고, 이후에는 그 도구에서 새로 생기는 함정 하나만 다룹니다 ("검증 사다리").

## 4. 결석 대비 — 일차끼리 내용으로 잇지 않기

- **그날 수업은 그날 안에서 시작하고 끝납니다.** 이전 수업의 결과물이 있어야 진행되는 구성은 만들지 않습니다.
- 이전 자료가 필요한 날은 **"준비 자료 (수강생 복사용)"**를 일차 파일 끝에 넣습니다.
  - 제공 방식은 **txt 내용 복사 → 붙여넣기**입니다. 강사 드라이브 공유 방식은 쓰지 않습니다.
  - 시트용 표는 탭으로 구분해서 A1 칸에 붙이면 칸이 자동으로 나뉘게 합니다.
  - 문서용 글은 해당 과목에서 쓰는 문서 도구에 붙이게 합니다.
  - "수업용 가상 자료입니다"라고 표시합니다.
- 지난 시간에 만든 자기 파일은 **"있으면 써도 됨"** 정도의 선택 사항으로만 둡니다.
- 가상 회사 설정(예: 해오름상사)은 이야기로 이어져도 됩니다. 단, **그날의 상황은 그날 처음부터 설명**합니다. "3일차에 만든 ~" 같은 문장은 쓰지 않습니다.
- "Deep Research(6일차)"처럼 앞으로 배울 내용을 알려 주는 예고는 괜찮습니다.
- 여러 일차에 같은 가상 데이터가 나오면 **숫자가 서로 맞게** 계산해서 만듭니다. (월 합계 = 품목별 합, 비율 등)

## 5. 프롬프트 실습 방식

- **복사·붙여넣기만 하는 수업은 의미가 없습니다.** 수강생이 프롬프트 구조를 보고 직접 채우고, 고치고, 빼는 연습이 핵심입니다.
- 프롬프트는 **"작성 틀"**로 줍니다. 칸은 `[무엇 — 예: 구체적인 예]` 형식으로 씁니다. 완성된 "예시"는 따로 둡니다.
- **복사용 프롬프트 안에 수업 진행 정보를 넣지 않습니다.** ("DAY 06에서 쓸 것" 같은 문장 금지)
- 초보자에게 "주제를 정해 보세요"라고만 하지 않습니다. **고를 수 있는 주제 예시를 5개 정도** 먼저 보여 줍니다.
- 키워드를 알아야 채울 수 있는 칸(카메라 거리, 조명, 구도, 음악 장르 등)은 실습 직전에 **키워드 예시 상자**로 먼저 가르칩니다.
- 비슷한 개념을 여러 개 동시에 가르치지 않습니다. 초보자에게 꼭 필요한 하나로 합칩니다. (예: 유저 플로우 + 스크린 플로우 → "흐름" 하나)
- 결과를 이어서 고치는 요청("더 짧게", "표로")을 꼭 넣습니다. 첫 답이 마지막 답이 아님을 체감하게 합니다.
- 틀린 답 줄이기 장치를 습관처럼 넣습니다.
  - "내가 주지 않은 숫자는 만들지 말고 [확인 필요]로 표시"
  - "원인은 추측이라고 표시"
  - "숫자 1~2개는 직접 검산"

### 연습 시간과 연습 문제 수준 (AI 오피스실무 v3, 사용자 확정 2026-11-18)
- **연습 시간은 지킵니다.** 새 내용을 넣으려고 연습을 줄이지 않습니다. 수강생이 3시간 내내 새 설명만 듣고 가지 않게, 매일 연습 25~30분을 둡니다. 연습이 있어야 발전한다는 것이 강사의 기준입니다.
- **문제 수는 고정하지 않습니다.** 매일 같은 개수(예: 역설계 3문제)는 또 다른 반복 구조가 됩니다. 어떤 날은 깊은 과제 1개 + 추가 문제, 어떤 날은 짧은 문제 2~3개로 바꾸고, 연습 방식(역설계, 실패한 지침 고치기, 골라 반영하기, 빈 화면에서 시작, 혼자 정리, 갱신 오류 찾기, 자료 판단)도 날마다 다르게 합니다.
- **연습 문제에는 복사해서 쓰면 끝나는 프롬프트를 주지 않습니다.** 프롬프트 몇 줄로 끝나거나, 내용만 보고 그대로 입력하면 결과가 잘 나오는 형식은 금지합니다. 연습 문제에는 작성 틀도, 완성 요청 예시도 싣지 않습니다. (본 수업 실습의 작성 틀·채워 본 예는 그대로 둠)
- **작성 틀은 날마다 조금씩 줄인다 (2026-11-18 사용자 확정, v3 본 수업 실습)**: 1~2일차 = 완성 문장 틀([ ] 빈칸) + 채워 본 예 / 3~5일차 = 칸 이름 + 짧은 안내 [ ]만, 원래 완성 문장은 접힌 "채워 본 예"로 / 6~7일차 = 칸 이름만(흐린 안내 글자 placeholder), 예시 없음 / 8일차 = 구조만(5칸 + 하지 말 것, "하지 말 것"에만 예 하나). 칸 이름은 1일차 5칸(역할·목적·대상·조건·결과 형식)을 바탕으로 쓰고, 자주 빠지는 "하지 말 것"은 따로 한 칸으로 둔다("NO프롬프트" 같은 새 말은 쓰지 않음). 3일차·6일차 첫 섹션에 "오늘부터 작성 틀이 달라집니다" 안내를 둔다. 자료 복사 칸·데이터 준비용 요청은 예외.
- **분량은 항상 넉넉하게 (2026-11-18 사용자 확정, 모든 v3 일차 고정)**: "많으면 빼면 되는데 부족하면 답이 없다." 시간이 빠듯해 보여도 내용을 줄이지 않는다. 대신 연습 문제마다 **기본 — 먼저 이것부터 / 더 해 보기** 표시를 붙이고(기본 1개 + 나머지 더 해 보기), 연습 위에 "기본 하나를 이어서 조건까지 끝내면 충분, 시간이 남으면 더 해 보기" 안내, 맨 아래에 **"빨리 끝났다면"** 안내를 둔다. 기본 문제: 01·02·04·05·06·07 = 연습 1, 03 = 연습 2. 08은 각 과제 끝 "빨리 끝났다면 — 더 해 보기"(① 보고까지 끝내기: Gmail 초안·[연습] 검토 일정 ② 내 일로 하나 만들기: 요청 → 확인 → 스킬 저장).
- 문제마다 안내 문구를 넣습니다: "연습입니다. 복사·붙여넣기 하지 말고 요청을 직접 쓰세요. 정답은 없습니다. 자료에 맞게 판단했는지가 중요합니다."
- 수준이 있어야 연습이 됩니다. 문제마다 아래 중 두 가지 이상을 넣습니다.
  - 자료끼리 충돌하거나 승인되지 않은 정보가 섞여 있음
  - 쓰면 안 되는 정보(소문·추측·옛 수치·구두 약속)가 그럴듯하게 섞여 있음
  - 결과를 받기 전에 먼저 판단할 것이 있음
  - 첫 결과 뒤에 펼치는 **"이어서 조건"**(작은 중간 변경)이 있어 한 번 이상 고치게 됨
- 진행 순서: 쓸 것·뺄 것·모르는 것 메모 → 요청 직접 작성 → 결과 확인 → 이어서 조건 반영 → 고친 이유 한 줄.
- 막혔을 때 도움 순서: **힌트 1**(생각해 볼 것) → **힌트 2**(요청에 들어갈 "내용"만, 문장 아님) → 강사. 요청 문장은 끝까지 제공하지 않습니다.
- 수강생 자기 파일 상태에 따라 난이도가 달라지는 연습(예: 갱신 오류 찾기)은 강사가 오류를 일부러 넣은 **공통 연습 파일**로 합니다.
- **오늘의 최소 완성 기준**: 날마다 3~4줄짜리 자기 확인 목록을 둡니다. 체크만 하고 점수·진행률 숫자로 바꾸지 않습니다. 평가가 아니라 "오늘 여기까지 하면 됐다"를 알려 주는 장치입니다.

  - 시작 프레임(첫 장면 이미지)은 실습에 씁니다. **끝 프레임(마지막 장면 이미지)은 활용이 어려워 설명만** 하고 실습에는 쓰지 않습니다.

- **이미지 생성:** 한 장 만들고 끝내지 않습니다. 같은 대상을 **여러 구도**로 만들어 보는 시간, **여러 콘셉트로 바꿔 보는 시간**처럼 변형해 보는 실습을 넣습니다.
- **메뉴 이름은 계속 바뀝니다.** 화면 안내에는 "메뉴 이름은 계정·업데이트에 따라 다를 수 있음"을 붙이고, 막히면 해당 과목에서 쓰는 AI에게 "메뉴 순서를 알려줘"라고 묻는 방법을 함께 줍니다.
- Gemini 패널(문서·시트 오른쪽)은 Pro 계정이면 보이지만, 메뉴 위치가 바뀔 수 있으니 **Gemini 앱(gemini.google.com)에서 하는 방법도 함께** 적어 둡니다.

## 7. 어렵거나 강사도 처음인 기능 (예: Apps Script)

(AI 오피스실무 v3에서는 Apps Script를 빼기로 했습니다. 아래 원칙은 다른 과목의 어려운 기능에도 그대로 씁니다.)

- 강사도 써 본 적이 없고 수강생도 어려워할 수 있다는 전제로, **쉽게 따라 할 예제 2개 정도**로 단계를 나눕니다.
  - 예제 ①은 원리를 익히는 가장 쉬운 것 (예: 나에게 메일 1통)
  - 예제 ②는 실무형 (예: 시트 명단으로 맞춤 메일)
- STEP마다 무엇을 누르는지 순서대로 쓰고, **가장 많이 막히는 곳**(권한 허용 경고 화면 등)은 따로 풀어 씁니다.
- 막혔을 때를 위한 **강사용 예비 코드**와 **"자주 막히는 곳" 표**를 넣습니다.
- 안전 장치를 넣습니다. 예: 실제 동료에게 보내지 않기, 내 주소 뒤에 `+글자`를 붙여 나에게만 오게 하기.
- "코드를 고치려 하지 말고, 무슨 일이 일어났는지 해당 과목에서 쓰는 AI에게 말하기"를 핵심 메시지로 둡니다.
- 강사에게 **수업 전에 한 번 직접 실행해 보기**를 권합니다.

## 9. 마지막 날 — 기획 연습과 선택형 개인 과제 (AI 오피스실무 전용)

- 앞부분은 자료에서 실행 방법을 정해 기획 1쪽을 함께 만든다. 뒤에서는 수강생이 상품 판매·카페 운영·사내 반복 문의 중 하나를 골라 혼자 해결한다.
- 목적은 혼자 시작하고 끝내는 경험과 성취감이다. 평가·채점·발표·제출·강사 심사는 하지 않는다. 강사는 막히는 사람을 돕는다.
- 과제 카드는 제목과 상황을 간단히 보여 준다. 선택한 과제의 요청과 자료만 펼쳐진다. 게임식 점수·등급·순위·경쟁은 넣지 않는다.
- 과제별 상황·수치·의사결정은 달라도 된다. 평가용 난이도 동등화나 강사용 정답지는 만들지 않는다. 어느 과제도 배운 방법과 제공 자료로 시작하고 끝낼 수 있게 한다.
- 자료는 한 화면에서 이해할 수 있는 소규모 가상 기록·현장 메모·실행 조건이다. 새 정리 도구나 대량 데이터 처리부터 시작하지 않는다.
- 기본 결과물: 짧은 분석 요약, 실행안 1쪽, Canvas 슬라이드 3장. 파일 공유와 요청문·검산 기록 제출은 요구하지 않는다. Google 슬라이드 내보내기와 차트 연결은 더 해 보기다.
- 모호한 요청의 확인 질문을 먼저 생각하고 요청자의 추가 설명을 펼친다. 자료에 없는 답은 미정으로 남긴다.
- 중간 변경은 초안이 나온 뒤 본인이 펼친다. 완료한 분석·기획을 수정하고 이어 만드는 슬라이드에도 반영한다. 진행 속도와 상관없이 변경 대응을 경험하게 한다.
- 막히면 힌트 1(생각해 볼 것) → 힌트 2(요청에 들어갈 내용, 접어 둠) → 강사 순서로 지원한다. 복사해서 쓸 수 있는 요청 예시는 싣지 않는다(v3 · 2026-11-18 확정). 프롬프트 창에는 빈칸 양식(비교할 것 · 찾을 것 · 결과 모양 · 하지 말 것 같은 칸 이름)만 둔다.
- 중요한 숫자 확인·근거 없는 단정 피하기·변경 반영·저장을 자기 체크한다. 체크는 점수나 심사 기준이 아니다.
- Apps Script는 선택 학습으로 보존하며, 필수 과제 완료 조건에 넣지 않는다. (v2 기준. **v3에서는 제외** — 에이전트 과목과 겹침)
- v3에서는 개인 과제 시간을 약 100분으로 늘리고, 마지막에 분석 요약·실행안·슬라이드 세 결과물의 숫자·조건이 서로 맞는지 자기 확인한다.

## 11. 과목 구분 (2026-09 기준)

- **AI 오피스실무 (구 AI실무활용):** 사무·실무 과목입니다. 이론은 1~2일차에 섞고, 나머지는 메일·회의·일정·문서·시트·슬라이드·조사·기획으로 채웁니다. 자동화는 AI 에이전트, 웹 제작은 바이브코딩, 이미지·영상은 AI 스마트스튜디오가 맡습니다 (2026-11-18 갱신).
- **AI 스마트스튜디오 (구 AI콘텐츠제작):** 이미지 기획·생성, 만화, 광고, 인스타 카드뉴스, 노래 만들기 등 콘텐츠 제작 과목입니다. (AI프롬프트엔지니어링2의 5일차 이후 내용 계열)
  - 마지막 날은 실전 과제형이 아니라 **자유 주제 제작**(광고·만화·뮤직비디오 등 골라서)입니다. 노래 만들기는 짧은 꼭지로 다른 주제와 섞습니다.
  - CapCut 편집은 중반(5일차쯤)에 배워서 뒤의 만화·뮤직비디오·자유 주제에서 계속 씁니다.
- 두 과목에서 같은 개념을 겹쳐 가르치지 않도록 과목별 역할을 나눕니다.
