# AI 강의자료 사이트 제작 스킬 (v4 · 2026-10-23)

여러 과목의 강의자료(HTML)를 모아 둔 다과목 사이트를 만들고 고칠 때 따르는 규칙입니다.
새 DAY 페이지를 만들거나 기존 페이지를 고치기 전에 이 문서를 먼저 읽습니다.
**새 과목 · 일차별 커리큘럼을 기획할 때는 `MD/curriculum-planning.md`를 함께 읽습니다** (기획 원칙 · 시간 · 결석 대비 · 도구 확정 사항).

---

## 1. 수강생과 수업의 전제 — 모든 규칙의 바탕

- **수강생**: 웹 · 디자인 · 코딩을 모르는 성인 초보자 (고등학생 ~ 성인 눈높이). 노안이 있는 분도 있으니 글씨를 너무 작게 쓰지 않는다.
- **수업**: 학원 정규 수업, 보통 8회 · 회당 1교시 50분 + 휴식 10분 + 2교시 50분, 각자 자기 자리에서 개인 실습.
- **발표 수업 · 레크리에이션(조별 대결, 투표 등)은 넣지 않는다.** 마무리는 과목에 따라 "제출" 또는 "만들어 보기"로 끝낸다.
- **시간 배분은 강사가 현장에서 정한다.** 분량이 많아 보여도 "시간이 넘친다"며 실습을 빼거나 "시간이 되면"으로 옮기자고 하지 않는다. 내용은 부족한 것보다 넘치는 편이 낫다.
- **결석 대비**: 그날 수업은 그날 안에서 시작하고 끝난다. 앞 DAY의 결과물이 필요하면 "준비 자료 (수강생 복사용)" 섹션이나 "없어도 괜찮습니다" 안내를 둔다.
- **`참고자료/`의 원본 교안은 대본이 아니라 참고 자료**다. 흐름 · 수강생 수준 · 실제 도구 동작에 맞게 순서 변경 · 병합 · 삭제 · 보강을 자유롭게 하고, 주요 변경점은 완료 보고 때 알린다.
- 구조를 크게 바꾸는 일은 **먼저 의견을 말하고, 사용자가 정한 뒤 고친다.** 선택지를 늘어놓기보다 하나를 추천한다.

- 수강생은 **n8n 유료 Cloud**를 쓴다. 무료 설치형(Self-hosted)은 학원 PC 환경(관리자 권한 · 재부팅 시 초기화 · 가상화) 때문에 **수업 중 설치 · 시연 없이** "이런 게 있다" + DAY 02 15번 "집에서 해 보기"(선택 학습)만 둔다. 설치 방법은 **Docker Desktop + `compose.yaml`(`docker compose up -d`, 포트 `127.0.0.1:5678`, 볼륨 `n8n_data`) 한 가지**로 통일하고 Node.js · `npx n8n` 안내는 쓰지 않는다. `docker compose down -v`(데이터 삭제)는 경고로만 보여 주고 실습하지 않는다. 학원 서버 하나에 설치해 계정을 나눠 주는 방식은 n8n 라이선스상 권하지 않는다.
- **Google Opal은 2026-11-17 종료.** DAY 01에서 "도구가 아니라 Node 생각 체험"으로만 쓰고, Opal이 안 되면 ChatGPT · Gemini 대화로 앞 단계 결과를 다음 단계에 붙여 넣는 대안을 쓴다.
- **「AI와 함께 문제 해결하는 기본 루틴」**(5절 (T))이 8일 전체를 관통한다. DAY 01 예고 → DAY 02 정식 소개(질문 완성 예시) → DAY 03~05 칸 이름만 → DAY 06~ 틀 없이 직접.
- DAY 04 · 06은 내용을 줄이지 않고 "수업 시간에 꼭 끝낼 것 · 못 끝내면 과제로" 상자로 구분한다 (다음 수업에 꼭 필요한 것은 Gemini · Google 연결과 Agent가 Tool을 고르는 것 확인뿐).
- 이 과정에는 "혼자 써 보기"를 따로 넣지 않는다 (혼자 만들기 · 도전 과제 · 개인 프로젝트가 그 역할).
- **내 자동화 후보 찾기**: DAY 01 4번 "내가 줄여 보고 싶은 일 찾기"에서 수강 목적을 고르고, "자주 하는 일 → 번거로운 부분 → 줄면 좋아지는 점" 순서로 후보 2~3개를 각자 적는다(확정하지 않음, 제출 없음). DAY 01 Flow 실습(연습 ②)에서 관심 후보를 우리말 흐름으로 풀고, DAY 07 4번은 "1일차 후보가 있으면 다시 검토, 없거나 바뀌었으면 새로 정하기"로 잇는다(결석생도 처음부터 가능). DAY 06 정리 섹션에만 "내 일에 떠올려 보기" 한 줄 상자를 둔다 — 다른 날에 늘리지 않는다. DAY 03은 15번 "같은 Workflow, 다른 활용" + 16번 "빠른 수강생 도전(선택)", DAY 04는 14번 "같은 Gemini, 다른 활용"(후기 요약 · 회의 메모 · 문의 처리, 만들지 않아도 됨) + 15번 "빠른 수강생 도전(선택, Workflow 복제 → 입력 · Prompt만 바꾸기)"으로 대신한다. DAY 05는 IF(점수 80 이상) → 조건 칸 읽기(왼쪽 값 · 비교 · 기준, 자주 쓰는 비교 5개만) → Switch → Gemini 분류 + Switch 순서, 13번 "같은 분기, 다른 업무"(재고 IF · 문의 Switch · Gemini priority IF) + 14번 "빠른 수강생 도전(IF/Switch를 스스로 고르게)". "길의 규칙은 사람이 정한다(DAY 05) vs AI가 Tool을 고른다(DAY 07 Agent)"로 구분한다. DAY 04 Prompt 상자에는 식(`{{ }}`)을 넣지 않고 제목에 "맨 아래에 request 끌어다 놓기"처럼 안내한다(상자 안 [ ]는 "직접 고쳐 쓰기" 안내가 떠서 쓰지 않음).
- DAY 03은 초보자 기준: Expression은 직접 입력 대신 INPUT에서 끌어다 놓기, 자동으로 생긴 표시는 "n8n이 만든 표시" 한 줄 설명만. OAuth · Google Cloud 설정 설명 없음. 필수 실습 섹션에는 "필수 실습" 배지, 활용 예시 · 빠른 수강생 도전은 배지와 점선 상자로 구분.
- 자동화 조건(자주 반복 · 입력 모양 비슷 · 결과 모양 정해짐)은 "처음 만들기 쉬운 일"로만 설명하고 필수 조건처럼 쓰지 않는다. 다른 서비스는 "된다 · 안 된다"로 단정하지 않고 "이 과정에서 직접 만드는 범위(요약 · 분류 · 시트 · 메일 · 분기 · Tool)"와 "원하는 기능에 따라 연결 방법을 따로 확인"으로 안내한다.

```
└── html/<과목 폴더>/dayNN/index.html
```

- **DAY 페이지 경로**: 항상 `html/<과목>/dayNN/index.html`. 공통 자산은 `../../../css/theme.css`처럼 3단계 위로.
- **기존 DAY를 새 내용으로 교체할 때**: 기존 폴더는 지우지 않고 `dayNNv2` 폴더를 새로 만든 뒤, `index.html`의 카드 링크와 `day-nav-config.js`의 href만 새 폴더로 바꾼다. 부분 수정은 기존 폴더에서 그대로 고친다.
- **이미지**: 원본 PNG는 올리지 않는다. 가로 1400px 이하(사진 480px 안팎) JPG, 한 장 200KB 안팎, 파일 이름은 영문 소문자(`day03-reverse-perfume.jpg`). 다른 과목 이미지를 쓸 때는 그 과목 폴더로 **복사**해서 쓴다. 휴대폰 사진은 방향이 돌아갔는지 확인.
- **메인 허브(index.html)**: Tailwind 없이 theme.css + 파일 안 `<style>`. 과목마다 `.subject-box` → `.day-list` → `.day-link` 카드(`DAY NN` · 제목 · 설명). DAY를 추가하면 카드와 `.subject-meta`("8개 강의")를 갱신한다. 설명 문구는 지금 길이를 유지한다. `<main>`의 id는 `mainContent`로 두지 않는다.
- 홈 과목 목록은 **정규 과목**(`.subject-list`, 01~)과 **특강**(`.subject-group-head` "// SPECIAL · 특강" 아래 두 번째 `.subject-list`, 01~)으로 나뉜다. 번호는 목록마다 따로 매기고, 새 특강은 특강 목록 아래에 02, 03 … 으로 추가한다. 숨길 과목은 지우지 않고 `.subject-box`에 `hidden style="display:none"`.

## 4. DAY 페이지 뼈대

**새 DAY는 같은 과목의 기존 DAY 페이지를 통째로 복사해 뼈대로 쓴다.** 바꿀 곳:
- `<title>DAY NN. 제목</title>`, `#authGate`의 `data-subject` · `data-day`(그 과목 안의 순번, 폴더가 v2여도 순번 그대로)
- 헤더 `DAY NN` 배지, `.crumb__title`(짧은 제목)
- 목차(`aside#sidebar`)와 본문(`main#mainContent`). 하단 `#dayPager` · 푸터 · 맨 위로 버튼 · 토스트 · 스크립트 4줄(`day-nav-config.js` → `theme.js` → `auth-config.js` → `auth.js`)은 그대로.
- 로고 링크의 `title="메인으로"`는 지우지 않는다 (auth.js가 씀).

**목차(사이드바)**
- `<div class="doc-sidebar__head"><span>학습 목차</span><span>NN개 세션</span></div>` + `<nav class="toc">`
- 반드시 **PART로 묶는다**: 각 PART 첫 링크 앞에 `<p class="toc-group">PART A · 이름</p>`. PART는 2~4개. `.toc-link`에는 Tailwind 클래스를 붙이지 않는다.
- 시간이 될 때 하는 확장 실습은 "시간이 되면" PART로 묶고, 섹션에 `확장 실습 · 시간이 되면` 라벨(amber, `fa-clock`)을 단다.
- 목차 번호 = 본문 섹션 번호. 섹션을 끼우면 뒤 번호와 개수를 모두 고친다.

**본문**
- 제목 영역: `section.doc-hero` 안에 `p.doc-eyebrow`(DAY NN · 과목명) / `h1`(DAY 번호 없이) / `p.doc-lead`(한두 문장). 그라디언트 배너는 쓰지 않는다.
- 섹션: `<section id="sec-…"><h2 class="doc-h2"><span class="doc-h2__num">N.</span><span>제목</span></h2>…</section>`. 섹션 태그에 클래스는 필요 없다.
- 한 섹션 안에서 소제목이 이어지면 두 번째부터 `h3`에 `text-lg mt-16 pt-12 mb-4 border-t border-dashed border-slate-200`.
- 권장 순서: 수업 구성(오늘의 수업) → 오늘 배우는 내용 & 전체 흐름 → 본문 · 실습 → 정리 & 다음 수업(또는 오늘의 결과물). 섹션은 대체로 13~17개.
- 실습 STEP을 하나씩 섹션으로 만들지 말고 2~3개씩 묶는다.

## 5. UI 패턴 (내용에 맞게 조합)

과목 색 자리는 아래 예시의 `indigo`를 그 과목 색으로 바꿔 쓴다.

**기본 상자**
- **정의 박스**: `bg-indigo-50/80 border-l-4 border-indigo-600 p-5 rounded-r-xl` + `h3.text-sm.font-bold` + 정의 문장
- **비교 카드**: `grid grid-cols-1 md:grid-cols-2 gap-6` — 왼쪽 `bg-slate-50 border-slate-200`(기존), 오른쪽 `bg-indigo-50/40 border-indigo-200`(새 방식)
- **O/X 카드**: X `bg-rose-50 border-rose-200` / O `bg-emerald-50 border-emerald-200`, 실제 프롬프트 문장으로
- **주의 박스**: `bg-amber-50/70 border border-amber-200 rounded-2xl p-6` + `fa-triangle-exclamation`. 짧은 안내는 `bg-amber-50 … rounded-xl` + `fa-circle-info`
- **표**: `thead bg-slate-100`, `tbody divide-y divide-slate-200`, 행 `hover:bg-slate-50`, 첫 칸 `font-bold bg-slate-50/50`. 넓은 표는 `overflow-x-auto` + `min-w-[520px]`
- **칩 목록**: `flex flex-wrap gap-1.5` + `px-2.5 py-1 bg-slate-100 text-slate-700 text-xs rounded-lg`
- **카드 그리드**: 아이콘 상자(`w-8 h-8 rounded-lg bg-indigo-50 text-indigo-600`) + 제목 + 설명
- **코드 블록**: `pre.bg-slate-900.text-slate-100.p-3.5.rounded-xl.font-mono.overflow-x-auto` (명령어는 `text-emerald-400`)
- **비유**: "비유하자면 —" 한 문단 (식당 · 장부 · 창고처럼 생활 장면)
- **"핵심 —" 강조 문구는 페이지당 2~3개까지만.**

**흐름 표현**
- **세로 플로우**(7단계 이하): `max-w-md mx-auto space-y-1` 상자들 사이에 `fa-arrow-down`, 마지막 단계만 진한 색
- **번호 칩 그리드**(8단계 이상 · 전체 흐름): `grid grid-cols-[repeat(auto-fit,minmax(220px,1fr))] gap-3` + 원형 번호 배지. **고정 열(`lg:grid-cols-4`)은 쓰지 않는다**

**프롬프트 실습** (복사만 하는 수업이 되지 않게)
- **(A) 작성 틀 — 모든 복사용 프롬프트의 기본형**
  ```html
  <div class="prompt-editor" data-title="작성 틀 ① — 제목"><textarea id="고유id" class="prompt-editor__input">
  칸 이름: [무엇을 쓰는 칸인지 — 예: 구체적인 예]</textarea></div>
  <div class="prompt-example" data-summary="막히면 예시 보기 — 완성된 예">완성 예시 (줄바꿈 그대로)</div>
  ```
  머리줄 · 복사하기 · 처음으로 · 펼치기 버튼은 `theme.js`가 만든다. 완성 프롬프트를 그대로 줄 때도 같은 상자를 쓴다. 예전의 "상자를 누르면 복사" 방식은 새 페이지에 쓰지 않는다.
  안내 문구는 내용에 따라 자동으로 바뀐다: 빈 칸 → "직접 써 보세요" / `[ ]` 칸이 있음 → "[ ] 부분을 고쳐 쓰세요" / `[ ]` 없음 → "그대로 복사하기를 눌러 입력하세요". 그래서 **고칠 칸이 아닌 소제목에는 `[ ]`를 쓰지 않는다** — `■ 예산`처럼 쓴다 (`[확인 필요]`는 예외로 무시됨).
- **(D) 직접 쓰기 실습 — 기본형** (2026-10-23): 빈 작성 틀(`placeholder`에 문장 뼈대 힌트) + 위에 "생각해 볼 것" 칩 + 아래 "다 써 본 뒤에 펼치기 — 예시 프롬프트"(`.prompt-example`). 완성 프롬프트를 복사만 시키는 실습은 **같은 프롬프트로 결과를 비교하는 것이 목적일 때만**. 그대로 따라 하는 단계형 실습은 "같이 해 봅시다" 톤으로 쓴다.
- **(B) 바꿔 보기**: 상자 아래 `div.edit-hint` > `p.edit-hint__title`(`fa-pen` "바꿔 보기 — 처음 한 번은 그대로, 다음엔 내 ○○로") + 바꿀 예시. 이어서 고치는 요청에는 붙이지 않는다.
- **(C) 쓰기 전 키워드 상자**: `div.keyword-box … bg-sky-50/60 border-sky-200`(`fa-tags`) — 용어 + 짧은 뜻 칩. 우리말 이름 먼저, 영어 키워드는 괄호. 끝에 "쉬운 말로 써도 AI가 알아듣는다".
- **(P) 혼자 써 보기 — 작성 틀 연습 바로 뒤에 백지에서 쓰기**
  - 매일 · 매 교시가 아니라 **어울리는 실습 뒤에만, 하루 최대 2번**(①②).
  - 구성: 검은 라벨 → 안내 → **새 상황**(연습과 다른 대상 · 주제 · 받는 사람) → 빈 입력칸 → 힌트(칸 이름만) → 확인 칩 → **예시 · 설계 포인트**(맨 아래, 접어 둠)
  ```html
  <div class="solo-write mt-10 p-6 sm:p-8 bg-white border-2 border-dashed border-slate-400 rounded-2xl">
    <p class="inline-flex items-center gap-1.5 px-2.5 py-1 bg-slate-900 text-white text-xs font-bold rounded-md mb-4"><i class="fa-solid fa-pen-nib" aria-hidden="true"></i> 혼자 써 보기 ①</p>
    <p class="text-sm text-slate-700 leading-relaxed mb-4">안내 — 틀 없이 처음부터 써서 복사해 입력하고 결과 확인</p>

    <div class="prompt-editor" data-title="내가 처음부터 쓰는 프롬프트"><textarea id="…" class="prompt-editor__input" placeholder="여기에 처음부터 직접 써 보세요."></textarea></div>
    <div class="prompt-example" data-summary="막히면 힌트 보기 — 들어가면 좋은 칸 이름만">칸 이름 · 칸 이름 · …</div>

  ```
  - 혼자 쓰기가 너무 어려운 활동(예: 선택형 이야기 웹 콘텐츠)은 혼자 써 보기 대신 **"새 채팅에서 AI에게 기획부터 맡기고 나는 고르고 고치기"** 따라 하기 실습으로 만든다.
- **(Q) 판단 문제 — 먼저 생각하고 펼쳐 보기**: `<details class="group p-4 bg-white border border-slate-200 rounded-xl">` + summary(문제 · "생각 정리 보기") + 해설. 예: "무엇이 빠졌을까? — 빠진 칸 찾아 고쳐 보기"(빠진 칸 + 고친 예), "AI에게 입력해도 될까?". **답이 뻔한 A/B 고르기는 쓰지 않는다.**

**용어 정리 패턴**
- **"개발자들은 / 무슨 뜻인가요? / 우리는 이렇게 말해요" 3칸 표** — 초보자가 몰라도 되는 전문 용어를 소개할 때. 위에 "예전 — 개발자식 요청 / 지금 — 우리말 요청" 비교 카드, 아래에 "영어 용어는 외우지 않아도 되고, AI 답에 나오면 알아보면 충분"을 붙인다. 개발자 용어 칸은 `text-slate-500`. (예: 바이브코딩 DAY 07 화면 배치, DAY 08 디자인 다듬기)
- **오늘도 같은 틀 — 프롬프트 7칸 상자**(prompt-eng-1 DAY 03~08 흐름 섹션 끝): 7칸이 그날 실습에서 무엇을 뜻하는지 한 줄씩. 줄 자료 · 확인할 것 두 칸은 진한 색.

**기타**
- **본문 이미지**: `figure.doc-figure` > `a.doc-figure__zoom[href]` > `img[alt][width][height][loading=lazy]` + `span.doc-figure__hint`(크게 보기) + `figcaption`. 세로 이미지는 `max-w-sm mx-auto`.

- **교시 구분**: 섹션 첫 줄에 `1교시` / `2교시` 작은 라벨, 사이에 "10분 휴식" 구분선. **분 단위 시간은 페이지에 쓰지 않는다**(시간 배분은 강사용 txt에만). 수학학원 AI 활용 특강은 교시 라벨 · 구분선을 쓰지 않는다.
- **준비 자료 (수강생 복사용)**: 페이지 끝 섹션, 작성 틀 상자에 넣고 "수업용 가상 자료"라고 표시. 가상 데이터는 숫자가 서로 맞게(합계 등).

## 6. 글쓰기 원칙

**말투**
- 수강생이 읽는 교재다. "학생이 ~합니다" 대신 "직접 ~해 보세요", "각자 ~".
- 목록 · 제목은 "~하기", 정의 문장만 "~입니다".
- 핵심목표는 한 문장. 추상적 표현("예쁘게")은 X 예시로만 쓰고 구체적 대안을 O로 짝지운다. AI가 할 일과 사람이 판단할 일을 나눠 설명한다.

**쉬운 용어 (2026-10 확정)**
- 초보자가 **몰라도 되는 전문 용어는 뺀다.** 꼭 소개해야 하면 우리말을 앞에 쓰고 "개발자들은 OO라고 부릅니다" 한 줄이나 5절의 3칸 표로.
- 남기는 화면 이름: **Header · Section · Card · Footer**. 메뉴바(Navigation) · 첫 화면(Hero) · 행동 버튼(CTA) · 입력창(Form)은 우리말을 앞에. 흐름(User Flow) · 화면 설계도(Wireframe)도 우리말이 먼저.
- 도구 화면에 실제로 적힌 버튼 · 메뉴 이름(Settings, Pages, Authentication, Clone Repository, Console 등)은 수강생이 찾아 눌러야 하므로 그대로 쓴다.
- 꼭 필요한 개념은 남긴다: HTML · CSS · JavaScript, Git · GitHub · Repository · Commit · Push, Database · SQL · Table · Column · Row, 서버 · 호스팅 · 배포, 데이터베이스 · 스토리지 · 메모리, 트래픽 · 동시접속, API · API 키(공개용/비밀용), RLS(접근 규칙), 도메인 · DNS · SSL · HTTPS, 인증 · 권한, 하네스 · CLAUDE.md · 스킬 · MCP.
- 빼거나 바꾼 예: 렌더링, PATH · CLI · Diff, Pull · Remote, 토큰 · 세션(→ 임시 출입증), CRUD, Policy, TLS, 해시(→ 암호문으로 저장), UID(→ 회원 번호), 서브도메인(→ 기본 주소), MVP(→ 첫 완성본), Testing(→ 직접 눌러 보며 확인), Debugging(→ 원인 찾아 오류 고치기), Regression(→ 고친 뒤 다시 확인하기), QA(→ 최종 점검), Feature Freeze(→ 새 기능 추가 멈추기), Typography · Spacing · Padding(→ 글자 스타일 · 여백).
- 비유는 생활 장면으로, 수준은 고등학생 ~ 성인 (초 · 중학생용 표현은 쓰지 않는다).
- 비슷한 개념을 여러 개 가르치지 않고 하나로 합친다 (예: User Flow + Screen Flow → "흐름").
- 복사용 프롬프트에 "DAY 06~07" 같은 수업 일정 표현을 넣지 않는다 (AI가 기간으로 오해).

**프롬프트 실습 원칙**
- 흐름: **작성 틀로 연습 → 혼자 써 보기(새 상황, 백지) → 입력 · 결과 확인 → 한 줄 고쳐 다시 → 예시 · 설계 포인트와 비교.**
- 프롬프트에는 정답이 없다. "정답" 대신 **"예시 프롬프트", "설계 포인트"**라고 쓴다.
- **프롬프트 7칸**(prompt-eng-1 공통 틀, DAY 02에서 소개): 목적 · 상황 · 대상 · 조건 · 결과 형식 + **줄 자료 · 확인할 것**. 영어 약어(GOAL · CONTEXT …)는 쓰지 않는다.
- 첫 답이 마지막 답이 아니다 — "더 짧게", "표로" 같은 이어서 고치기를 꼭 넣는다. 고칠 때는 **유지할 것 · 바꿀 것 · 어떻게**를 나눠 말하게 한다.
- 틀린 답 줄이기를 습관처럼: "내가 주지 않은 숫자는 지어내지 말고 [확인 필요]로", "원인은 추측이라고 표시", "숫자 1~2개는 직접 검산", AI가 SQL · 코드를 주면 "실행 전에 무슨 작업인지 설명".
- 막연한 요청은 바로 AI에게 넣지 않는다 — 먼저 "무엇을 알아야 하지?"를 적고, AI에게는 아이디어 대신 확인할 질문 목록부터 받는다.
- 주제를 정하라고만 하지 않고 고를 수 있는 예시를 5개 정도 먼저 보여 준다. 단, 혼자 써 보기에서는 구체적 조건까지 정해 주지 않고 **주제만** 던진다(예: "부모님 · 연인 · 자녀 · 친구 중 한 사람과 떠나는 여행", "내 업무에 적용해 보기").
- **같은 내용을 위아래 섹션에서 다시 설명하지 않는다.** 뒤에서 실습할 내용이면 앞에서는 "다음 실습에서 해 봅니다" 한 줄로.
- 짧은 요청 vs 구체적인 요청 비교는 **너무 극단적이지 않게** — 짧은 쪽도 실제로 쓸 법한 문장으로("이메일 써줘." X).
- 조건이 많은 프롬프트는 `■ 묶음 이름` + `- 항목`으로 나눠 보여 준다.

**정확성**
- 도구 메뉴 이름 · 위치는 자주 바뀐다. "메뉴 이름은 업데이트에 따라 다를 수 있습니다" + "막히면 AI에게 메뉴 순서를 물어보기"를 붙인다.
- AI 서비스 기능은 수시로 바뀐다(예: ChatGPT 캔버스 종료). 최신 기능 · 요금 · 무료 체험 조건은 **웹에서 확인한 뒤** 쓰고, 공식 자료로 확인되지 않은 수치는 "알려져 있다" 정도로만 쓰고 강사 확인 필요 목록에 올린다.
- 통계 · 최신 수치는 지어내지 않는다.
- 안전: 회사 자료 · 개인정보 입력 금지, 비밀용 API 키는 코드 · GitHub · 캡처 어디에도 올리지 않기, 공개 전 비밀 정보 점검.

## 10. 작업 환경 · 커밋 규칙

- **배포**: `.github/workflows/deploy.yml`이 main에 올라올 때마다 `index.html · css · js · img · html`만 골라 GitHub Pages에 올린다. `참고자료/ · MD/ · sql/`은 웹사이트에 올라가지 않는다(공개 저장소라 github.com에서는 보임). **웹사이트에 보여야 하는 새 폴더·루트 파일을 만들면 deploy.yml의 복사 목록에 추가한다.**
- **커밋**: 사용자가 요청할 때만 한다. `git add -A`로 `참고자료/` 등 미추적 파일까지 모두 포함 → 커밋 제목은 `vX.YY 핵심 단어 몇 개`(예: `v2.80 프롬프트1 예시 · 설계 포인트 · 역설계`) → 태그 `verX.YY` → `git push origin main` + `git push origin verX.YY`. 버전은 마지막 태그에서 0.01씩 올린다(`git tag --sort=-creatordate | head -1`).
- **Windows 환경**: Git Bash에 Python · Node가 없을 수 있다 → 일괄 치환 · 끼워 넣기는 `perl`로. `참고자료/`의 txt는 대부분 CRLF 줄바꿈이라 정규식 전에 `s/\r\n/\n/g`, 저장할 때 다시 CRLF로.
- **여러 페이지를 한꺼번에 만들 때**: 같은 과목 기존 페이지의 머리(목차 직전까지)와 꼬리(`#dayPager`부터)를 잘라 템플릿으로 쓰고, 본문만 새로 써서 이어 붙인다. 붙인 뒤 제목 · `data-day` · 배지 · crumb를 치환하고 9번 검증을 돌린다.
- 커리큘럼 txt(`참고자료/<과목> 자료/`)는 강사용 기획 문서다. 일차별 시간 배분 · 강사 메모는 txt에 쓰고 HTML에는 쓰지 않는다.
