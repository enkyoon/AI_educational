4.n8n이란?

n8n (엔에잇엔)

여러 서비스와 기능을 Node 단위로 연결해 Workflow를 만드는 자동화 도구입니다. 블록을 이어 붙이듯 화면에서 Node를 연결해 자동화를 만듭니다.

예를 들어 앞으로 이런 작업들을 연결하게 됩니다.

이메일 도착 내용 가져오기 AI가 내용 분석 Google Sheets 저장 담당자에게 이메일
사용자 문의 AI가 문의 종류 판단 고객 정보 검색 답변 작성 이메일 발송

n8n은 하나의 도구일 뿐이다

목표는 n8n의 버튼 위치를 모두 외우는 것이 아닙니다. 아래 과정을 스스로 할 수 있으면 도구가 바뀌어도 그대로 쓸 수 있습니다.

5.n8n Cloud와 설치형

n8n은 크게 두 가지 방법으로 쓸 수 있습니다.

n8n Cloud — 이번 과정의 주 실습 환경

n8n 회사가 운영하는 서버에서 씁니다. 웹브라우저에서 로그인만 하면 바로 쓸 수 있어 서버 관리가 필요 없습니다.

Self-hosted (설치형) — 오늘 체험만

내 컴퓨터나 서버에 n8n을 직접 설치해서 씁니다. 서버·업데이트·저장 공간을 직접 관리해야 할 수 있습니다.

구분n8n CloudSelf-hosted
설치필요 없음직접 설치
서버 관리n8n이 관리직접 관리
시작 난이도낮음상대적으로 높음
접속 방법웹브라우저설치한 컴퓨터의 주소
이번 수업주 사용 환경설치 체험

처음 배울 때는 Cloud를 쓰면 설치 걱정 없이 Workflow 자체를 익히는 데 집중할 수 있습니다.

7.시작점 Manual Trigger

모든 Workflow에는 시작점(Trigger)이 필요합니다. n8n에는 이런 Trigger가 있습니다.

특정 시간이 되었을 때 이메일이 도착했을 때 입력 양식(Form)이 제출되었을 때 다른 서비스에서 데이터가 들어왔을 때(Webhook) 사용자가 직접 실행했을 때 ← 오늘 사용

Manual Trigger (직접 실행)

버튼을 눌러 Workflow를 직접 실행해 테스트할 때 쓰는 시작점입니다. "지금 이 Workflow를 한번 돌려 보겠다"는 뜻입니다.

오늘은 외부 서비스 없이 연습하기 위해 Manual Trigger로 시작합니다. 자동으로 돌아가는 시스템을 만드는 것이 아니라 Workflow가 움직이는 원리를 연습하는 단계입니다.

Manual Trigger 데이터 만들기 데이터 바꾸기 결과 확인

n8n 버전에 따라 이 Node는 Node 검색창에서 Trigger manually로 찾고, Canvas에는 When clicking 'Execute workflow'라는 이름으로 표시되기도 합니다. 모두 같은 Node입니다.

INPUT에서 이름표를 끌어다 놓으면 Value 칸에 초록색 글자로 아래 같은 표시가 생깁니다. 이것이 "앞 Node의 name 값을 가져와라"라는 뜻입니다. 이렇게 값을 가리키는 칸을 n8n에서는 Expression(연결식)이라고 부릅니다.

{{ $json.name }}   ← 바로 앞 Node의 name 값

끌어다 놓기가 잘 안 되면 아래 문장을 복사해 Value 칸에 붙여넣어도 됩니다. 이때 칸 위의 Fixed / Expression 중 Expression이 선택되어 있어야 합니다.

11.전체 실행과 실행 기록

지금까지는 Node 하나씩 실행했습니다. 이번에는 Canvas 아래의 Execute workflow(버전에 따라 Test workflow) 버튼으로 Workflow 전체를 실행합니다. 데이터가 순서대로 이동하는 모습을 확인하세요.

1Trigger 시작
2첫 Node 실행
3Output 생성
4다음 Node로 전달
5두 번째 Node 실행
6최종 Output

Execution (실행 기록)

Workflow가 한 번 실행된 것을 말합니다. 세 번 테스트하면 실행 기록이 세 개 남습니다. 화면 위쪽의 Executions 탭에서 볼 수 있습니다.

실행 기록을 열면 다음을 확인할 수 있습니다.

정상적으로 실행되었는가?
어떤 Node까지 실행되었는가?
어떤 데이터가 전달되었는가?
어느 Node에서 문제가 생겼는가?

"된다 / 안 된다"가 아니라 "어디까지 정상으로 실행되었는가?"를 봅니다.

13.오류는 위치를 찾는다

Node가 2개일 때는 문제를 쉽게 찾지만, 문의 접수 → 고객 확인 → AI 분석 → 분류 → 담당자 검색 → 기록 → 이메일 작성 → 발송 → 완료 기록처럼 Node가 많아지면 결과만 보고는 원인을 찾기 어렵습니다. 그래서 Node를 하나씩 확인하며 문제의 위치를 좁혀 갑니다.

오류를 두려워하지 마세요. 오류가 났다고 Workflow 전체가 잘못된 것은 아닙니다. 자동화를 만들다 보면 오류는 반드시 생기고, 고치는 과정이 곧 실력입니다.

실습: 일부러 오류 만들어 보기

12번에서 만든 3단계 Workflow를 이렇게 바꿔 봅니다.

방법 1첫 번째 Node의 이름표 name을 user_name으로 바꾸기
방법 2세 번째 Node는 그대로 $json.name을 쓰도록 두기

전체 실행을 해 보면 빨간 오류 표시 없이 "님은 AI에 관심이 있는…"처럼 이름 자리만 비어 나올 수 있습니다. 오류 표시가 없다고 정상인 것은 아닙니다. 그래서 결과를 직접 확인해야 합니다.

문제를 찾는 순서

1어느 Node부터 결과가 이상한가?
2바로 앞 Node의 Output은 정상인가?
3지금 Node가 어떤 값을 가져오려 하는가?
4이름표(Field) 이름이 똑같은가?
5Input과 Output 비교하기

좋지 않은 접근 vs 좋은 접근

좋지 않은 접근

안 된다 → 처음부터 다시 만든다

좋은 접근

결과가 이상하다 → 마지막 Node 확인 → Input 확인 → 앞 Node Output 확인 → 잘못된 데이터 발견 → 해당 Node만 수정 → 다시 실행

핵심 — 자동화 문제 해결은 문제가 생긴 위치를 좁혀 가는 것입니다.

15.체험: 내 컴퓨터에서 n8n 실행

지금까지 쓴 것은 n8n Cloud입니다. 이번에는 내 컴퓨터에서도 n8n을 실행할 수 있다는 것을 확인합니다. 설치형을 주로 쓰지는 않으므로 목표는 아래 정도입니다.

설치형이 무엇인지 알기
Cloud와 무엇이 다른지 확인하기
내 컴퓨터에서 n8n이 뜨는 과정 보기
나중에 설치 방법을 다시 찾을 수 있기

Docker (도커)

프로그램과 그 프로그램이 돌아가는 데 필요한 환경을 하나의 상자에 담아 실행해 주는 도구입니다. "n8n이 바로 돌아갈 수 있게 준비된 상자를 내 컴퓨터에서 여는 것"이라고 생각하면 됩니다.

Docker Desktop이 설치되어 있어야 합니다. 설치가 어려운 환경이라면 강사 시연을 보는 것으로 충분합니다.

STEP 1. Docker 설치 확인

PowerShell(맥은 터미널)을 열고 입력합니다. 버전 정보가 나오면 Docker를 쓸 수 있습니다.

STEP 2. n8n 데이터 보관 공간 만들기

n8n에서 만든 Workflow를 보관할 공간을 만듭니다.

STEP 3. n8n 실행하고 접속하기

아래 명령어로 n8n을 실행한 뒤, 준비가 끝나면 웹브라우저에서 http://localhost:5678로 접속합니다. (n8n 공식 문서의 Docker 실행 방법 기준)

localhost인터넷 너머의 다른 서버가 아니라 지금 쓰고 있는 내 컴퓨터를 뜻합니다.
5678n8n에 들어가는 문 번호(Port)입니다. 한 컴퓨터 안에서 여러 프로그램을 구분하는 번호입니다.

Cloud와 localhost 비교

인터넷 → n8n 회사의 서버 → 나의 Workflow

Self-hosted

화면은 비슷해도 n8n이 어디에서 돌아가고 있는지가 다릅니다. 설치 명령어는 외울 필요가 없습니다. 필요할 때 공식 문서에서 지금 권장하는 설치 방법을 찾아 GPT와 함께 적용하는 능력이 더 중요합니다.

(선택 학습) Pin Data — 테스트 데이터 고정하기

Workflow를 만들다 보면 매번 처음부터 데이터를 가져오는 것이 번거롭습니다. Node의 OUTPUT 화면에서 핀(Pin) 아이콘을 누르면 그 결과를 고정해 두고, 뒤쪽 Node만 반복해서 테스트할 수 있습니다. 예를 들어 "고객 데이터 가져오기 → AI 분석 → 이메일 작성"에서 고객 데이터를 고정해 두고 AI 분석만 여러 번 고쳐 볼 수 있습니다. Workflow가 길어질수록 유용합니다.

먼저 답을 떠올린 뒤 눌러서 확인하세요.

Q1앞 Node의 데이터를 다음 Node에서 가져다 쓰는 것을 무엇이라고 하는가?답 보기

Data Mapping(데이터 연결)입니다. n8n에서는 INPUT의 값을 끌어다 놓으면 {{ $json.이름표 }} 형태의 Expression이 만들어집니다.

Q2고정값과 변하는 값의 차이는?답 보기

고정값은 매번 똑같이 쓰는 문장이나 값이고, 변하는 값은 이름·이메일·문의 내용처럼 실행할 때마다 달라지는 데이터입니다. 변하는 값은 앞 Node에서 가져옵니다.

Q3Workflow가 이상하게 동작할 때 가장 먼저 확인할 것은?답 보기

어느 Node부터 결과가 이상해졌는지, 그리고 그 바로 앞 Node의 Output이 정상인지 확인합니다.

Q4n8n Cloud와 Self-hosted의 가장 큰 차이는?답 보기

n8n이 어디에서 돌아가는지입니다. Cloud는 n8n 회사의 서버에서, Self-hosted는 내 컴퓨터나 서버에서 돌아가며 관리도 직접 합니다.
