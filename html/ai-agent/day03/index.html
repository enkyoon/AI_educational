4.Credential — 서비스 연결 허락

Credential (연결 정보)

"이 Workflow가 내 Google 서비스에 들어가도 된다고 허락한 연결 정보"입니다. Google Sheets Node를 추가했다고 바로 내 시트를 쓸 수 있는 것이 아니라, 먼저 n8n과 내 Google 계정을 연결해야 합니다.

비유하자면: 집 비밀번호를 알려주는 것이 아니라, 택배 기사님에게 현관 출입 카드를 발급해 주는 것과 같습니다. 필요한 곳에만 들어갈 수 있고, 필요 없어지면 카드만 회수하면 됩니다.

Credential과 비밀번호는 다르다

n8n Node에 Google 비밀번호를 직접 입력하지 않습니다. n8n Cloud에서는 Google Sheets·Gmail을 Google 로그인 버튼(Sign in with Google)으로 연결할 수 있습니다. 이런 방식을 OAuth(오어스)라고 합니다.

일반적인 로그인

서비스 → 아이디 / 비밀번호 입력 → 로그인

OAuth 방식의 연결

n8n → Google에 연결 요청 → Google에서 로그인 → 내가 권한 허용 → n8n에 접근 권한 부여

다른 서비스에 비밀번호를 알려주는 것이 아니라 Google을 통해 접근 권한을 허락하는 구조입니다. 기술적인 원리는 외울 필요 없습니다.

Credential이 만들어지는 순서

1n8n에서 연결 요청
2Google 로그인
3접근 권한 확인 · 허용
4Credential 생성
5Node에서 선택해 사용

7.Mapping — 열과 데이터 연결

이제 가장 중요한 단계입니다. 시트의 열(name, email, request, status)과 n8n의 데이터를 짝지어 연결합니다. DAY 02에서 배운 Data Mapping과 같은 원리입니다.

Edit Fields의 name시트의 name 열 Edit Fields의 email시트의 email 열 Edit Fields의 request시트의 request 열 Edit Fields의 status시트의 status 열

연결하는 방법

Google Sheets Node의 Mapping Column Mode에서 Map Each Column Manually(열마다 직접 연결)를 고르면 시트의 열 이름이 칸으로 나타납니다. 각 칸에 왼쪽 INPUT의 같은 이름 값을 끌어다 놓습니다.

Map Automatically(자동 연결)를 고르면 이름이 똑같은 것끼리 알아서 연결됩니다. 편하지만 오늘은 원리를 눈으로 보기 위해 직접 연결합니다.

8.실습: Sheets 데이터 읽어오기

Google Sheets는 저장만 하는 곳이 아닙니다. 저장된 데이터를 다시 n8n으로 가져올 수도 있습니다. 방향이 반대가 됩니다.

저장 (Append row)

n8n → Google Sheets

읽기 (Get row(s))

Google Sheets → n8n

1새 Workflow에 Manual Trigger 추가
2Google Sheets → Get row(s) in sheet 고르기
3아까 만든 Credential · 파일 · 탭 선택
4실행하고 OUTPUT 확인

OUTPUT에 시트의 줄들이 나타납니다. 시트에 있던 데이터가 이제 다음 Node가 쓸 수 있는 Output이 되었습니다. Credential은 한 번 만들면 다른 Node에서도 다시 고르기만 하면 됩니다.

10.실습: 이름이 바뀌는 이메일

지금 이메일은 항상 같은 내용을 보냅니다. 하지만 실제 업무에서는 받는 사람마다 내용이 달라져야 합니다.

첫 번째 실행 — "김민지님, 문의가 정상적으로 접수되었습니다."
두 번째 실행 — "박하늘님, 문의가 정상적으로 접수되었습니다."

고정 문장 + 변하는 데이터

자동화에서 가장 많이 쓰는 방식입니다. 바뀌지 않는 문장은 직접 쓰고, 바뀌는 부분만 앞 Node에서 가져옵니다.

고정 문장

"님, 안녕하세요. 문의가 정상적으로 접수되었습니다. … 확인 후 안내드리겠습니다."

변하는 데이터
email → 받는 사람 name → 본문 request → 본문

따라하기

방금 만든 Gmail Node 앞에 Edit Fields(고객 정보)를 끼워 넣고, 이번에는 To와 Message에 앞 Node의 값을 끌어다 놓습니다. 김민지와 문의 내용은 직접 입력하지 않습니다.

ToINPUT의 email을 끌어다 놓기
Subject문의가 정상적으로 접수되었습니다. (고정)

Message는 끌어다 놓기로 직접 만들어 보고, 막히면 아래를 붙여넣으세요 (Expression 선택).

실행 후 메일함에서 이름과 문의 내용이 Edit Fields의 값으로 채워졌는지 확인하세요.

12.필요한 데이터를 찾는 습관

Google Sheets Node를 지나면 데이터가 사라질까요? 아닙니다. 다만 Node마다 내보내는 데이터의 모양이 다를 수 있어서, 각 Node의 실제 OUTPUT을 확인하는 습관이 중요합니다.

지금 Node의 Input은? 지금 Node가 한 일은? 지금 Output에 어떤 값이 있나? 다음 Node에 필요한 값은?

바로 앞이 아닌 Node에서 데이터 가져오기

Edit Fields → Google Sheets → Gmail 구조에서, Gmail에 필요한 값이 바로 앞 Sheets가 아니라 처음 Edit Fields에 있는 경우도 있습니다. 데이터는 꼭 바로 앞 Node에서만 가져와야 하는 것이 아닙니다.

Gmail Node 왼쪽 INPUT 위쪽의 Node 선택 목록에서 Edit Fields를 고르면 그 Node의 데이터가 보이고, 거기서 끌어다 놓을 수 있습니다. 그러면 아래처럼 Node 이름이 들어간 연결식이 만들어집니다.

바로 앞 Node의 값
{{ $json.email }}

이름을 지정한 Node의 값 (예: Edit Fields)
{{ $('Edit Fields').item.json.email }}

* 연결식을 외울 필요는 없습니다. 끌어다 놓으면 n8n이 알아서 만들어 줍니다.

필요한 값이 안 보일 때 — 바로 직접 입력하지 않기

3그 Node의 Output에 값이 있나?
4필요한 칸에 끌어다 연결

실습: 데이터가 바뀌어도 동작하는지 확인하기

Edit Fields의 값만 바꿔 두 번 실행하고, 매번 시트와 메일함을 확인합니다.

Workflow는 고치지 않았는데 결과 내용만 바뀐다면 변하는 데이터가 제대로 연결된 것입니다.

13.문제 해결: 세 가지로 나누기

실습: 일부러 잘못 연결해 보기

Edit Fields의 이름표 email을 customer_email로 바꾸고, Gmail Node는 그대로 둔 채 실행해 봅니다. 받는 사람이 비어 오류가 날 것입니다. 아래 순서로 원인을 찾아 고쳐 보세요.

1어느 Node까지 정상 실행됐나?
2Gmail이 받은 Input 확인
3email 데이터가 있는지 확인
4앞 Node의 Output 확인
5Field 이름이 바뀌었는지 확인
6연결 고치고 다시 실행

오류는 크게 세 종류

외부 서비스를 연결하면 오류 종류도 많아집니다. 먼저 어떤 종류의 문제인지 나누면 찾아볼 범위가 확 줄어듭니다.

14.테스트 데이터와 Node 이름

연습할 때는 실제 고객 정보를 쓰지 않기

자동화 실습에서는 실제 고객의 개인정보를 쓰지 않습니다. 잘못 연결하면 엉뚱한 사람에게 이메일이 실제로 발송될 수 있기 때문입니다.

테스트용 이름 자신의 이메일 주소 가상의 문의 내용

충분히 테스트해서 제대로 동작하는 것을 확인한 뒤에 실제 업무에 적용합니다.

Workflow가 길어지면 읽는 법

Manual Trigger → Edit Fields → Google Sheets → Gmail(고객) → Gmail(담당자)처럼 길어지면 세 가지 기준으로 읽습니다.

시작무엇이 Workflow를 시작시키는가?
데이터어떤 정보가 Node 사이를 이동하는가?
행동각 Node가 데이터로 어떤 일을 하는가?

Node 이름을 역할로 바꾸기

같은 종류의 Node가 여러 개면 n8n은 뒤에 숫자를 붙입니다. 나중에 보면 무엇이 무엇인지 알 수 없습니다. Node를 선택하고 F2를 누르거나 이름을 눌러 바꿉니다.

알아보기 어려운 이름

Edit Fields · Edit Fields1
Google Sheets · Google Sheets1
Gmail · Gmail1

역할이 보이는 이름

고객 확인 메일 · 담당자 알림 메일

Workflow는 만드는 것뿐 아니라 나중에 다시 읽을 수 있어야 합니다. 이름을 바꾸면 12번의 $('Edit Fields') 같은 연결식 안의 이름도 n8n이 함께 바꿔 줍니다.

16.최종 실습: 혼자 만들어 보기

아래 요구사항을 보고 Workflow를 직접 구성합니다. n8n을 바로 열지 말고 Flow부터 적어 보세요.

요구사항
  • · 교육 신청자가 있다.
  • · 신청자의 이름, 이메일, 과정명, 신청 목적을 기록해야 한다.
  • · 데이터는 Google Sheets에 저장한다.
  • · 저장이 끝나면 신청자에게 접수 완료 이메일을 보낸다.
[Flow] 1단계: Manual Trigger (직접 실행) 2단계: Edit Fields — 신청자 정보 만들기 3단계: Google Sheets — Append row로 신청 내역 저장 4단계: Gmail — 신청자에게 접수 완료 이메일 발송 [필요한 데이터 — 시트의 열 이름] 1. name 2. email 3. course 4. purpose [쓸 Node] Manual Trigger, Edit Fields, Google Sheets, Gmail

Flow를 다 적었으면 그대로 n8n에서 Node를 고르고 연결해 완성합니다. 이메일 본문에 이름과 과정명이 자동으로 들어가게 만드는 것까지가 목표입니다.

스스로 확인하기

먼저 답을 떠올린 뒤 눌러서 확인하세요.

Q1Credential은 어떤 역할을 하는가?답 보기

n8n이 내 Google Sheets·Gmail 같은 외부 서비스에 접근해도 된다고 허락한 연결 정보입니다. 한 번 만들면 여러 Node에서 골라 쓸 수 있습니다.

Q2Gmail의 받는 사람을 매번 직접 입력하지 않으려면?답 보기

To 칸에 앞 Node의 email 값을 끌어다 연결(Mapping)합니다.

Q3Credential 오류와 Mapping 오류는 어떻게 다른가?답 보기

Credential 오류는 서비스에 접근 자체를 못 하는 연결 문제(인증 필요, 권한 부족)이고, Mapping 오류는 접근은 되지만 필요한 값이 없거나 잘못된 칸에 연결된 데이터 문제입니다.

Q4Google Sheets에서 가져온 데이터를 다음 Node에서 다시 쓸 수 있는가?답 보기

쓸 수 있습니다. Get row(s)로 가져온 데이터는 다른 Node의 Output과 똑같이 다음 Node의 Input이 됩니다.
