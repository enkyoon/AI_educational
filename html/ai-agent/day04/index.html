4.API란?

API (에이피아이)

서로 다른 프로그램이 정해진 방식으로 요청과 결과를 주고받도록 만든 연결 창구입니다.

사람이 Gemini를 쓸 때

사람 → Gemini 웹사이트 → 질문 입력 → Gemini 답변

프로그램이 Gemini를 쓸 때

n8n → Gemini API → 요청 전달 → Gemini 처리 → 결과 반환 → n8n

사람이 Gemini 웹페이지를 열지 않아도 프로그램이 Gemini에게 일을 맡길 수 있습니다.

비유하자면: 음식점과 같습니다.

손님주문하는 쪽 (n8n)
직원 = API주문을 주방에 전달
주방실제로 처리 (Gemini)
완성된 음식돌아온 결과

Request와 Response

Request (요청) — 서비스에 보내는 것

"다음 고객 문의를 3줄로 요약해주세요."

Response (응답) — 서비스가 돌려주는 것

고객은 수업 취소를 원하고 있습니다.
결제 금액 환불 방법을 문의하고 있습니다.
환불 절차에 대한 안내가 필요합니다.

n8n에서는 이 Response를 다음 Node의 데이터로 쓸 수 있습니다.

5.API Key와 안전 관리

API를 쓸 수 있도록 발급되는 나만의 인증 정보입니다. 아무나 API를 쓸 수 있다면 누가 얼마나 썼는지 알 수 없으니, 요청마다 이 키로 "누가 보낸 요청인지"를 확인합니다.

10.정보 추출과 문장 생성

③ 정보 추출 — 필요한 정보만 뽑기

AI는 문장 속에서 필요한 정보만 찾아낼 수 있습니다. 아래 문장을 request에 넣고 실행해 보세요.

예상 결과
이름: 김민수
예약일: 10월 15일
시간: 오후 3시
이메일: minsu@example.com

AI가 없는 데이터를 지어낼 수 있어요

원문에 이메일이 없는데 AI가 그럴듯한 주소를 만들어 넣으면 큰 문제가 됩니다. 그래서 위 Prompt처럼 "없는 정보는 추측하지 말고 '없음'이라고 표시하라"는 조건을 꼭 넣습니다. 이메일 문장을 지우고 다시 실행해 "없음"이 나오는지 확인해 보세요.

11.결과의 모양도 설계하기

사람이 읽기 좋은 답 ≠ 프로그램이 쓰기 좋은 답

사람이 읽는 결과

이 고객은 수업 일정 변경에 대해 문의하고 있으며, 카테고리는 수업문의로 판단됩니다.

프로그램이 쓰기 좋은 결과

summary: 수업 일정 변경 가능 여부 문의
category: 수업문의

Prompt가 너무 자유로우면 생기는 문제

"문의 내용을 분석해줘."라고만 하면 실행할 때마다 모양이 다른 답이 나옵니다.

결과 1이 문의는 수업 일정에 관한 문의입니다.
결과 2고객은 일정 변경을 희망하고 있습니다. 카테고리는 수업 문의입니다.
결과 3수업일 변경 요청으로 보입니다.

사람은 다 이해하지만, 시트의 category 열에 넣으려면 곤란합니다. 그래서 AI에게 무엇을 할지뿐 아니라 어떤 모양으로 답할지도 정해 줍니다.

Structured Output (정해진 모양의 결과)

AI가 자유롭게 답하지 않고 미리 정한 칸에 맞춰 결과를 만들게 하는 것입니다. 더 발전된 Workflow에서는 아래처럼 JSON이라는 형식을 쓰기도 합니다. 오늘은 문법을 외울 필요 없이, 결과의 모양도 설계해야 한다는 점만 기억하세요.

{
  "summary": "수업 일정 변경 가능 여부 문의",
  "category": "수업문의"
}

실습: Prompt 고쳐 쓰기

"이 문의를 정리해줘."라는 Prompt를 아래 틀로 직접 고쳐 써 봅니다. 역할 · 작업 · 카테고리 · 길이 · 출력 형식 · 추측 금지 · 데이터가 모두 들어가야 합니다.

당신은 고객 문의를 정리하는 담당자입니다. 다음 고객 문의를 분석하세요. 1. 문의 내용을 한 문장으로 요약하세요. 2. 다음 카테고리 중 하나로 분류하세요. - 수업문의 - 결제문의 - 환불문의 - 기타 3. 입력에 없는 내용은 추측하지 마세요. 아래 형식으로만 답하세요. summary: category: 고객 문의: {{ $json.request }}

완성한 Prompt를 Gemini Node에 넣고 여러 문의로 실행해 보세요. 매번 summary: / category: 모양이 지켜지는지 확인합니다.

12.실습: AI 고객 문의 처리

이제 DAY 03의 Workflow에 Gemini를 넣습니다. AI Node를 어디에 넣을지는 목적에 따라 달라집니다. 정답이 하나만 있는 것은 아닙니다.

예 1 · AI가 먼저 정리하고 저장

문의 → Gemini 요약 → Google Sheets

예 2 · 원문부터 저장하고 AI 분석

문의 → Google Sheets → Gemini 분석

예 3 · AI가 이메일 작성

문의 → Google Sheets → Gemini 답변 작성 → Gmail

오늘 만들 구조

요약과 분류를 Gemini Node 두 개로 나누면 각각의 결과를 시트의 다른 칸에 바로 넣을 수 있습니다. Node 이름을 역할대로 바꿔 두세요.

Manual Trigger
고객 문의 생성 (Edit Fields — name · email · request)
Gemini 요약 → summary
Gemini 분류 → category
문의 내역 저장 (Google Sheets)
고객 확인 메일 (Gmail)

STEP 1. 시트에 열 추가하기

DAY 03의 AI_AGENT_DAY03 파일에 새 탭 ai_inquiry를 만들고, 1행에 아래 다섯 칸을 적습니다. AI가 만든 결과도 일반 데이터처럼 저장할 수 있습니다.

nameemailrequestsummarycategory

STEP 2. 고객 문의 생성 → Gemini 요약

Edit Fields(이름: 고객 문의 생성)에 name(자신의 이름), email(자신의 이메일), request를 만듭니다. request에는 "수업을 신청했는데 개인 일정 때문에 다른 날짜로 변경하고 싶습니다."를 넣습니다. 그 뒤에 Gemini Node(이름: Gemini 요약)를 연결하고 Prompt ②를 넣습니다.

STEP 3. Gemini 분류 — 앞앞 Node의 문의 가져오기

Gemini 요약 뒤에 Gemini Node(이름: Gemini 분류)를 하나 더 연결합니다. 이 Node의 바로 앞은 Gemini 요약이라 $json.request가 없습니다. DAY 03에서 배운 대로 고객 문의 생성 Node의 request를 가져와야 합니다.

* Node 이름을 다르게 지었다면 $('…') 안의 이름도 똑같이 맞춰야 합니다. 헷갈리면 INPUT에서 고객 문의 생성 Node를 골라 request를 끌어다 놓으세요.

STEP 4. 시트에 저장 — 여러 Node에서 값 모으기

Google Sheets Node(Append row, 탭: ai_inquiry)를 연결하고 열마다 값을 연결합니다. INPUT 위쪽의 Node 선택 목록을 바꿔 가며 끌어다 놓으세요.

시트 열어느 Node의 무엇을 가져오나
name · email · request고객 문의 생성 Node의 같은 이름 값
summaryGemini 요약 Node의 OUTPUT 속 AI가 쓴 글(text)
categoryGemini 분류 Node의 OUTPUT 속 AI가 쓴 글(text)

* Gemini의 OUTPUT은 여러 겹으로 되어 있어 content → parts → text처럼 안쪽에 글이 들어 있을 수 있습니다. 경로를 외우지 말고 OUTPUT에서 AI가 쓴 문장이 보이는 칸을 찾아 끌어다 놓으세요.

STEP 5. AI가 쓴 요약을 이메일로 보내기

마지막으로 Gmail Node(이름: 고객 확인 메일)를 연결합니다. To에는 고객 문의 생성의 email을, 본문에는 이름과 Gemini 요약 결과를 넣습니다. 이제 AI의 Output이 실제 외부 서비스까지 전달됩니다.

[고객 문의 생성의 name]님, 안녕하세요.

문의가 정상적으로 접수되었습니다.

문의 요약:
[Gemini 요약의 결과 글]

담당자가 확인 후 안내드리겠습니다.

완성 후 확인하기

① 고객의 원문은 어느 Node에 있는가?
② Gemini의 결과는 어느 Node에 있는가?
③ 시트에는 어떤 값이 저장되었는가?
④ 이메일에는 어떤 값이 쓰였는가?

13.AI 결과 검증과 테스트

AI가 항상 정확한 결과를 만든다고 보장할 수 없습니다. AI Workflow에서는 "실행됐다"가 성공 기준이 아닙니다. 결과가 적절한지도 확인해야 합니다.

내용이 원문과 맞는가?
AI가 없는 정보를 지어내지 않았는가?
정해 준 카테고리를 썼는가?
원하는 출력 형식을 지켰는가?
중요한 정보가 빠지지 않았는가?

하나의 데이터만 테스트하지 않기

12번에서 만든 Workflow에 request를 바꿔 가며 네 번 실행하고, 시트에 쌓인 category가 예상과 맞는지 비교합니다.

Case문의예상 분류실제 결과

02카드 결제가 가능한가요?결제문의직접 기록

오류와 품질 문제는 다르다

오류 (Error) — 실행 자체가 안 됨
  • · API 인증 실패
  • · Credential 오류
  • · 필요한 데이터 없음

연결과 데이터를 확인

  • · 분류가 부정확함 · 요약이 너무 김
  • · 출력 형식이 들쭉날쭉함
  • · 필요 없는 내용을 덧붙임

Prompt와 AI 설정을 확인

결과가 마음에 들지 않을 때 — 모델부터 바꾸지 않기

1작업이 분명한가?
2카테고리를 분명히 정했는가?
3출력 형식을 정했는가?
4필요한 데이터가 실제로 전달됐는가?

핵심 — Prompt도 Workflow의 중요한 일부입니다. 결과가 나쁘면 Prompt부터 고칩니다.

14.한 번에 vs 나눠서 · 사용량

"요약하고 분류한 뒤 답변 이메일까지 작성하세요."처럼 Prompt 하나로 처리할 수도 있고, 12번처럼 요약 Node → 분류 Node → 답변 작성 Node로 나눌 수도 있습니다. 각각 장단점이 있습니다.

한 번에 처리

Workflow가 단순함 · AI 호출 횟수가 적음

Workflow가 길어짐 · AI 호출이 늘어남

Node를 무조건 많이 만드는 것이 좋은 것은 아닙니다. 필요한 만큼 나누는 것이 중요합니다.

API 호출에도 사용량이 쌓인다

Gemini Node가 실행될 때마다 Gemini API에 요청이 갑니다. 요약 → 분류 → 이메일 작성 구조라면 데이터 한 건에 AI를 세 번 부릅니다. 실제로 운영할 때는 아래를 함께 따집니다.

호출 횟수 처리할 데이터 양 사용할 모델 속도 비용 API 사용 한도

ChatGPT는 n8n 안에서 돌아가는 모델이 아니라 Workflow 만드는 과정을 돕는 보조 도구입니다. 분류 결과가 들쭉날쭉하다면 지금 쓰는 Prompt를 GPT에게 보여 주고 고쳐 달라고 할 수 있습니다.

16.최종 실습: AI 문의 정리 시스템

아래 요구사항을 보고 처음부터 Workflow를 구성합니다. 12번에서 따라 한 내용을 보지 않고 만들어 보는 것이 목표입니다.

요구사항
  • · 고객의 이름, 이메일, 문의 내용이 들어온다.
  • · AI가 문의를 읽고 summary와 category를 만든다. (category: 수업문의 · 결제문의 · 환불문의 · 기타)
  • · 시트에 이름 · 이메일 · 원문 · 요약 · 카테고리를 저장한다.
  • · 저장이 끝나면 고객에게 접수 완료 이메일을 보낸다.
  • · 쓸 서비스: n8n · Gemini · Google Sheets · Gmail
[Flow] 1단계: Manual Trigger 2단계: 고객 문의 생성 (Edit Fields) 3단계: Gemini 요약 → Gemini 분류 (또는 형식을 정한 Gemini 하나) 4단계: 문의 내역 저장 (Google Sheets · Append row) 5단계: 고객 확인 메일 (Gmail) [Input — 들어오는 데이터] 1. name 2. email 3. request [AI Output — AI가 만들 데이터] 1. summary 2. category

④ 시트에 모든 정보가 저장되었는가?

Q1사람이 Gemini 웹사이트를 쓰는 것과 n8n이 Gemini API를 쓰는 것의 차이는?답 보기

웹사이트는 사람이 직접 질문을 입력하지만, API는 프로그램(n8n)이 사람 없이 Gemini에 요청을 보내고 결과를 받아 다음 단계로 넘깁니다.

Q2API Key를 공개하면 안 되는 이유는?답 보기

다른 사람이 내 계정으로 API를 쓸 수 있고, 유료 계정이라면 그 비용도 내게 청구될 수 있기 때문입니다.

Q3Prompt에 출력 형식을 정하면 어떤 점이 좋은가?답 보기

결과가 매번 같은 모양으로 나와서 시트의 열이나 이메일 칸처럼 다음 Node에서 쓰기 쉬워집니다.

Q4요약과 정보 추출은 어떻게 다른가?답 보기

요약은 전체 내용을 짧게 줄이는 것이고, 정보 추출은 이름·날짜·이메일처럼 정해진 항목만 골라내는 것입니다.

Q5Workflow 오류와 AI 결과의 품질 문제는 어떻게 다른가?답 보기

오류는 실행 자체가 안 되는 것(연결·데이터 확인), 품질 문제는 실행은 되지만 결과가 원하는 대로 나오지 않는 것(Prompt·AI 설정 확인)입니다.
