왜 Edit Fields에 값을 바로 넣지 않고 Gemini를 쓸까?

문의 요약이나 분류를 Edit Fields에 미리 적으려면 사람이 문의를 하나하나 읽어야 합니다. 단어 규칙을 만들어도 한계가 있습니다. 예를 들어 "문의에 '환불'이 있으면 → 환불 문의"라는 규칙은 이런 문장을 놓칩니다.

단어 규칙으로는 놓침

"수업을 더 이상 들을 수 없는데 결제한 금액을 돌려받을 수 있을까요?"

'환불'이라는 단어가 없음

AI는 의미를 읽음

문장의 뜻을 읽고 "환불 문의"로 판단할 수 있습니다.

AI Workflow는 일반 Workflow 안에 AI 처리 단계가 하나 들어간 구조입니다. Gemini는 ChatGPT처럼 따로 열어 쓰는 도구이기도 하지만, n8n 안에서는 Node 하나로 들어가 데이터를 처리합니다.

4.API란?

API (에이피아이)

서로 다른 서비스가 기능이나 데이터를 주고받을 수 있도록 연결해 주는 방법입니다.

사람이 Gemini를 쓸 때

사람 → Gemini 웹사이트에 질문 입력 → Gemini 답변

n8n이 Gemini를 쓸 때

n8n → Gemini API → Gemini 처리 → 결과가 n8n으로 돌아옴

사람이 Gemini 웹페이지를 열지 않아도 n8n이 Gemini에게 일을 맡길 수 있습니다. n8n이 보내는 것은 Prompt(지시)이고, 돌아온 답은 다음 Node가 쓰는 데이터가 됩니다.

비유하자면: 음식점과 같습니다.

손님주문하는 쪽 (n8n)
직원 = API주문을 주방에 전달
주방실제로 처리 (Gemini)
완성된 음식돌아온 결과

5.API Key와 Credential

API Key (API 키)

n8n이 Gemini를 사용할 수 있도록 연결할 때 쓰는 인증 정보입니다. Gemini는 이 키를 보고 "누가 보낸 요청인지" 확인합니다.

오늘 연결 순서

Google AI Studio API Key 발급 n8n Credential 등록 Gemini 사용
API Key — Gemini 쪽에서 받는 것

Google AI Studio에서 발급받는 인증 정보입니다. 긴 영문·숫자 한 줄로 되어 있습니다.

Credential — n8n 쪽에 저장하는 것

그 키를 n8n에 저장해 두고 골라 쓰는 연결 설정입니다. DAY 03에서 만든 Google Credential과 같은 목록에 저장됩니다.

키는 Credential에 한 번만 넣습니다. Workflow 칸이나 코드에 직접 붙여넣지 않습니다.

API Key는 비밀번호처럼 관리하기

키가 새어 나가면 다른 사람이 내 계정으로 Gemini를 쓸 수 있습니다. 요금이 나오는 계정이라면 비용도 내가 내게 됩니다.

SNS · 단체 채팅방에 올리기
공개 GitHub 저장소에 올리기
화면 캡처에 키가 보이게 공유하기
다른 사람에게 내 키 전달하기

8.Prompt 쓰는 법

Prompt (프롬프트)

Gemini에게 어떤 작업을 해야 하는지 알려주는 지시입니다.

공식을 외울 필요는 없습니다. 무엇을 할 것인지 + 어떤 결과를 원하는지 두 가지만 분명하게 쓰면 됩니다.

좋지 않은 예

"정리해줘."

무엇을, 얼마나, 어떤 모양으로 정리할지 알 수 없습니다.

조금 더 좋은 예

"다음 고객 문의를 3줄 이내로 요약하고, 고객이 원하는 핵심 요청을 한 문장으로 정리해줘."

할 일(요약 · 핵심 요청)과 결과(3줄 · 한 문장)가 보입니다.

Gemini Node도 결국 Input → 처리 → Output

Input

고객 문의

처리

Prompt대로 Gemini가 내용 분석

Output

요약 결과

AI라고 해서 n8n의 데이터 흐름이 달라지지 않습니다. 앞 Node의 Output이 Gemini의 Input이 되고, Gemini의 Output이 다음 Node의 Input이 됩니다.

7번 Workflow에서 먼저 Prompt의 지시 문장을 "내용의 핵심을 한 문장으로 요약하세요."로 바꿔 두고, content 값만 아래 문장으로 바꿔 가며 실행합니다.

입력이 달라져도 같은 Workflow를 계속 다시 쓸 수 있습니다.

③ 정보 추출 — 필요한 정보만 뽑기

AI는 문장 속에서 필요한 정보만 찾아낼 수 있습니다. 아래 문장을 request에 넣고 실행해 보세요.

예상 결과
이름: 김민수
예약일: 10월 15일
시간: 오후 3시
이메일: minsu@example.com

AI가 없는 데이터를 지어낼 수 있어요

원문에 이메일이 없는데 AI가 그럴듯한 주소를 만들어 넣으면 큰 문제가 됩니다. 그래서 위 Prompt처럼 "없는 정보는 추측하지 말고 '없음'이라고 표시하라"는 조건을 꼭 넣습니다. 이메일 문장을 지우고 다시 실행해 "없음"이 나오는지 확인해 보세요.

④ 문장 생성 — AI 답변 초안 만들기

이번에는 가진 정보로 새 문장을 만듭니다. Edit Fields에 name: 김민지, request: 수업 시간 변경 문의, status: 확인중을 만듭니다. Prompt를 넣은 뒤 이름 · 문의 · 상태 뒤에 INPUT의 name · request · status를 하나씩 끌어다 놓습니다.

예상 결과
김민지님, 문의해주셔서 감사합니다.
수업 시간 변경 요청을 확인하고 있습니다.
확인되는 대로 안내드리겠습니다.

11.결과의 모양 정하기

Prompt가 너무 자유로우면 생기는 문제

"문의 내용을 분석해줘."라고만 하면 실행할 때마다 모양이 다른 답이 나옵니다.

결과 1이 문의는 수업 일정에 관한 문의입니다.
결과 2고객은 일정 변경을 희망하고 있습니다. 카테고리는 수업 문의입니다.
결과 3수업일 변경 요청으로 보입니다.

사람은 다 이해하지만, 시트의 category 열에 넣으려면 곤란합니다. 그래서 어떤 모양으로 답할지도 Prompt에 정해 줍니다.

정해진 모양의 결과 (Structured Output)

AI의 답을 매번 같은 항목으로 받는 것입니다. 일반 답변은 표현이 조금씩 달라지지만, 항목이 정해져 있으면 다음 Node가 쓰기 쉽습니다.

Gemini 결과

summary: 수업 일정 변경 가능 여부 문의
category: 수업문의

각 항목의 뜻

summary = 문의 요약

category = 문의 유형 (정해 준 네 가지 중 하나)

* 다른 자료에서 { } 괄호로 된 모양(JSON)을 볼 수도 있습니다. 같은 내용을 다른 방식으로 적은 것이니 문법은 몰라도 됩니다. 오늘은 Prompt에 "아래 형식으로만 답하세요"라고 적는 방법만 씁니다.

실습: Prompt 고쳐 쓰기

"이 문의를 정리해줘."라는 Prompt를 아래 칸을 채우며 고쳐 써 봅니다. 다 쓰면 Gemini Node에 넣고, 문의는 INPUT에서 끌어다 놓습니다.

다음 고객 문의를 분석하세요. 1. 문의 내용을 한 문장으로 요약하세요. 2. 다음 카테고리 중 하나로 분류하세요. - 수업문의 - 결제문의 - 환불문의 - 기타 3. 입력에 없는 내용은 추측하지 마세요. 아래 형식으로만 답하세요. summary: category: 고객 문의: (여기에 INPUT의 request 끌어다 놓기)

여러 문의로 실행해 보고, 매번 summary: / category: 모양이 지켜지는지 확인합니다.

12.실습: AI 고객 문의 처리

필수 실습

DAY 03에서 만든 흐름 가운데에 Gemini를 넣은 Workflow를 새로 만듭니다. Google Sheets와 Gmail은 DAY 03에서 이미 배운 Node이고 Credential도 그대로 고르면 됩니다. 달라지는 것은 Gemini가 처리한 결과를 저장하고 보낸다는 점뿐입니다.

오늘 만들 구조

요약과 분류를 Gemini Node 두 개로 나누면 각각의 결과를 시트의 다른 칸에 바로 넣을 수 있고, 어느 단계가 문제인지 찾기도 쉽습니다. Node 이름을 역할대로 바꿔 두세요.

Manual Trigger
고객 문의 생성 (Edit Fields — name · email · request)
Gemini 요약 → summary
Gemini 분류 → category
문의 내역 저장 (Google Sheets)
고객 확인 메일 (Gmail)

* 11번처럼 Gemini 하나로 요약과 분류를 한 번에 할 수도 있습니다. 처음에는 나눠서 만드는 쪽이 고치기 쉽습니다.

STEP 1. 시트에 새 탭 만들기

DAY 03의 AI_AGENT_DAY03 파일에 새 탭 ai_inquiry를 만들고, 1행에 아래 다섯 칸을 적습니다. AI가 만든 결과도 일반 데이터처럼 저장할 수 있습니다.

nameemailrequestsummarycategory

STEP 2. 고객 문의 생성 → Gemini 요약

새 Workflow에 Manual Trigger → Edit Fields(이름: 고객 문의 생성)를 놓고 name(자신의 이름), email(자신의 이메일), request를 만듭니다. request에는 "수업을 신청했는데 개인 일정 때문에 다른 날짜로 변경하고 싶습니다."를 넣습니다. 그 뒤에 Gemini Node(이름: Gemini 요약)를 연결하고 9번의 Prompt ①(문의 요약)을 넣습니다. Gemini Credential은 7번에서 만든 것을 고릅니다.

STEP 3. Gemini 분류 — 두 칸 앞 Node의 문의 가져오기

Gemini 요약 뒤에 Gemini Node(이름: Gemini 분류)를 하나 더 연결하고 9번의 Prompt ②(문의 분류)를 넣습니다. 이 Node의 바로 앞은 Gemini 요약이라 INPUT에 request가 바로 보이지 않습니다.

INPUT 위쪽 Node 선택 목록에서 "고객 문의 생성"을 고르면 그 Node의 request가 보입니다. 거기서 "문의:" 아래로 끌어다 놓으세요. DAY 03에서 Gmail에 Edit Fields 값을 가져온 방법과 같습니다. 칸 안의 표시가 조금 길어져도 정상입니다.

STEP 4. 시트에 저장 — 여러 Node에서 값 모으기

Google Sheets Node(Append row in sheet, 탭: ai_inquiry)를 연결하고 DAY 03 Credential을 고릅니다. INPUT 위쪽의 Node 선택 목록을 바꿔 가며 열마다 값을 끌어다 놓으세요.

시트 열어느 Node의 무엇을 가져오나
name · email · request고객 문의 생성 Node의 같은 이름 값
summaryGemini 요약 Node의 OUTPUT 속 AI가 쓴 글(text)
categoryGemini 분류 Node의 OUTPUT 속 AI가 쓴 글(text)

* Gemini의 OUTPUT은 여러 겹으로 접혀 있어 AI가 쓴 글이 안쪽에 있을 수 있습니다. 화살표를 펼쳐 AI가 쓴 문장이 보이는 text 칸을 찾아 끌어다 놓으세요.

STEP 5. AI가 쓴 요약을 이메일로 보내기

마지막으로 Gmail Node(이름: 고객 확인 메일, Send a message)를 연결하고 DAY 03의 Gmail Credential을 고릅니다. To에는 고객 문의 생성의 email을 끌어다 놓고, Subject는 "문의가 접수되었습니다"처럼 직접 입력합니다. 본문에는 이름과 Gemini 요약 결과를 끌어다 놓습니다. 이제 AI의 Output이 실제 외부 서비스까지 전달됩니다.

본문 완성 모양 고객 문의 생성의 name님, 안녕하세요.

문의가 정상적으로 접수되었습니다.

Gemini 요약의 text

혼자 해결이 안 되면 ChatGPT와 함께

ChatGPT는 n8n 안에서 돌아가는 모델이 아니라 Workflow 만드는 과정을 돕는 보조 도구입니다. 지금 화면과 원하는 결과를 설명하면 해결 방법을 함께 찾을 수 있습니다.

실행 어느 Node에서 멈췄는지 확인 화면 캡처 지금 결과 · 원하는 결과 설명 수정 다시 실행
이 정도로 말하면 충분합니다 (캡처와 지금 Prompt를 함께) "n8n에서 Gemini로 고객 문의를 수업문의 · 결제문의 · 환불문의 · 기타 중 하나로 분류하고 있습니다. 그런데 '결제 관련 문의입니다.'처럼 설명이 붙어서 나옵니다. 카테고리 이름 하나만 나오게 하고 싶습니다. Prompt를 어떻게 고치면 될까요?"

캡처를 올리기 전에 API Key가 화면에 보이지 않는지 꼭 확인하세요.

스스로 확인하기

먼저 답을 떠올린 뒤 눌러서 확인하세요.

Q1사람이 Gemini 웹사이트를 쓰는 것과 n8n이 Gemini API를 쓰는 것의 차이는?답 보기

웹사이트는 사람이 직접 질문을 입력하지만, API를 쓰면 n8n이 사람 없이 Gemini에 일을 맡기고 결과를 받아 다음 단계로 넘깁니다.

Q2API Key와 Credential은 어떻게 다른가?답 보기

API Key는 Google AI Studio에서 발급받는 인증 정보이고, Credential은 그 키를 n8n에 저장해 두고 Node에서 골라 쓰는 연결 설정입니다. 키는 다른 사람이 내 계정으로 쓸 수 있으니 공개하지 않습니다.

Q3Prompt에 결과 모양을 정하면 어떤 점이 좋은가?답 보기

결과가 매번 같은 항목으로 나와서 시트의 열이나 이메일 칸처럼 다음 Node에서 쓰기 쉬워집니다.

Q4고객 후기 요약과 회의 메모 정리를 만들려면 새 Node가 필요한가?답 보기

아닙니다. 같은 Edit Fields → Gemini 구조에서 입력 데이터와 Prompt만 바꾸면 됩니다.

Q5Workflow 오류와 AI 결과의 품질 문제는 어떻게 다른가?답 보기

오류는 실행 자체가 안 되는 것(연결·데이터 확인), 품질 문제는 실행은 되지만 결과가 원하는 대로 나오지 않는 것(Prompt부터 확인)입니다.
