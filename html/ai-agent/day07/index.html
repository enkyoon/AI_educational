순서

도구보다 문제가 먼저입니다. "n8n으로 뭘 만들까?"가 아니라 "무엇이 귀찮고 반복되는가?"에서 시작합니다.

개인 프로젝트는 Workflow 또는 Agent 중 목적에 맞는 구조를 고릅니다. 이름이 "AI Agent 과정"이라고 모든 것을 Agent로 만들 필요는 없습니다. 처음 만드는 사람은 대부분 AI Workflow로 충분하고, Agent는 AI가 스스로 Tool을 골라야 할 때만 씁니다 (8번에서 판단).

5.큰 문장을 작은 행동으로 나누기

"고객 문의를 자동으로 관리하고 싶다"는 아직 너무 큽니다. 한 번에 하나씩 일어나는 행동으로 쪼갭니다.

큰 문장

고객 문의를 자동으로 관리하고 싶다

작은 행동
  • 1. 문의가 들어온다
  • 2. AI가 내용을 요약한다
  • 3. AI가 종류를 나눈다
  • 4. 시트에 저장한다
  • 5. 급하면 담당자에게 알린다

오늘 계속 쓰는 다섯 가지 질문

1무엇이 들어오는가? (Input)
2무엇을 해야 하는가? (처리)
3무엇이 나와야 하는가? (Output)
4어디에 저장·전달하는가?
5언제 시작되는가? (Trigger)

6.실습: 흐름 · Input · Output 쓰기

흐름 (User Flow)

사용자가 무엇을 하면 → 시스템이 무엇을 하고 → 결과가 어떻게 나오는지를 순서대로 적은 것입니다. Node 이름을 몰라도 우리말로 쓰면 됩니다.

Input — 들어오는 것

사용자가 주는 정보, 외부에서 오는 데이터
예: 이름 · 이메일 · 문의 내용

처리 — 그 사이에서 하는 일

요약 · 분류 · 계산 · 판단
예: AI가 문의 종류를 판단

Output — 나가는 것

저장되는 것, 보내지는 것, 보여 주는 것
예: 시트 한 줄 · 알림 메일

[흐름] 1. 내가 오늘 공부한 내용을 채팅으로 보낸다 2. AI가 핵심 3줄로 요약한다 3. AI가 복습 질문 3개를 만든다 4. 시트에 날짜 · 요약 · 질문을 저장한다 5. 나에게 정리 메일이 온다 [Input] 공부한 내용(글) [Output] 시트 한 줄(날짜 · 요약 · 질문), 정리 메일

7.실습: AI가 필요한 곳 표시하기

흐름의 모든 칸에 AI가 필요한 것은 아닙니다. 각 단계 옆에 [규칙] 또는 [AI]를 붙여 보세요.

[규칙] — 정해진 대로 하면 됨
  • · 시트에 저장한다
  • · 금액이 10만 원 이상인지 본다
  • · 날짜를 붙인다
  • · 정해진 주소로 메일을 보낸다
[AI] — 의미를 읽어야 함
  • · 내용을 요약한다
  • · 무슨 종류인지 판단한다
  • · 감정을 읽는다
  • · 답장 문장을 쓴다

AI를 많이 넣을수록 좋은 것이 아닙니다. 규칙으로 되는 곳은 규칙으로 — 더 빠르고, 더 정확하고, 비용도 적습니다.

8.실습: Workflow인가 Agent인가?

구조이럴 때예
일반 Workflow항상 같은 순서신청서 → 시트 저장 → 확인 메일
조건 Workflow정해진 몇 갈래로 나뉨금액별 · 종류별 처리
AI Workflow순서는 같고 중간에 AI가 읽고 씀문의 요약 → 저장
AI Agent요청이 다양하고 그때그때 할 일이 다름채팅으로 조회 · 등록 · 메일을 골라서

구조 고르기 체크

  • 할 일의 순서가 매번 같은가? → 예라면 Workflow
  • 조건에 따라 정해진 몇 갈래로만 나뉘는가? → 조건 Workflow
  • 사용자가 여러 종류의 요청을 자유롭게 하는가? → Agent를 고려
  • Agent가 아니면 정말 안 되는가? 더 단순한 방법은 없는가?

처음 만드는 사람은 대부분 AI Workflow로 충분합니다. Agent는 필요할 때만.

내 프로젝트의 수준 고르기

10.흐름을 Node 후보로 바꾸기

2교시 · 기획을 n8n 구조로 바꾸기

흐름의 한 줄이 꼭 Node 하나는 아닙니다. 흐름 옆에 필요해 보이는 Node를 적어 봅니다. 정확한 이름을 몰라도 괜찮습니다.

흐름Node 후보
후기를 입력한다Manual Trigger + Edit Fields (또는 Chat Trigger)
AI가 감정을 판단한다Gemini (Message a model)
시트에 저장한다Google Sheets (Append row)
부정이면IF
알림 메일을 보낸다Gmail (Send)

"?"로 남은 칸은 AI에게 물어봅니다 — "n8n에서 [하고 싶은 일]을 하려면 어떤 Node를 쓰나요? 초보자용으로 하나만 추천해 주세요."

문제 해결 루틴

기획 단계에서도 루틴을 씁니다. 필요한 Node를 모를 때 GPT에게 묻고, ⑤ 단계처럼 그 Node가 내 n8n에 실제로 있는지, 이름과 설정이 같은지 직접 확인합니다.

① 어디까지 정상인지 확인② 화면 캡처③ 지금 상황 설명④ 원하는 결과 설명⑤ 답을 내 화면과 비교⑥ 직접 수정⑦ 다시 실행⑧ 결과 검증
이번에 캡처할 곳기획서의 흐름 · 지금 n8n 캔버스
질문 쓰기틀 없이 직접 — 만들려는 것 · 지금 흐름 · 모르는 부분 · 원하는 답의 모양(예: Node 후보와 이유)

11.AI에게 설계 검토받기

"이거 만들어줘"라고 통째로 맡기지 않습니다. 내 생각을 먼저 보여 주고 빠진 곳을 짚어 달라고 합니다. 그래야 내 프로젝트로 남습니다.

AI 답변을 검토할 때

  • 내 목적과 다른 방향으로 바꾸지 않았는가?
  • 지금 배운 범위 밖의 어려운 기능을 권하지 않는가?
  • 받아들일 것 / 받아들이지 않을 것을 내가 골랐는가?

AI가 매번 구조를 통째로 바꾸게 두면 끝나지 않습니다. 결정은 내가 합니다.

12.실습: 한 번에 다 만들지 않기

최소 버전 (Minimum Version)

핵심 기능 하나만 일단 끝까지 작동하는 가장 작은 버전입니다. 이게 되면 하나씩 더합니다.

VERSION 1 — 오늘 · 다음 시간 목표

입력 → AI 처리 → 시트 저장

VERSION 2 — 시간이 남으면

+ 조건 분기, + 알림 메일

VERSION 3 — 나중에

+ 채팅 Agent, + Tool 여러 개

기능 우선순위 — 꼭 · 있으면 좋음 · 언젠가

너무 큰 프로젝트는 줄인다

"고객 관리 · 결제 · 예약 · 메일 · 통계를 다 하는 Agent" → 다음 시간 안에 끝나지 않습니다. "고객 조회 + 등록만 하는 Agent"처럼 하나로 줄이세요. 작게 끝낸 것이 크게 시작한 것보다 낫습니다.

13.실습: n8n에 뼈대 세우기

이제 n8n을 엽니다. 새 Workflow DAY07_[프로젝트 이름]을 만들고 VERSION 1의 Node를 순서대로 놓기만 합니다. 설정은 다음 시간에 해도 됩니다.

  1. 1흐름 순서대로 Node를 캔버스에 놓고 연결합니다
  2. 2Node 이름을 역할대로 바꿉니다 (예: 후기 입력 · AI 감정 판단 · 후기 저장 · 부정 후기 확인 · 알림 메일)
  3. 3캔버스 빈 곳에 Sticky Note(메모)를 붙이고 한 줄 설명을 적습니다 (빈 곳을 오른쪽 클릭하거나 Shift + S)
  4. 4캔버스를 보며 처음부터 끝까지 흐름을 소리 내지 않고 읽어 봅니다 — 기획서와 같은가요?

데이터 이름표 정하기

Node끼리 주고받을 데이터 이름을 지금 정해 두면 다음 시간에 헷갈리지 않습니다. 영어 소문자로 짧게 씁니다.
