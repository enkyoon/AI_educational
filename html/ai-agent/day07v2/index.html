■ 반복하는 일 다섯 가지 1. 하는 일: 거래처 요청을 요약하고 접수 기록과 답장 초안 만들기 반복 주기: 요청을 받을 때마다 번거로운 점: 메일을 다시 읽고 시트와 답장에 같은 내용을 옮긴다. 2. 하는 일: 구매·시설·IT 요청을 담당 업무별로 정리하기 반복 주기: 매일 번거로운 점: 담당 부서를 고르고 요청을 다시 전달해야 한다. 3. 하는 일: 진행 중인 업무의 상태를 찾아 알려 주기 반복 주기: 상태를 물어볼 때마다 번거로운 점: 시트를 열어 요청 번호와 담당자를 반복해서 찾는다. 4. 하는 일: 회의 메모에서 할 일과 담당자 정리하기 반복 주기: 회의를 마칠 때마다 번거로운 점: 메모를 읽고 업무 목록에 다시 옮긴다. 5. 하는 일: 기한이 가까운 업무를 모아 보고 초안 만들기 반복 주기: 매일 업무를 마칠 때 번거로운 점: 여러 행을 확인하고 보고 문장을 다시 쓴다. ■ 이번에 만들어 볼 자동화 고른 일: 거래처 요청 정리와 답장 초안 만들기 선택 이유: 요청을 읽고 기록하고 답장 준비하는 반복 작업을 줄이고 싶다.

처음 만들기 쉬운 일 — 자주 반복되고, 들어오는 정보의 모양이 비슷하고, 결과의 모양이 정해진 일입니다. 꼭 다 맞아야 하는 조건은 아니고, 많이 맞을수록 만들기 쉽습니다. 생각이 안 나면 Gemini에게 "나는 [직업이나 역할 — 예: 학원 행정 담당자]야. 문의 정리·시트 저장·메일 안내 중 n8n으로 줄일 만한 반복 업무를 추천해줘"라고 물어보세요.

5.실습: 입력부터 결과까지 흐름 정리하기

흐름 (User Flow)

사용자가 무엇을 하면 → 시스템이 무엇을 하고 → 결과가 어떻게 나오는지를 순서대로 적은 것입니다. Node 이름을 몰라도 우리말로 쓰면 됩니다.

Input — 들어오는 것

사용자가 주는 정보, 외부에서 오는 데이터
예: 이름 · 이메일 · 문의 내용

처리 — 그 사이에서 하는 일

요약 · 분류 · 계산 · 판단
예: AI가 문의 종류를 판단

Output — 나가는 것

저장되는 것, 보내지는 것, 보여 주는 것
예: 시트 한 줄 · 알림 메일

먼저 우리말로 적습니다. 단계 수는 내 흐름에 맞게 늘리거나 줄이고, 필요 없는 단계는 지우세요.

■ 시작할 때 주는 정보 입력할 내용: 요청 번호(request_id), 연락처(contact_email), 요청 내용(request_text) 입력하는 곳: 요청 입력(Edit Fields) ■ 처리할 순서 1. 시작: 내가 Execute를 누른다. 2. 입력 준비: 요청 번호·연락처·요청 내용을 넣는다. 3. 핵심 처리: LLM이 요청 내용·기한·추가 확인 사항을 요약한다. 4. 결과 저장: 연락처가 있으면 requests에, 없으면 needs_followup에 기록한다. 5. 마무리: 연락처가 있는 요청만 LLM으로 답장 본문을 만들고 Gmail 임시보관함에 저장한다. ■ 마지막에 확인할 결과 저장할 내용: 요청 번호·연락처·원문·요약이 같은 기록으로 남음 알려 줄 내용: 자동 발송은 하지 않음. 담당자가 초안을 확인한 뒤 사용

6.실습: 어떤 구조가 필요한가?

구조이럴 때예
일반 Workflow항상 같은 순서신청서 → 시트 저장 → 확인 메일
조건 Workflow (IF · Switch)정해진 몇 갈래로 나뉨금액별 · 종류별 처리
AI Workflow순서는 같고 중간에 AI가 읽고 씀문의 요약 → 저장
AI Agent요청에 따라 AI가 연결된 Tool을 골라야 함채팅으로 조회 · 메일 중 골라서 (DAY 06)

구조 고르기 체크

  • 할 일의 순서가 매번 같은가? → 예라면 Workflow
  • 조건에 따라 정해진 몇 갈래로만 나뉘는가? → 조건 Workflow
  • 요청에 따라 AI가 조회·메일 같은 Tool을 골라 실행해야 하는가? → Agent를 고려
  • Agent가 아니면 정말 안 되는가? 더 단순한 방법은 없는가?

저장·계산·조건 비교만 필요하면 일반 또는 조건 Workflow로 시작합니다. 글을 읽거나 쓰는 단계에 AI를 넣고, Tool 선택까지 맡길 때 Agent를 고려합니다.

네 구조는 서로 완전히 나뉜 종류가 아닙니다. AI Workflow에도 IF를 넣을 수 있고, AI Agent도 Workflow 안에서 동작합니다. 위 표는 내 작업에서 어떤 처리가 필요한지 고르기 위한 안내입니다.

내 프로젝트의 수준 고르기

어느 수준이든 완성하면 좋은 프로젝트입니다. 지금까지 따라온 정도를 보고 다음 시간까지 끝까지 돌릴 수 있는 수준을 고르세요. 기본형을 먼저 완성하고 시간이 남으면 한 단계 올려도 됩니다.

수준구조예시시작 프로젝트 (9번)
기본형Workflow 또는 조건 Workflow신청 내용을 시트에 저장하고 확인 메일 보내기—
응용형AI Workflow (+ 조건)거래처 요청을 요약하고 IF로 접수·보완을 나눈 뒤 답장 초안A 거래처 요청 정리 · B 사내 요청 배정
도전형AI Agent + Tool채팅으로 요청하면 업무 조회·등록·메일 초안 중 골라 실행C 업무 지원 Agent

앞의 구조 비교표에서 내 작업에 필요한 처리를 골라 적습니다. AI가 필요 없다면 AI에게 맡길 일에는 없음이라고 써도 됩니다.

■ 내가 만들 구조 프로젝트 수준: 응용형 처리 구조: AI Workflow + IF 선택 이유: 처리 순서는 정해져 있고, 글의 요약과 초안 작성만 LLM이 한다. ■ 역할 나누기 AI에게 맡길 일: 요청 요약, 답장 초안 작성 정해진 규칙으로 처리할 일: 연락처 빈칸 확인, 시트 기록, 임시보관함 저장 ■ 연결할 곳 사용할 서비스: Google Sheets, Gmail 저장할 위치: AI_AGENT_DAY07 파일의 requests·needs_followup 탭, Gmail 임시보관함

8.실습: 시험할 입력과 기대 결과 정하기

만들기 전에 "무엇이 들어오면 무엇이 나와야 성공인지"를 정해 둡니다. 만든 뒤 이 메모와 실제 결과를 비교합니다.

실제로 넣어 볼 값과 확인할 결과를 적습니다. 직접 확인하는 것과 자동으로 처리하는 것을 구분하세요. 자동으로 빈칸을 막으려면 IF 조건이나 Agent의 추가 질문까지 만들어야 합니다.

■ 확인 1. 대표적인 입력 넣어 볼 값: RQ-101, 내 Gmail의 연습용 별칭 주소, 모니터 12대 견적과 납기 확인 요청 기대하는 결과: requests에 기록되고 Gmail 임시보관함에 답장 초안이 생김 확인할 곳: requests 탭과 Gmail 임시보관함 ■ 확인 2. 다른 내용의 요청 넣어 볼 값: RQ-102, 내 Gmail의 연습용 별칭 주소, 테이블 4개 설치비 확인 요청 기대하는 결과: 모니터 요청 내용이 섞이지 않고 설치비 확인이 필요한 새 초안 생성 확인할 곳: 시트 원문·요약과 초안 본문 ■ 확인 3. 필요한 정보가 빠진 입력 빠진 정보: contact_email이 빈칸 처리 방법: IF에서 연락처가 비어 있는지 비교 기대하는 결과: needs_followup에 기록되고 Gmail 초안은 생기지 않음 ■ 완성 확인 요청 번호·원문·요약이 일치하고 연락처가 없는 요청이 보완 목록으로 간다. 초안에 없는 가격·납기 약속을 만들지 않는다.

기획 점검표 — 만들기 전에

  • 목적이 한 줄로 설명되는가?
  • Input과 Output이 분명한가?
  • 흐름이 순서대로 적혀 있는가?
  • AI가 필요한 곳과 아닌 곳을 나눴는가?
  • 정해진 처리·AI 판단·Tool 선택 중 무엇이 필요한지 이유와 함께 정했는가?
  • 먼저 만들 범위가 오늘과 다음 시간에 직접 확인할 만큼 구체적인가?
  • 시험할 입력과 직접 확인할 결과가 있는가?

11.실습: n8n에 뼈대 세우기

이제 n8n을 엽니다. 먼저 만들 흐름의 Node를 순서대로 놓기만 합니다. 설정은 다음 섹션에서 한 칸씩 합니다. Agent 프로젝트의 Chat Model과 Tool은 주 흐름 옆이 아니라 AI Agent 아래 전용 연결에 붙입니다.

STEP 1새 Workflow 만들기

  1. n8n 왼쪽 위 + → Workflow
  2. 왼쪽 위 이름을 눌러 DAY07_[프로젝트 이름]으로 바꿉니다.

STEP 2Node를 순서대로 놓기

  1. Add first step을 눌러 기획서의 시작(트리거)을 고릅니다.
  2. Node 오른쪽 +를 눌러 기획서 순서대로 다음 Node를 붙입니다. 아직 설정은 비워 둡니다.
  3. Node를 하나씩 선택하고 F2를 눌러 이름을 역할대로 바꿉니다 (예: 요청 입력 · 요청 요약 · 요약 정리 · 접수 기록 · 답장 초안).
  4. Canvas 빈 곳을 오른쪽 클릭 → Add sticky note(또는 Shift + S)로 메모를 붙이고 한 줄 설명을 적습니다.

Canvas만 보고 처음부터 끝까지 흐름을 읽었을 때 기획서와 같으면 성공입니다.

12.실습: 한 단계 설정하고, 실행 결과 확인하기

앞에서 놓은 Node를 처음부터 하나씩 설정합니다. 한 단계가 끝날 때마다 그 단계까지 실행해 OUTPUT을 확인하고 다음으로 넘어갑니다.

순서하나 설정하고, 한 번 실행하기

  1. 시작 방식에 맞는 입력을 준비합니다. Manual Trigger 방식은 뒤의 Edit Fields에 값을 넣고, Chat Trigger 방식은 채팅으로 요청합니다.
  2. 입력 Node를 실행한 뒤 OUTPUT에서 기획한 데이터가 들어왔는지 확인합니다.
  3. AI를 사용하는 프로젝트는 AI Node를 실행하고 실제 응답을 확인합니다. AI가 필요 없는 흐름은 이 단계를 건너뜁니다.
  4. 저장 Node(Google Sheets)를 붙이고 Execute step → 시트 확인
  5. 조건 분기는 선택한 갈래로 흘러가는지 확인합니다. Agent의 Tool은 채팅으로 요청한 뒤 실행 기록에서 사용 여부와 결과를 확인합니다.
  6. 외부 작업은 마지막에 연결하고 결과를 직접 확인합니다. 시작 프로젝트의 Gmail은 발송이 아닌 초안 저장입니다.

실습 01 · 입력부터 확인

  • Trigger 뒤 첫 Node의 OUTPUT에 내가 넣은 데이터가 그대로 있는가?
  • 데이터 이름표가 기획서와 같은가? (request_id인데 다른 곳에서 requestId으로 쓰지 않았는가?)

이름표가 섞이면 뒤 Node에서 값이 비어 버립니다. 처음 정한 이름을 끝까지 그대로 씁니다.

실습 02 · AI 단계 확인

AI Node를 붙였으면 서로 다른 입력 세 개로 실행해 보고, 결과가 기대와 다르면 Prompt에 들어간 원문과 요청·결과 형식부터 고칩니다.

오류 (Error) — 실행이 멈춤

빨간 표시, 연결 실패, 값 없음
→ Credential · 연결 · 데이터 확인

품질 문제 — 실행은 되는데 결과가 아쉬움

분류가 틀림, 너무 김, 모양이 들쭉날쭉
→ Prompt · 결과 모양 · 예외 설명 확인
