3.정해진 길 vs 스스로 고르는 길

1교시 · AI Agent 맛보기

DAY 05의 문의 분배 Workflow는 이렇게 생겼습니다. 환불이면 이 길, 수업이면 저 길 — 사람이 그려 둔 길 밖으로는 갈 수 없습니다.

문의 Gemini 분류 Switch 정해진 담당 경로

그런데 요청이 이렇게 다양하다면 어떨까요?

요청 1

"김민지 고객의 신청 상태 알려줘."

→ 시트에서 찾아야 함

요청 2

"최유진 고객을 새로 등록해줘."

→ 시트에 써야 함

요청 3

"오늘 실습 끝났다고 테스트 메일 보내줘."

→ 메일을 보내야 함

요청마다 할 일이 다릅니다. Agent는 요청을 읽고 연결된 Tool 중에서 필요한 것을 골라 씁니다.

종류누가 길을 정하나예
일반 Workflow사람 — 항상 같은 길입력 → 저장 → 메일
조건 Workflow사람 — 조건별 길을 미리 그림환불이면 A, 수업이면 B
AI AgentAI — 요청을 보고 Tool 선택조회가 필요하면 조회, 메일이 필요하면 메일

Agent도 아무거나 할 수 있는 건 아니에요

Agent는 내가 연결해 준 Tool 안에서만 고릅니다. 삭제 Tool을 연결하지 않았다면 삭제는 할 수 없습니다. 무엇을 쥐여 줄지는 만드는 사람이 정합니다.

4.AI Agent의 네 가지 구성

Agent를 새로 들어온 신입 사원이라고 생각하면 쉽습니다.

Model — 두뇌

요청을 이해하고 무엇을 할지 판단합니다. 오늘은 Gemini를 씁니다.

Tool — 손발

실제로 일을 하는 도구. 시트 조회, 시트 기록, 메일 발송 등.

System Message — 업무 지침서

"너는 누구이고, 언제 어떤 도구를 쓰고, 무엇은 하지 마라."

Memory — 대화 기억

방금 나눈 대화를 기억합니다. "아까 그 고객" 같은 말을 알아듣게 합니다. (선택)

Tool이 없는 Agent는 아는 척만 할 수 있다

Gemini는 우리 회사 고객 명단을 모릅니다. Tool 없이 "김민지 고객 상태 알려줘"라고 하면 모른다고 하거나, 최악의 경우 그럴듯하게 지어냅니다. Tool을 연결해야 실제 데이터를 보고 답합니다.

5.실습: 고객 데이터 시트 준비

Gmail은 아이디 뒤에 +글자를 붙여도 내 메일함으로 옵니다. 예: myname+minji@gmail.com → myname@gmail.com 메일함. 그래서 Agent가 실수로 메일을 보내도 실제 다른 사람에게 가지 않습니다.

7.실습: Tool ① 고객정보조회

일반 Workflow의 Google Sheets는 순서가 오면 무조건 실행됩니다. Tool로 붙인 Google Sheets는 Agent가 필요하다고 판단할 때만 실행됩니다.

  1. 1AI Agent 아래 Tool의 +를 눌러 Google Sheets Tool을 고릅니다
  2. 2Node 이름을 고객정보조회로 바꿉니다
  3. 3Operation(작업)은 Get Row(s)(행 가져오기), 문서는 AI_AGENT_DAY06, 시트는 customers
  4. 4Filters에 name 열을 고르고, 값 칸은 비워 두는 대신 AI가 정하도록 합니다 — 값 칸 옆의 ✨ 버튼(모델이 정하기)을 누르면 됩니다
  5. 5Tool Description(Tool 설명)을 직접 쓰기로 바꾸고 아래 설명을 넣습니다

* ✨ 버튼 모양과 이름은 버전에 따라 다를 수 있습니다. 보이지 않으면 필터 없이 시트 전체를 가져오게 두어도 실습은 됩니다 — Agent가 전체 목록에서 찾습니다.

Tool 이름과 설명이 Agent의 판단 기준이다

Agent는 Tool의 이름과 설명을 읽고 언제 쓸지 정합니다. Google Sheets, Google Sheets1처럼 두면 무엇이 무엇인지 모릅니다. 이름은 역할대로, 설명에는 언제 쓰고 언제 쓰지 않는지를 씁니다.

11.실습: 흐름 · Input · Output 쓰기

흐름 (User Flow)

사용자가 무엇을 하면 → 시스템이 무엇을 하고 → 결과가 어떻게 나오는지를 순서대로 적은 것입니다. Node 이름을 몰라도 우리말로 쓰면 됩니다.

Input — 들어오는 것

사용자가 주는 정보, 외부에서 오는 데이터
예: 이름 · 이메일 · 문의 내용

처리 — 그 사이에서 하는 일

요약 · 분류 · 계산 · 판단
예: AI가 문의 종류를 판단

Output — 나가는 것

저장되는 것, 보내지는 것, 보여 주는 것
예: 시트 한 줄 · 알림 메일

[흐름] 1. 내가 오늘 공부한 내용을 채팅으로 보낸다 2. AI가 핵심 3줄로 요약한다 3. AI가 복습 질문 3개를 만든다 4. 시트에 날짜 · 요약 · 질문을 저장한다 5. 나에게 정리 메일이 온다 [Input] 공부한 내용(글) [Output] 시트 한 줄(날짜 · 요약 · 질문), 정리 메일

12.실습: Workflow인가 Agent인가?

구조이럴 때예
일반 Workflow항상 같은 순서신청서 → 시트 저장 → 확인 메일
조건 Workflow정해진 몇 갈래로 나뉨금액별 · 종류별 처리
AI Workflow순서는 같고 중간에 AI가 읽고 씀문의 요약 → 저장
AI Agent요청이 다양하고 그때그때 할 일이 다름채팅으로 조회 · 등록 · 메일을 골라서

구조 고르기 체크

  • 할 일의 순서가 매번 같은가? → 예라면 Workflow
  • 조건에 따라 정해진 몇 갈래로만 나뉘는가? → 조건 Workflow
  • 사용자가 여러 종류의 요청을 자유롭게 하는가? → Agent를 고려
  • Agent가 아니면 정말 안 되는가? 더 단순한 방법은 없는가?

처음 만드는 사람은 대부분 AI Workflow로 충분합니다. Agent는 필요할 때만.

예시 ③ · 고객 관리 Agent

예시 ④ · 학습 정리 AI

공부 내용 → AI 요약 + 복습 질문 → 시트 + 메일 (AI Workflow)

예시 ⑤ · 후기 분석

후기 입력 → AI 감정 판단 → 부정 후기만 담당자 알림 (조건 + AI Workflow)

프로젝트 이름: 후기 감정 알림이 해결하고 싶은 문제: 후기가 많아 불만 후기를 늦게 발견한다 사용자: 쇼핑몰 운영자(나) 구조: 조건 + AI Workflow Input: 고객 이름, 후기 내용 Output: 시트 한 줄(이름 · 후기 · 감정 · 이유), 부정 후기 알림 메일 핵심 흐름: 1. 후기를 입력한다 2. AI가 긍정 · 중립 · 부정과 이유 한 줄을 정한다 3. 시트에 저장한다 4. 부정이면 나에게 알림 메일을 보낸다 AI가 하는 일: 감정 판단, 이유 한 줄 연결 서비스: Google Sheets, Gmail

  2. 2Node 이름을 역할대로 바꿉니다 (예: 후기 입력 · AI 감정 판단 · 후기 저장 · 부정 후기 확인 · 알림 메일)
  3. 3캔버스 빈 곳에 Sticky Note(메모)를 붙이고 한 줄 설명을 적습니다 (빈 곳을 오른쪽 클릭하거나 Shift + S)
  4. 4캔버스를 보며 처음부터 끝까지 흐름을 소리 내지 않고 읽어 봅니다 — 기획서와 같은가요?
