4.완벽한 프로젝트보다 작동하는 프로젝트

MUST — 오늘 반드시

입력 → 핵심 처리 → 결과 저장. 이것이 끝까지 돌아야 함

SHOULD — 시간이 남으면

분기, 알림 메일, Tool 하나 더

COULD — 기록만

"나중에 추가하고 싶은 기능"으로 적어 둠

기획서를 다시 읽고 흐름 옆에 Node를 적습니다. 지난 시간 만든 뼈대가 있으면 불러오고, 없으면 새로 놓습니다.

5.실습: 한 칸 연결하고, 한 번 실행하기

Node를 다 붙여 놓고 한꺼번에 실행하면, 어디서 틀렸는지 찾기 어렵습니다. 하나 붙일 때마다 실행해서 OUTPUT을 확인합니다.

1Trigger + 입력 데이터 → 실행, INPUT/OUTPUT 확인
2AI Node 붙이기 → 실행, AI가 쓴 글 확인
3저장 Node 붙이기 → 실행, 시트 확인
4분기(IF·Switch) 또는 Tool 붙이기 → 실행
5메일 같은 외부 발송은 맨 마지막에

실습 01 · 입력부터 확인

  • Trigger 뒤 첫 Node의 OUTPUT에 내가 넣은 데이터가 그대로 있는가?
  • 데이터 이름표가 기획서와 같은가? (name인데 다른 곳에서 customer_name으로 쓰지 않았는가?)

이름표가 섞이면 뒤 Node에서 값이 비어 버립니다. 처음 정한 이름을 끝까지 그대로 씁니다.

실습 02 · AI 단계 확인

AI Node를 붙였으면 서로 다른 입력 세 개로 실행해 보고, 결과가 기대와 다르면 모델을 바꾸기 전에 Prompt부터 고칩니다.

오류 (Error) — 실행이 멈춤

빨간 표시, 연결 실패, 값 없음
→ Credential · 연결 · 데이터 확인

품질 문제 — 실행은 되는데 결과가 별로

분류가 틀림, 너무 김, 모양이 들쭉날쭉
→ Prompt · 결과 모양 · 예외 설명 확인

내 프로젝트 구조에 맞는 표 하나를 채웁니다. 모든 길, 모든 Tool을 한 번씩 지나가게 하는 것이 목표입니다.

7.디버깅 — 어디까지는 정상인가?

디버깅 (Debugging)

문제가 생긴 위치와 원인을 찾아 고치는 일입니다. 처음 실행에서 완벽한 사람은 없습니다. 실패는 과정의 일부입니다.

가장 중요한 질문은 하나입니다 — "어디까지는 정상인가?" 앞 Node부터 OUTPUT을 하나씩 열어, 처음으로 이상해지는 지점을 찾습니다.

Trigger ✓ 입력 ✓ AI ✓ 저장 ✗ ← 여기부터 확인 메일

실습 · 오류 기록하기

문제가 생길 때마다 Google 문서에 한 줄씩 적습니다. 이 기록이 그대로 프로젝트 기록이 됩니다.

8.AI에게 문제 물어보기 — 정리해서 묻고, 검증하고, 하나씩

"안 돼요, 고쳐 주세요"로는 좋은 답이 나오지 않습니다. 오류 기록을 그대로 붙여 묻습니다.

캡처할 것

Workflow 전체 · 문제 Node의 설정 · INPUT · OUTPUT/오류 화면

가릴 것

API Key · 비밀번호 · 실제 개인정보가 보이지 않게

답을 받은 뒤

AI 답도 틀릴 수 있습니다. 한 번에 하나만 고치고 바로 실행해 확인합니다

여러 군데를 한꺼번에 고치면 무엇 때문에 고쳐졌는지(또는 망가졌는지) 알 수 없습니다.

12.실습: 프로젝트 기록 쓰고 제출하기

Google 문서 DAY08_프로젝트기록_이름을 만들고 아래 틀을 채웁니다. 오늘 쓴 오류 기록과 테스트 결과표를 그대로 옮기면 됩니다.

함께 낼 것

  1. 1Workflow 전체 화면 캡처 1장 — 문서에 붙여 넣기 (API Key · 개인정보가 보이지 않게)
  2. 2결과 화면 캡처 1장 — 저장된 시트나 받은 메일
  3. 3Workflow 파일 — n8n 오른쪽 위 ⋯ 메뉴 → Download로 내려받은 파일 (메뉴 이름은 버전에 따라 다를 수 있음)
  4. 4강사가 안내하는 방법으로 문서 링크와 파일을 제출합니다

내려받은 Workflow 파일에는 API Key가 들어 있지 않습니다. 연결 정보(Credential)는 n8n 안에 따로 저장되기 때문입니다. 그래도 파일을 공개된 곳에 올리지는 않습니다.

  • Input · Output — 들어오고 나가는 것이 분명한가?
  • AI — 결과 모양이 일정하고, 없는 정보를 지어내지 않는가?
  • 분기 · Tool — 모든 길 · 모든 Tool을 한 번씩 테스트했는가?
  • 안전 — 메일은 테스트 주소로만, 위험한 Tool은 없는가?
  • 기록 — 어려웠던 문제와 해결 방법을 적었는가?

완성 = 기능이 많은 것이 아니라, MUST가 끝까지 돌고 → 테스트로 확인했고 → 기록이 남은 것.

14.혼자 만들 때 쓰는 전체 과정

수업이 끝나도 같은 순서로 새 프로젝트를 만들 수 있습니다. n8n이 아닌 다른 도구로 바뀌어도 순서는 같습니다.

막혔을 때는 언제나 「AI와 함께 문제 해결하는 기본 루틴」 — 어디까지 정상인지 확인 → 캡처 → 상황 · 원하는 결과 설명 → 답을 내 화면과 비교 → 직접 수정 → 다시 실행 → 결과 검증. 2일차부터 반복한 이 루틴이 있으면 강사가 없어도 새 Workflow와 Agent를 혼자 만들어 갈 수 있습니다.
