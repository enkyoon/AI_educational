3.자료에서 실행할 기획안으로 바꾸기

앞에서 배운 분석·문서·조사를 바탕으로 다음에 할 일을 정합니다. 기획안은 왜 필요한지, 무엇을 할지, 어떻게 실행할지와 확인할 비용·성과를 정리한 문서입니다.

같이 해 볼 상황
거래처가 재생 용지를 매번 주문하는 일이 번거롭다고 합니다. 팀장은 큰 투자 전에 작은 개선을 시험하려고 합니다. 판매 수량과 고객 의견은 참고할 수 있지만, 배송비와 추가 업무시간은 아직 모릅니다.

기획 연습 자료 · 수업용 가상 자료

  1. 1.확인할 질문을 정하고 해결할 문제 하나를 고릅니다.
  2. 2.실행 방법 두 가지를 비교합니다.
  3. 3.내가 고른 방법과 선택 이유를 적습니다.
  4. 4.일정·담당·확정 비용·미정 비용·성과 확인 방법을 정리합니다.
  5. 5.Canvas에서 기획 1쪽으로 작성하고 필요한 부분만 고칩니다.
나는 총무·기획 담당자야. 위 자료로 거래처의 재생 용지 반복 주문을 간편하게 할 시범 운영을 제안하려고 해. 아직 본문을 쓰지 말고 확인할 질문을 정리하고, 정기 배송과 재주문 안내를 고객 편의·기존 2명의 운영 부담·비용 확인 가능성으로 비교해줘. 내가 하나를 고르면 준비·실행·확인 단계의 담당과 일정, 확정 비용과 미정 비용, 성과 확인 방법을 정리해줘. 현재 재주문율이 없으니 임의의 개선율을 과거 실적처럼 쓰지 마. 미정 비용은 0원으로 계산하지 마. 마지막에 팀장이 시범 준비 여부를 결정할 기획 1쪽을 작성해줘.

AI의 추천을 읽고 직접 선택합니다. 검토 의견도 모두 따를 필요는 없습니다. 실행 조건에 맞지 않거나 근거가 없는 부분을 골라 고칩니다.

4.내가 해 볼 미션 고르기

이번에는 배운 방법으로 혼자 시작하고 끝내 봅니다. 평가·채점·발표·제출은 없습니다. 막히면 도움말을 펼치거나 강사에게 도움을 요청하세요. 마음이 가는 상황 하나를 고르면 됩니다.

위에서 해 보고 싶은 상황을 하나 골라 주세요.

  2. 아래 작성 틀을 채워 보냅니다.

매주 월요일 오전 9시에 국내 기업용 친환경 사무용품 소식을 찾아 3개로 정리해줘. 항목마다 한 줄 요약 · 발행일 · 출처 링크를 적어줘. 새로 확인된 내용이 없으면 "이번 주 새 소식 없음"이라고만 적어줘. 출처를 확인할 수 없는 내용은 넣지 마.

결과는 정한 시각 무렵에 도착하므로 수업 중에는 등록까지만 확인합니다. 예약 메뉴가 보이지 않으면 계정에 아직 열리지 않았을 수 있으니 건너뛰고 Apps Script로 넘어갑니다. 메뉴 이름은 업데이트에 따라 다를 수 있습니다.

명단대로 정확히 — Apps Script

예약 작업은 정리해서 알려 주는 일에 맞습니다. 시트 명단대로 메일을 보내는 것처럼 정해진 동작을 그대로 실행할 때는 Apps Script를 씁니다.

Apps Script

Google 시트·문서·Gmail에 "이 일을 자동으로 해줘"라고 시킬 수 있는 기능입니다. 반복 작업을 해 주는 "매크로"와 비슷하고, 추가 비용이나 설치가 없습니다.

①Gemini에게 말로 요청
②코드를 복사해 붙여넣기
③실행 버튼

안전 약속

  • · 받는 사람은 내 메일 주소로만. 실제 동료·거래처에게 보내지 않습니다.
  • · 개인 Google 계정은 자동 메일을 하루에 보낼 수 있는 수에 제한이 있습니다. 연습에는 충분합니다.
  • · 코드를 이해할 필요는 없지만, 무엇을 하는 코드인지는 Gemini에게 물어 확인하고 실행합니다.

실습: 예제 ① 나에게 테스트 메일 한 통

  1. 1새 Google 시트 → 이름 "08_자동메일연습_이름"
  2. 2위쪽 메뉴 확장 프로그램 → Apps Script → 새 탭의 코드 편집 화면에서 이미 적힌 function myFunction() { }을 모두 지우기
  3. 3아래 요청문을 Gemini 새 채팅에 보내 코드 받기
  4. 4코드 붙여넣기 → 저장(Ctrl + S)
  5. 5위쪽 함수 선택 칸에 "sendTestMail"이 보이는지 확인 → ▶ 실행
  6. 6권한 허용 (처음 한 번만) — 아래 상자 참고
  7. 7실행 로그에 "실행 완료" → Gmail 받은편지함 확인

권한 허용 — 가장 많이 막히는 곳

  • ① "승인 필요" 창 → 권한 검토 → 내 Google 계정 선택
  • ② "Google에서 확인하지 않은 앱" 화면 → 내가 방금 붙여 넣은 코드라서 나오는 화면입니다. 남이 보낸 코드라면 여기서 멈춥니다.
  • ③ 왼쪽 아래 고급 → "(프로젝트 이름)(으)로 이동(안전하지 않음)"을 누릅니다.
  • ④ 어떤 권한을 달라고 하는지 읽습니다. 메일 보내기처럼 하려던 일과 맞으면 허용을 누릅니다.

실습: 예제 ② 시트 명단으로 맞춤 메일 보내기

이번 코드는 메일을 바로 보내지 않고, 먼저 미리보기(누구에게 어떤 메일이 갈지 로그로만 보여 주기)를 실행한 뒤 실제로 보냅니다. 보낸 줄에는 "보냄"이 적혀서, 다시 실행해도 그 줄은 건너뜁니다.

오늘 만든 기획안을 관련 담당자들에게 이름을 넣어 안내하는 상황입니다.

STEP 01 같은 시트에 명단 만들기

A 이름B 이메일C 부서D 보낸 상태
김하늘내주소+kim@gmail.com영업팀
이바다내주소+lee@gmail.com서울점
박나무내주소+park@gmail.com부산점

Gmail은 주소 뒤에 +글자를 붙여도 모두 내 받은편지함으로 옵니다. 예) mymail@gmail.com → mymail+kim@gmail.com. 실제로는 나에게 3통이 오지만 3명에게 보낸 것처럼 연습할 수 있습니다. (회사 메일은 안 될 수 있으니 개인 Gmail로)

STEP 02 코드 요청

  1. 3Apps Script 화면으로 돌아와 예제 ① 코드 아래에 받은 코드를 이어 붙여 넣고 저장(Ctrl + S)합니다.
  2. 4코드 맨 위의 내 주소 칸을 실제 내 Gmail 주소로 바꾸고 다시 저장합니다.
  3. 5함수 선택 칸에서 "previewMails" → ▶ 실행. 아래 실행 로그에 세 사람의 받는 주소 · 제목 · 본문이 나오는지 봅니다. (권한 창이 또 나오면 같은 순서로 허용)
  4. 6로그가 맞으면 함수 선택 칸에서 "sendMails" → ▶ 실행을 한 번만 누릅니다.
  5. 7받은편지함에 메일 3통(이름·부서가 각각 다르게)이 왔는지, 시트 D열에 "보냄"이 적혔는지 확인합니다.

더 해 보기 (선택) — 메일 내용에 기획안 Google 문서 링크 넣기 / 시트 위쪽 메뉴에 "메일 보내기" 버튼 만들기

자동화가 막혔을 때 확인하기

실행 전후 점검

함수가 안 보임: 저장 후 함수 목록에서 previewMails 또는 sendMails를 고릅니다. 명단 오류: 탭 이름 명단과 첫 행 이름·이메일·부서·보낸 상태 확인. 테스트 주소 오류: 코드의 TEST_EMAIL을 내 Gmail 주소로 바꿨는지 확인. 주소 건너뜀: 외부 주소·빈칸·오타는 발송하지 않는 것이 맞습니다. 메일 실패: 실행 로그와 오류 상태를 보고 원인을 확인합니다. 보냄을 무턱대고 지우고 재실행하지 않습니다. 권한: 내가 검토한 수업용 코드인지 확인하고 권한 내용을 읽습니다. 알 수 없는 앱·코드의 경고를 그대로 따라 넘기지 않습니다.

그래도 안 되면 아래 칸을 채워 코드를 받았던 Gemini 대화에 보냅니다. 실제 수신 주소나 개인정보는 가리고 보냅니다.
