3.초안과 완성본은 무엇이 다를까?

1교시 · AI를 활용한 기획안 고도화

초안
  • • 무엇을 할지는 있음
  • • [확인 필요]가 군데군데
  • • "왜 이렇게 하나?"에 대한 근거가 약함
  • • 누가 읽어도 같은 내용
완성본
  • • 근거와 숫자가 확인되어 있음
  • • 위험 요소와 대응이 적혀 있음
  • • 읽는 사람이 물을 질문에 미리 답함
  • • 읽는 사람에 맞춘 길이와 강조

오늘은 AI에게 심사자 · 질문자 · 편집자 세 가지 역할을 차례로 맡겨 초안을 완성본으로 만듭니다. 고치는 결정은 매번 내가 합니다.

4.SET 01. 심사자에게 피드백 받기

새 채팅에 기획안 초안을 올리고(또는 붙여 넣고) 심사를 맡깁니다. "좋네요"만 듣지 않도록 점수 기준과 형식을 정해 줍니다.

우선순위 3가지 중 내가 동의하는 것만 고릅니다. 실제 상황과 맞지 않는 지적(예: 예산을 두 배로 늘리라는 제안)은 "그건 어려워. 다른 방법을 알려줘"라고 답해도 됩니다.

혼자 써 보기 ①

방금은 결정하는 사람의 입장에서 심사를 받았습니다. 이번에는 틀 없이, 다른 입장의 심사 요청을 처음부터 직접 써 보세요.

상황 — 이번에는 기획에 실제로 참여할 사람(손님 · 직원 · 참가자)의 입장에서 기획안을 평가받고 싶습니다.
누구의 입장인지 · 무엇을 기준으로 볼지 · 결과 모양 (점수표 · 이유 · 고칠 점) · 말투

다 썼으면 복사해서 ChatGPT에 입력하고 결과를 확인하기

□ 사장님 · 팀장님 심사와 다른 지적이 나왔나?□ 반영할 지적을 내가 골랐나?□ 마음에 안 들면 한 줄 고쳐서 다시 입력

5.SET 02. 근거와 숫자 채우기

"왜 이걸 해야 하나?"에 답하는 것이 근거입니다. AI에게 근거를 지어내게 하지 말고, 어떤 근거가 필요한지 목록을 받아 내가 채웁니다 (DAY 02의 할루시네이션 줄이기).

근거를 바로 확인할 수 없다면 [확인 필요]로 그대로 두는 것이 정답입니다. 그럴듯한 가짜 숫자가 들어간 기획안은 나중에 더 큰 문제가 됩니다.

6.SET 03. 예상 질문에 미리 답하기

예상 질문과 답은 기획안 맨 뒤에 "자주 묻는 질문"으로 붙여 두면 읽는 사람이 편합니다.

7.SET 04. 읽는 사람별 버전 만들기

같은 기획이라도 결정하는 사람과 참여하는 사람이 알고 싶은 것은 다릅니다. 내용은 그대로 두고 길이와 강조만 바꿉니다.

버전 B 안내문은 2교시 웹페이지의 내용으로 그대로 씁니다. 복사해 두세요.

8.SET 05. 최종본 정리하기

□ 심사에서 고른 우선순위 3가지를 고쳤는가?
□ 숫자와 합계를 직접 확인했는가?
□ 남은 [확인 필요]는 왜 남았는지 아는가?
□ 처음 보는 사람이 읽어도 이해되는가?

답 아래의 복사 버튼으로 전체를 복사해 Word에 붙여 넣고 "기획안_최종"으로 저장합니다.

9.말로 웹페이지를 만든다는 것 — 바이브코딩 맛보기

2교시 · 간단한 웹페이지 제작 체험

바이브코딩 (Vibe Coding)

코드를 직접 외워서 쓰지 않고, 만들고 싶은 화면을 말로 설명해서 AI가 코드를 쓰게 하는 방식입니다. 지금까지 배운 프롬프트 요령 — 목적 · 대상 · 조건 · 한 번에 하나씩 고치기 — 이 그대로 쓰입니다.

HTML뼈대 — 제목, 글, 버튼이 무엇인지
CSS옷 — 색, 글꼴, 배치
JavaScript움직임 — 누르면 일어나는 일

세 가지 이름만 알면 충분합니다. 오늘은 ChatGPT에게 한 장짜리 웹페이지 코드를 받고, 답 안의 코드 칸에서 바로 미리보기로 확인합니다.

10.SET 06. 기획안 소개 페이지 만들기

새 채팅을 열고, SET 04의 참여자용 안내문을 붙여 넣어 요청합니다.

답에 나온 코드 칸 위쪽의 미리보기(Preview) 버튼을 누르면 코드가 실제 웹페이지 모양으로 보입니다. 버튼이 보이지 않으면 걱정하지 말고 SET 08처럼 파일로 저장해서 브라우저로 열어 보세요. 버튼 이름과 위치는 계정 · 업데이트에 따라 다를 수 있습니다.

11.SET 07. 말로 고치기 — 한 번에 하나씩

코드를 몰라도 화면을 보고 어디를 어떻게 바꾸고 싶은지 말하면 됩니다. 여러 곳을 한꺼번에 고치면 무엇이 바뀌었는지 놓치기 쉬우니 하나씩 요청하고 미리보기로 확인하세요.

X 막연한 요청

"좀 더 예쁘게 해줘."

O 위치 + 무엇을 + 어떻게

"첫 화면 제목을 지금보다 크게, 신청하기 버튼은 진한 갈색으로 바꿔줘. 다른 부분은 그대로 둬."

이렇게 말해 보세요 — 골라서 하나씩

"일정 · 장소 부분을 카드 3개로 나란히 보여줘."
"자주 묻는 질문은 누르면 답이 펼쳐지게 해줘."
"신청하기 버튼을 누르면 신청 방법 부분으로 부드럽게 내려가게 해줘."
"전체 색을 [초록 계열]로 바꿔줘. 배치는 그대로 둬."
"휴대폰 화면에서 글씨가 작아. 휴대폰에서만 조금 키워줘."
"방금 바꾼 게 마음에 안 들어. 바로 전 상태로 되돌려줘."

신청 버튼을 눌러도 실제로 신청이 저장되지는 않습니다. 실제로 신청을 받으려면 데이터를 저장하는 서버가 필요합니다. 오늘은 화면을 만드는 경험까지입니다.

혼자 써 보기 ②

이번에는 기획안과 상관없이, 내가 만들고 싶은 웹페이지를 처음부터 요청해 봅니다. 새 채팅에서 입력하세요.

상황 — 만들고 싶은 페이지를 하나 정하세요. 예: 내 자기소개 페이지, 동네 맛집 소개, 우리 동호회 안내, 좋아하는 책 소개.
무엇을 위한 페이지 · 보는 사람 · 페이지 구성 (위에서 아래 순서) · 분위기와 색 · 휴대폰에서도 보기 좋게 · HTML 파일 하나로

다 썼으면 복사해서 ChatGPT에 입력하고 결과를 확인하기

□ 미리보기나 파일로 열어서 확인했나?□ 한 번에 하나씩 고쳐 봤나?□ SET 08처럼 다른 이름(예: mypage.html)으로 저장해 열어 봤나?□ 마음에 안 들면 한 줄 고쳐서 다시 입력

12.SET 08. 파일로 저장하고 열어 보기

1코드 칸 오른쪽 위의 복사 버튼으로 코드 전체 복사
2메모장 열고 붙여넣기
3다른 이름으로 저장 → 파일 이름 index.html, 인코딩 UTF-8
4저장한 파일을 더블클릭 → 브라우저로 열림
한글이 깨져 보이면 저장할 때 인코딩을 UTF-8로 골랐는지 확인하세요. 메모장 저장 창 아래쪽에 인코딩 선택이 있습니다. 확장자가 .txt로 붙어 버렸다면 파일 형식을 "모든 파일"로 바꿔 다시 저장합니다.

지금 만든 페이지는 내 컴퓨터에서만 열립니다. 인터넷 주소로 다른 사람에게 보여 주려면 서버에 올리는 과정(배포)이 필요합니다. 더 배우고 싶다면 바이브코딩 과정에서 Claude Code로 웹사이트를 만들고 인터넷에 공개하는 법까지 다룹니다.
