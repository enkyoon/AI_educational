04
Usage & Credits

Claude 사용량 한도와 사용 크레딧 이해하기

Claude는 무제한으로 사용할 수 있는가?

Claude는 사용하고 있는 플랜에 따라 사용할 수 있는 양에 제한이 있습니다. 단순히 "하루에 질문 100번" 처럼 메시지 개수만으로 정해지는 방식은 아닙니다.

사용량에 영향을 주는 요소
대화의 길이 입력한 내용의 양 첨부파일 사용하는 모델 Effort 설정 사용하는 기능 대화에 누적된 내용 Claude Code 작업량
💡 Claude 웹과 Claude Code 등 같은 Claude 계정에서 사용하는 서비스의 사용량은 동일한 플랜 사용량 한도에 함께 포함될 수 있습니다.

주요 사용량 한도

세션 사용량 한도

일정 시간 동안 사용할 수 있는 사용량

→ 일반적인 유료 플랜에서는 5시간 단위의 세션 사용량 한도 적용

주간 사용량 한도

한 주 동안 사용할 수 있는 전체 사용량

→ 플랜에 따라 사용 가능한 양 차이 발생

그 외 서비스 상황이나 플랜에 따라 추가적인 모델별·기능별 제한이 적용될 수 있습니다.

주의

Claude의 기본 사용량을 "일간 + 주간 + 월간의 세 가지 고정 한도"라고 단순하게 이해하지 않기.
"세션 사용량 한도 + 주간 한도 + 플랜별 추가 제한" 형태로 이해하기

사용 크레딧이란?

기본 사용량을 모두 사용했을 경우

지원되는 유료 Claude 플랜에서는 기본 사용량을 모두 사용한 이후 사용 크레딧(Usage Credits)을 이용하여 추가 비용을 지불하고 계속 사용할 수 있습니다.

기본 플랜 사용량
사용량 한도 도달
사용 크레딧 사용
추가 사용량에 대해 종량제 방식으로 계속 이용

(사용 크레딧을 사용하지 않는 경우 → 기본 사용량이 다시 초기화된 후 이용)

사용 크레딧과 토큰은 같은 것인가? — 사용 크레딧 ≠ 토큰

토큰(Token)

→ AI가 글자와 문장을 처리하기 위해 내용을 잘게 나눈 기술적인 데이터 단위

사용 크레딧(Usage Credits)

→ 기본 플랜 사용량을 초과하여 Claude를 추가 이용할 때 사용하는 결제·사용 방식

API에서는 실제 처리한 토큰 수가 비용 계산의 중요한 기준이 되지만, Claude 유료 플랜에서 추가 사용과 관련된 사용자용 공식 표현은 사용 크레딧입니다.

Claude는 무제한 서비스가 아닙니다. 현재 사용량을 확인하면서 작업하기.
특히 여러 파일을 읽고 수정하는 Claude Code 작업은 단순한 짧은 질문보다 사용량이 빠르게 증가할 수 있습니다.

웹 Claude Code / VS Code Claude Code 비교

Claude Code는 웹에서도 사용할 수 있는데 왜 VS Code를 사용할까?

웹 Claude Code에서는 GitHub Repository를 연결한 뒤 브라우저에서 원하는 개발작업을 요청할 수 있습니다. 웹 Claude Code는 내 컴퓨터가 아닌 Anthropic이 제공하는 원격 Cloud 환경에서 코드를 실행하고 수정합니다.

결과 확인 및 검토

웹 Claude Code의 큰 장점

  • 별도의 Local 개발환경 없이 작업 가능내 컴퓨터에 직접 Clone하거나 개발환경을 모두 구성하지 않아도 GitHub Repository만 연결하면 작업 가능
  • 작업을 맡겨두고 다른 일을 할 수 있음요청 후 원격 환경에서 작업하는 동안 사용자는 다른 일을 진행하고 완료 후 결과만 검토
  • 여러 작업을 동시에 진행하기 편리서로 다른 작업을 각각 독립적인 환경에서 실행 가능
  • 명확하게 정해진 작업에 강점특정 오류 수정, 반복적인 코드 정리, 작은 기능 추가, 파일 리팩터링 등
작업내용을 명확하게 전달하고 결과를 나중에 확인하는 방식에 강점

웹 Claude Code의 큰 단점

  • 내 컴퓨터의 실제 개발환경과 분리됨내 컴퓨터의 파일·Local 설정·설치 프로그램·Local Server 등을 그대로 사용하는 환경과 차이 발생
  • 작은 수정이 반복되는 작업에는 상대적으로 불편글자 크기 수정 → 확인 → 이미지 크기 수정 → 확인처럼 작은 변경과 확인이 계속 반복되는 웹디자인 작업에 불리
  • 초급자에게는 작업과정이 잘 보이지 않을 수 있음어떤 파일이 만들어지고 수정되었는지 확인하며 학습하기 어려울 수 있음

VS Code 설치하기

VS Code(Visual Studio Code)란 Microsoft에서 무료로 제공하는 코드 편집기 프로그램입니다. Windows, Mac 등 대부분의 컴퓨터에서 사용할 수 있으며, 회원가입 없이 누구나 다운로드하여 설치할 수 있습니다.

Git과 GitHub 이해하기

Git을 설치하는 이유 — VS Code가 있는데 Git은 왜 따로 설치해야 할까?

VS Code에는 Source Control이라는 Git 관리 화면이 기본으로 존재하지만, VS Code 자체가 Git 프로그램을 대신하는 것은 아닙니다. VS Code는 컴퓨터에 설치되어 있는 Git을 이용하여 변경내용 확인 · Stage · Commit · Clone · Push · Pull 등의 작업을 수행합니다.

Git = 실제로 기록을 처리하는 엔진  |  VS Code Source Control = Git을 조작하는 운전대와 계기판

→ 이번 수업에서 Git을 설치하는 이유: 프로젝트의 변경내용을 기록하고 GitHub와 연결하기 위해서입니다.

Git이란?

프로젝트 파일이 어떻게 변경되었는지 내 컴퓨터에서 기록하고 관리하는 버전 관리 프로그램입니다.

Git을 사용하지 않는 경우

최종수정.html

진짜진짜최종.html
Git을 사용하는 경우

하나의 프로젝트를 유지하면서 수정한 시점마다 변경내용을 기록합니다.

→ 여러 개의 복사본을 만들지 않고 하나의 프로젝트 안에서 작업이력 관리하기

Git과 GitHub의 차이

Git

내 컴퓨터에서 프로젝트의 변경내용을 기록하는 프로그램

파일 변경 확인하기 작업이력 기록하기 Commit 만들기 이전 변경내용 확인하기

인터넷이 없어도 기본적인 Local 버전관리가 가능합니다.

쉽게 표현하면 "개인 작업일지"
GitHub

Git으로 관리하는 프로젝트를 인터넷에 저장하고 공유하는 온라인 서비스

프로젝트 온라인 저장하기 다른 컴퓨터에서 가져오기 공유하기 협업하기

온라인에서 변경이력을 확인할 수 있습니다.

쉽게 표현하면 "작업일지를 저장하고 공유하는 온라인 공간"
구분 Git GitHub
형태 프로그램 온라인 서비스
위치 내 컴퓨터 인터넷
핵심 역할 변경내용 기록 프로젝트 저장·공유
대표 기능 Commit Repository
인터넷 기본 기록에는 불필요 필요
가장 중요한 차이 — Git 설치 = GitHub 설치 X  /  GitHub 계정 생성 = Git 설치 X
Claude Code · VS Code · Git · GitHub 관계 이해하기

Local / Remote 이해하기

Local: 내 컴퓨터에 존재하는 프로젝트 (VS Code에서 실제로 작업하는 공간)
