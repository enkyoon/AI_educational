Database 기본 개념

Database란?

웹사이트에서 계속 사용해야 하는 정보를 저장하는 공간. 오늘은 메뉴 이름, 설명, 가격, 이미지 경로를 저장합니다.

Database의 기본 구조 — Table · Column · Row

name description price image_url
Cream Latte 부드러운 크림과 에스프레소가 어우러진 시그니처 라떼 6500 images/cream-latte.jpg
Classic Tiramisu 진한 마스카포네 크림과 커피 향을 담은 수제 티라미수 7000 images/tiramisu.jpg
Mellow Ade 레몬과 허브를 사용한 상큼한 시그니처 에이드 6000 images/mellow-ade.jpg
Table

같은 종류의 데이터를 저장하는 표. 오늘 만들 Table은 menus

Column

실제로 저장된 데이터 한 건 (Cream Latte 한 개 = 하나의 Row)

쉽게 생각하면 — 메뉴 하나

06
Key Concept

SQL이란?

SQL (Structured Query Language, 구조화 질의 언어)

Database에 데이터를 만들고, 저장하고, 찾고, 수정하고, 삭제하도록 요청할 때 사용하는 언어. Database가 "창고"라면 SQL은 창고에 일을 시키기 위한 언어입니다.

사람의 말과 SQL 비교하기

사람이 말한다면

"menus에 있는 모든 메뉴를 보여줘."

SQL에서는 
SELECT * FROM menus;
사람이 말한다면

"Strawberry Latte라는 새로운 메뉴를 저장해줘."

SQL에서는 
INSERT INTO menus (name, price)
VALUES ('Strawberry Latte', 7000);

핵심 — 우리가 직접 SQL을 외워 작성하지 않아도, AI에게 "무엇을 하고 싶은지" 정확하게 알려주면 필요한 SQL을 작성하도록 요청할 수 있습니다.

SQL로 할 수 있는 기본 작업 & CRUD

SELECT

데이터 가져오기

"보여줘." · Read

INSERT

새로운 데이터 추가하기

"추가해줘." · Create

UPDATE

기존 데이터 수정하기

"바꿔줘." · Update

DELETE

기존 데이터 삭제하기

"지워줘." · Delete

오늘 실제로 사용할 것 — CREATE TABLE(Table 만들기), INSERT(메뉴 추가), SELECT(메뉴 확인), UPDATE(메뉴 수정). DELETE는 개념만 알아두고 오늘 핵심 실습에서는 사용하지 않습니다.

프롬프트 01 — 다 함께 입력하기
상자를 클릭하면 바로 복사돼요

Supabase에서 MELLOW BEAN 카페의 메뉴 데이터를 저장할 Database Table을 만들려고 해. 아직 내 프로젝트의 HTML, CSS, JavaScript 파일은 수정하지 마. Supabase SQL Editor에서 실행할 SQL만 만들어줘. Table 이름은 menus로 만들어줘. 다음 데이터를 저장할 수 있어야 해. 1. 각 메뉴를 구분하는 id 2. 메뉴 이름 name 3. 메뉴 설명 description 4. 가격 price 5. 이미지 경로 image_url 6. 데이터가 만들어진 시간 created_at id는 자동으로 생성되도록 만들어줘. name, description, price, image_url은 반드시 값이 있도록 설정해줘. 기존 Table을 삭제하는 DROP 명령은 사용하지 마. 먼저 어떤 Table을 만드는 SQL인지 간단하게 설명하고, 그 다음 복사해서 실행할 수 있는 SQL을 하나의 코드블록으로 작성해줘.

AI가 작성한 결과 확인하기 — 바로 실행하지 않고 먼저 확인
CREATE TABLE Table 이름: menus id, name, description, price, image_url, created_at

핵심 — SQL 전체를 이해할 필요는 없지만, 이 SQL이 Table을 만드는 코드인지 정도는 확인합니다.

Database에 데이터가 들어갔다면 SQL로 직접 확인할 수 있습니다.

프롬프트 03
상자를 클릭하면 바로 복사돼요

Supabase의 menus Table에 저장된 모든 메뉴 데이터를 확인하고 싶어. 데이터를 수정하거나 삭제하지 말고 조회만 하는 SQL을 만들어줘. 메뉴가 생성된 순서대로 확인할 수 있도록 해줘. SQL을 실행하기 전에 어떤 작업인지 한 줄로 설명해줘.

SQL 실행 전 최소한 이것은 확인하기
SELECT → 조회 INSERT → 추가 UPDATE → 수정 DELETE → 삭제 DROP → 구조 삭제

특히 DELETE, DROP이 보인다면 무엇을 삭제하는 SQL인지 반드시 확인하기 — AI가 만들어줬다고 바로 실행하지 않기

STEP 05. 웹사이트에서 메뉴를 읽을 수 있도록 권한 설정하기

RLS (Row Level Security, 행 단위 보안)

Database에 저장된 데이터에 누가 어떤 작업을 할 수 있는지 제한하는 보안기능입니다. MELLOW BEAN 사이트를 방문한 사람은 메뉴를 보는 것은 가능하지만, 가격을 마음대로 바꾸거나 메뉴를 삭제하면 안 됩니다.

메뉴 보기 — 허용 (O)
메뉴 추가·수정·삭제 — 불허 (X)
프롬프트 04
상자를 클릭하면 바로 복사돼요

Supabase의 menus Table을 웹사이트에서 읽을 수 있도록 RLS와 Policy를 설정하고 싶어. 로그인하지 않은 일반 방문자도 메뉴를 조회할 수 있어야 해. 하지만 웹사이트에서는 새로운 메뉴 추가, 수정, 삭제는 할 수 없게 하고 싶어. 즉 일반 사용자는 SELECT만 가능하도록 최소한의 권한만 설정해줘. Supabase SQL Editor에서 사용할 SQL을 작성해줘. 기존 menus 데이터를 삭제하거나 Table 구조를 변경하지 마. 먼저 어떤 보안설정을 하는지 초보자가 이해할 수 있도록 설명하고, 그 다음 실행할 SQL을 작성해줘.

메뉴 관리(추가·수정)는 방문자가 아니라 Supabase Dashboard SQL Editor에서 관리자가 직접 진행합니다.

Publishable Key — 사용 O

웹브라우저에서 Supabase 프로젝트에 연결할 때 사용하는 공개용 Key. 실제 접근 가능한 작업은 RLS와 Policy로 제한됩니다.

Secret Key — 사용 X

높은 권한을 가진 서버용 Key. HTML, JavaScript 등 GitHub에 공개되는 Front-end 코드에는 절대 넣지 않습니다.

Supabase 연결이 완료되었어. 이제 menus Table의 데이터를 JavaScript에서 불러오는 기능을 만들어줘. 다음 Column을 가져와줘 — id, name, description, price, image_url id가 작은 순서부터 표시되도록 해줘. 우선 데이터를 정상적으로 불러오는지 확인할 수 있도록 Browser Console에도 결과를 출력해줘. 아직 기존 HTML의 Menu 카드 3개는 삭제하지 마. STEP 10

AI에게 새로운 메뉴 추가 SQL 요청하기

프롬프트 08
상자를 클릭하면 바로 복사돼요

Supabase의 menus Table에 새로운 메뉴 하나를 추가하고 싶어. Table 구조는 id, name, description, price, image_url, created_at으로 되어 있어. 추가할 메뉴정보는 다음과 같아. name: Strawberry Latte description: 신선한 딸기와 우유가 어우러진 부드러운 시즌 라떼 price: 7000 image_url: images/strawberry-latte.jpg 기존 메뉴와 Table 구조는 절대 수정하거나 삭제하지 말고, 새로운 메뉴 한 개만 추가하는 SQL을 만들어줘. 확인할 단어 — INSERT. 추가되는 값이 Strawberry Latte, 7000, images/strawberry-latte.jpg인지 확인 후 SQL을 복사합니다.

STEP 12

메뉴 가격 수정하기

이번에는 새로운 데이터 추가가 아니라 기존 데이터 수정입니다 — Cream Latte 가격을 6,500원에서 6,800원으로 변경합니다.

프롬프트 09
상자를 클릭하면 바로 복사돼요

Supabase의 menus Table에서 Cream Latte의 가격만 변경하고 싶어. 현재 price는 6500이고 새로운 가격은 6800이야. Cream Latte Row의 price만 변경하는 SQL을 만들어줘. 다른 메뉴의 데이터는 절대 수정하지 마. 실행 전에 어떤 데이터를 어떤 값으로 수정하는 SQL인지 설명해줘.

확인할 단어 — UPDATE + WHERE. WHERE는 "어떤 데이터에 작업할 것인지" 조건을 지정합니다 — 조건 없이 UPDATE하면 모든 데이터가 바뀔 수 있으니 항상 확인하는 습관을 들입니다.

STEP 13

SQL을 AI에게 더 정확하게 요청해보기

X 좋지 않은 요청

"가격 바꾸는 SQL 만들어줘."

O 개선한 요청

"Supabase의 menus Table에서 Cream Latte의 price만 6800으로 변경하는 SQL을 만들어줘. 다른 Row는 수정하지 마. WHERE 조건을 사용해서 Cream Latte만 수정되도록 해줘. 실행 전에 어떤 데이터를 수정하는 코드인지 설명해줘."

핵심 — SQL을 잘 요청하려면 SQL 문법보다 현재 데이터 구조와 원하는 작업을 정확하게 설명하는 능력이 중요합니다.

실행 전에 최소한 무슨 작업인지 확인합니다. 특히 DELETE, DROP, UPDATE처럼 기존 데이터에 영향을 줄 수 있는 SQL은 어떤 데이터를 대상으로 하는지 더 주의해서 확인합니다.

SELECT → 조회 INSERT → 추가 UPDATE → 수정 DELETE → 삭제 DROP → 구조 삭제 가능
