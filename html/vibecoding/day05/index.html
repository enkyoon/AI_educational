03
Scope & MVP

최종 프로젝트 범위 정하기

DAY 06~07을 이용해 실제 웹사이트를 제작하므로, 너무 큰 서비스는 기획하지 않습니다.

X — 대형 쇼핑몰

회원가입, 로그인, 장바구니, 결제, 배송, 리뷰, 쿠폰, 관리자 페이지

O — 작은 브랜드 상품 소개 사이트

브랜드 소개, 상품 목록, 상품정보 확인, 문의 작성, 문의정보 Database 저장

MVP (Minimum Viable Product, 최소 기능 제품)

프로젝트가 목적을 달성하기 위해 반드시 필요한 기능만 갖춘 첫 번째 완성본입니다.

Must Have (카페 웹사이트 예시)

카페 소개, 메뉴 확인, 위치 확인, 문의 작성

Nice to Have

메뉴 검색, 이미지 슬라이드, 복잡한 애니메이션, 좋아요 기능

핵심 — 처음부터 모든 기능을 만들지 않고, 필요한 기능을 먼저 완성한 뒤 시간이 남으면 기능을 추가합니다.

05
Direction

STEP 01. 프로젝트 방향 결정하기

처음부터 AI에게 "프로젝트 하나 만들어줘"라고 맡기지 않습니다. 먼저 학생이 직접 관심분야, 만들고 싶은 사이트, 주요 사용자, 사용자가 했으면 하는 행동을 생각해서 적어봅니다.

프롬프트 01 — 직접 작성한 내용을 채워서 사용하기
상자를 클릭하면 바로 복사돼요

지금부터 바이브코딩 최종 프로젝트를 기획하려고 해. 제작기간이 길지 않기 때문에 너무 큰 프로젝트는 만들지 않을 예정이야. 내가 생각한 프로젝트는 다음과 같아. 관심분야: [직접 입력] 만들고 싶은 웹사이트: [직접 입력] 주요 사용자: [직접 입력] 사용자가 사이트에서 했으면 하는 주요 행동: [직접 입력] 이 아이디어를 바탕으로 프로젝트를 구체화해줘. 다음 내용을 정리해줘. 1. 프로젝트 이름 2. 프로젝트 한 줄 설명 3. 주요 사용자 4. 사용자가 가지고 있는 필요 5. 핵심기능 DAY 06~07 안에 초급자가 Claude Code를 이용해서 구현할 수 있는 수준으로 판단해줘. 너무 복잡한 기능이 있다면 더 단순한 형태로 바꿔서 제안해줘. 아직 코드는 작성하지 마.

결과 확인하기 — AI 제안을 그대로 쓰지 않고 학생이 판단
이 기능이 정말 필요한가? 내가 만들고 싶은 사이트와 맞는가? 2일 안에 만들 수 있을까? 너무 많은 기능이 들어가지는 않았는가?
06
MVP

STEP 02. MVP 결정하기

학생이 먼저 꼭 필요한 기능(Must Have)과 시간이 남으면 넣고 싶은 기능(Nice to Have)을 구분합니다.

프롬프트 02
상자를 클릭하면 바로 복사돼요

지금까지 정한 프로젝트를 기준으로 MVP를 함께 정리해줘. 기능을 다음 두 가지로 구분해줘. 1. Must Have — 프로젝트가 실제로 작동하기 위해 반드시 필요한 기능 2. Nice to Have — 시간이 남으면 추가할 기능 Must Have 기능은 최대 4개까지만 정해줘. 그리고 각 Must Have 기능마다 사용자가 무엇을 하는 기능인지, Database가 필요한지를 함께 알려줘. Database를 사용하는 경우 DAY 04에서 배운 Supabase 수준에서 구현 가능한 범위로 제한해줘. 로그인이나 결제처럼 구현 난이도가 높은 기능은 이번 프로젝트에서 제외해줘.

Database가 필요하지 않은 예시

브랜드 소개, 자기소개, 정적인 Gallery, 위치정보, 서비스 설명

Database가 필요한 예시

문의내용 저장, 메뉴목록 관리, 게시글 저장, 신청내용 저장, 상품정보 관리

핵심 — 배웠다고 무조건 Supabase를 사용하는 것이 아니라 필요한 경우에만 사용합니다.

User Flow

User Flow란? · STEP 03

User Flow (사용자 흐름)

사용자가 웹사이트에 들어와 자신의 목적을 달성하기까지 거치는 행동의 흐름입니다.

카페 사이트

사이트 방문 → 메뉴 확인 → 마음에 드는 메뉴 확인 → 위치 확인 → 방문

클래스 신청 사이트

사이트 방문 → 클래스 확인 → 상세내용 확인 → 신청하기 → 신청정보 입력 → 신청 완료

핵심 — User Flow는 화면의 디자인이 아니라 사용자의 행동을 설계하는 것입니다.

STEP 03

User Flow 직접 만들어보기

AI에게 바로 만들라고 하지 않고, 학생이 먼저 시작 → 행동 → 행동 → 최종 목표 순서로 작성합니다. 완벽할 필요 없이 사용자가 어떤 행동을 할지 생각하는 것이 중요합니다.

프롬프트 03 — 직접 작성한 User Flow 검토받기
상자를 클릭하면 바로 복사돼요

내가 최종 프로젝트의 User Flow를 만들어봤어. 프로젝트 목적은 다음과 같아: [프로젝트 목적 입력] 주요 사용자는 [사용자 입력] 내가 만든 User Flow는 다음과 같아: [직접 만든 User Flow 입력] 이 흐름을 검토해줘. 사용자가 목표를 달성하는 과정에서 빠진 단계가 있는지 확인하고, 불필요한 단계가 있다면 알려줘. 전체 흐름이 너무 복잡해지지 않도록 해줘. 먼저 문제점을 설명한 후 개선된 User Flow를 화살표 형태로 정리해줘. 아직 화면 디자인이나 코드는 만들지 마.

08
Screen Flow

Screen Flow란? · STEP 04

Screen Flow (화면 흐름)

User Flow에서 발생하는 행동이 어떤 화면 또는 Section에서 이루어지는지 정리한 구조입니다. User Flow는 "무엇을 하는가", Screen Flow는 "어떤 화면에서 하는가"입니다.

User Flow

사이트 방문 → 상품 확인 → 문의하기 → 문의 작성 → 등록 완료

Screen Flow

Home → Product → Contact → Form → Complete Message

한 페이지 사이트라도 상관없습니다 — 예: Hero Section → [메뉴 보기] → Menu Section → [위치 보기] → Location Section처럼 Page뿐만 아니라 Section 이동도 Screen Flow로 표현할 수 있습니다.

STEP 04

Screen Flow 만들기

프롬프트 04
상자를 클릭하면 바로 복사돼요

지금 확정한 User Flow를 기준으로 Screen Flow를 만들어줘. 프로젝트는 [프로젝트 이름]이야. 먼저 이 프로젝트가 한 페이지 구조가 적절한지 여러 페이지 구조가 적절한지 판단해줘. 그 다음 각 화면 또는 Section에 대해 1.화면 이름 2.사용자가 확인할 내용 3.사용자가 할 행동 4.다음 화면으로 이동시키는 버튼이나 요소를 정리해줘. 불필요하게 많은 페이지를 만들지 말아줘. 마지막에는 전체 Screen Flow를 화살표 형태로 정리해줘. 아직 실제 코드는 만들지 마.

핵심 — 버튼은 장식이 아니라 사용자의 다음 행동을 연결하는 장치입니다. 먼저 "위치를 확인해야 함"이 있고, 그래서 "위치 보기" 버튼이 필요한 것이지, 그 반대가 아닙니다.

HomeNavigation, Hero, CTA

Wireframe (화면 설계도)

최종 디자인을 적용하기 전에 콘텐츠와 기능이 어디에 배치될지 정하는 화면 구조입니다.

Wireframe에서는 X

Color, 예쁜 사진, 화려한 Font, Animation

중요하게 볼 것 O

제목·이미지·버튼·메뉴 위치, 콘텐츠 순서, 카드 배치, 입력 Form

💡 Wireframe = 웹사이트의 평면도 — 집을 만들 때 방/문/창문 위치를 먼저 정하고 벽지·가구·조명을 나중에 고르는 것과 같습니다.

Build Wireframe

STEP 06~07. Wireframe 초안 · 실제 제작하기

STEP 06

먼저 AI에게 구조 제안 받기

프롬프트 05
상자를 클릭하면 바로 복사돼요

지금까지 확정한 프로젝트 목적, Must Have 기능, User Flow, Screen Flow를 기준으로 Low-Fidelity Wireframe 구조를 제안해줘. 아직 Color, 실제 이미지, Font, Animation 같은 디자인 요소는 고려하지 마. 각 화면 또는 Section마다 위에서 아래로 어떤 요소가 배치되어야 하는지 정리해줘. Header, Navigation, 제목, 설명, 이미지 영역, 카드, 버튼, Form, Footer 등의 요소가 필요한 경우 포함해줘. 각 요소가 User Flow에서 어떤 역할을 하는지도 간단하게 설명해줘. 아직 실제 코드는 작성하지 마.

STEP 07

실제 Wireframe 만들어보기

설계한 내용을 브라우저에서 확인할 수 있는 형태로 제작합니다. 단, 최종 웹사이트 제작은 아닙니다.

프롬프트 06
상자를 클릭하면 바로 복사돼요

지금까지 확정한 Screen Flow와 Wireframe 구조를 실제로 확인하고 싶어. 프로젝트 폴더에 wireframe.html 파일을 만들어줘. 이것은 최종 웹사이트가 아니라 Low-Fidelity Wireframe이야. 흰색, 회색, 검정색 정도만 사용해줘. 실제 이미지는 사용하지 말고 이미지가 들어갈 영역에는 IMAGE라고 표시해줘. 버튼은 위치와 크기만 확인할 수 있도록 만들어줘. 실제 Database 기능이나 복잡한 JavaScript는 연결하지 마. 화려한 Font, 그림자, Animation은 사용하지 마. 각 Section의 위치와 콘텐츠의 순서를 확인할 수 있는 수준으로만 제작해줘. 기존 프로젝트가 있다면 기존 파일은 수정하지 말고 wireframe.html을 별도로 만들어줘.

Wireframe 검토하기
첫 화면에서 목적이 보이는가? 콘텐츠 순서가 자연스러운가? 중요한 버튼 위치가 적절한가? 다음에 무엇을 해야 하는지 알 수 있는가? Section이 너무 많지 않은가? 과도한 스크롤이 없는가?
11
Refine

STEP 08. Wireframe 수정하기

학생이 반드시 하나 이상의 문제를 찾습니다 — 예: Hero가 너무 큼(중요 콘텐츠가 늦게 나타남), 문의버튼이 페이지 마지막에만 있음(찾기 어려움), Menu Section 카드가 너무 많음.

Recap

User Flow · Screen Flow · Wireframe 구분하기

하나의 예시로 연결하기 — 카페 사이트

User Flow방문 → 메뉴 확인 → 위치 확인 → 방문 결정
Screen FlowHome → Menu → Location
WireframeHero[메뉴 보기] → Menu[Card][위치 확인] → Location[주소/영업시간/지도버튼]

핵심 — 행동 → 화면 → 배치 순서로 구체화하기

14
Key Terms

오늘의 핵심 용어

MVP

목적을 달성하기 위해 반드시 필요한 핵심기능만 갖춘 첫 완성본

Must Have / Nice to Have

반드시 구현할 필수 기능 / 시간이 남으면 추가할 선택 기능

User Flow

사용자가 목표를 달성하기까지 거치는 행동의 흐름

Screen Flow

사용자의 행동에 따라 화면이나 Section이 연결되는 흐름

Wireframe

최종 디자인 전에 콘텐츠와 기능의 위치를 결정하는 화면 구조
