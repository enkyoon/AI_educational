3.인증 · 권한 — 출입증과 들어갈 수 있는 방

DAY 04에서는 "누구나 메뉴를 볼 수 있다"는 규칙(RLS)만 만들었습니다. 그런데 실제 서비스는 "회원만 주문할 수 있다", "내 주문 내역은 나만 볼 수 있다"처럼 사람마다 할 수 있는 일이 다릅니다. 이걸 가능하게 하는 두 개념이 인증과 권한입니다.

인증 (Authentication · 로그인)

"당신은 누구인가?"를 확인하는 것. 이메일과 비밀번호가 맞는지 확인해서 이 사람이 누구인지 알아냅니다.

비유 — 회사 입구에서 사원증을 찍는 것

권한 (Authorization)

"당신은 무엇을 할 수 있는가?"를 정하는 것. 누구인지 확인된 사람이 어떤 데이터를 보고, 쓰고, 지울 수 있는지 정합니다.

비유 — 사원증으로 열리는 방이 사람마다 다른 것

MELLOW BEAN에 적용하면

누가 메뉴 보기 단골 메뉴 저장 다른 사람의 단골 메뉴 보기
로그인 안 한 방문자OXX
로그인한 회원OO (내 것만)X

순서가 중요합니다. 인증이 먼저 있어야 권한을 정할 수 있습니다. 서버가 "이 요청은 김민지 님이 보낸 것"이라는 걸 알아야 "김민지 님의 데이터만 보여 준다"는 규칙을 적용할 수 있기 때문입니다.

핵심 — 인증 = 누구인지 확인(로그인), 권한 = 무엇을 할 수 있는지 결정(RLS 규칙)

4.로그인은 어떻게 작동할까? — 비밀번호 저장과 로그인 유지

로그인 버튼 하나 뒤에는 생각보다 많은 일이 숨어 있습니다. 이걸 직접 만들면 몇 주가 걸리지만, Supabase의 Auth(인증) 기능이 대신 처리해 줍니다. 그래도 무슨 일이 일어나는지 알아야 문제가 생겼을 때 AI에게 정확히 물어볼 수 있습니다.

① 회원 정보는 어디에 저장될까?

회원가입을 하면 Supabase 안의 회원 전용 표(auth.users)에 이메일과 가입 시간 등이 저장됩니다. 메뉴를 저장한 menus 표와는 따로 관리되고, Supabase 화면의 Authentication → Users에서 볼 수 있습니다.

② 비밀번호는 그대로 저장하지 않는다

비밀번호는 되돌릴 수 없는 암호문으로 바꿔서 저장합니다. 고기를 갈아 다짐육으로 만들면 다시 원래 고기 덩어리로 되돌릴 수 없는 것과 같습니다. 로그인할 때는 입력한 비밀번호를 똑같이 갈아 보고, 결과가 같으면 맞는 비밀번호로 판단합니다. 그래서 관리자도 회원의 비밀번호를 볼 수 없습니다.

③ 로그인 상태는 어떻게 유지될까? — 임시 출입증

로그인에 성공하면 서버가 임시 출입증을 발급하고, 브라우저가 이것을 보관합니다. 그 뒤로는 요청할 때마다 출입증을 함께 보내서 페이지를 옮겨도 다시 로그인하지 않아도 됩니다. 놀이공원 입구에서 받는 손목 밴드와 같습니다. 출입증에는 유효 시간이 있어서 시간이 지나면 자동으로 새로 발급되거나, 로그아웃하면 버려집니다.

이메일 · 비밀번호 입력
Supabase가 암호문끼리 비교
맞으면 임시 출입증 발급
브라우저가 출입증 보관
요청마다 출입증을 보여 주고 내 데이터 받기
Supabase Auth가 대신 해 주는 일

회원 표 관리, 비밀번호 암호화, 로그인 출입증 발급 · 갱신, 비밀번호 찾기 메일, 구글 · 카카오 로그인 연결

우리가 할 일

회원가입 · 로그인 화면 만들기, 로그인 상태에 따라 화면 바꾸기, "누가 무엇을 할 수 있는지" 규칙 정하기

메뉴 이름과 위치는 Supabase 업데이트에 따라 조금 다를 수 있습니다. 찾기 어려우면 Claude Code에게 "Supabase에서 이메일 가입 확인(Confirm email)을 끄는 메뉴 위치를 알려줘"라고 물어보세요.

왜 가입 확인 메일을 끄나요?

실제 서비스에서는 "이 이메일이 진짜 내 것"임을 확인하려고 가입 확인 메일을 보냅니다. 그런데 Supabase의 기본 메일 발송은 시간당 보낼 수 있는 수가 아주 적어서, 반 전체가 동시에 가입하면 메일이 오지 않아 수업이 멈춥니다.

그래서 수업에서는 끄고 진행합니다. 실제로 서비스를 운영할 때는 다시 켜고, 별도 메일 발송 서비스를 연결해야 합니다.

8.하네스란? — AI 모델과 AI 작업 환경

2교시

하네스 (Harness · AI 작업 환경)

AI 모델을 둘러싸고 실제로 일을 할 수 있게 만들어 주는 작업 환경 전체입니다. 원래 말에 채워 수레를 끌게 하는 마구(馬具)를 뜻합니다. 아무리 힘센 말도 마구가 없으면 수레를 끌 수 없듯, 똑똑한 AI 모델도 파일을 읽고 고치고 명령을 실행할 수 있는 환경이 있어야 실제 일을 합니다.

모델 (Model) — 엔진

Claude Opus, Sonnet처럼 생각하고 글을 쓰는 AI 자체. 혼자서는 대화만 할 수 있습니다.

하네스 — 엔진을 얹은 자동차

Claude Code가 바로 하네스입니다. 모델에게 파일 읽기 · 쓰기, 명령 실행, 규칙 기억, 외부 서비스 연결 같은 "손과 발"을 달아 줍니다.

같은 모델이라도 하네스를 어떻게 꾸미느냐에 따라 결과가 달라집니다. 바이브코딩을 잘하는 사람은 프롬프트만 잘 쓰는 사람이 아니라, AI가 매번 같은 기준으로 일하도록 작업 환경을 꾸며 두는 사람입니다.

Claude Code에서 내가 꾸밀 수 있는 것

구성 요소 하는 일 비유 오늘
CLAUDE.md프로젝트 규칙 파일. 대화를 시작할 때마다 항상 읽음사내 규칙집실습
스킬 (SKILL.md)특정 작업의 설명서. 필요할 때만 꺼내 읽음업무 매뉴얼 한 권실습
MCP카페24 · GitHub 같은 외부 서비스와 연결업무용 전화선실습 (11번)
실제 사례 — 이 강의 사이트도 이렇게 만들었습니다. 지금 보고 있는 강의자료는 디자인 · 색 · 용어 · 파일 위치 규칙을 적은 약 700줄짜리 규칙 문서를 AI가 먼저 읽고 만듭니다. 그래서 수십 개 페이지가 같은 모양과 말투로 나옵니다. 페이지마다 "제목은 이렇게, 색은 이렇게"를 다시 말하지 않아도 됩니다.

11.MCP — AI와 외부 서비스를 잇는 연결 규격

MCP (Model Context Protocol)

AI 도구가 외부 서비스(카페24, GitHub, 구글 드라이브, Notion 등)와 연결할 때 쓰는 공통 규격입니다. 서비스 쪽에서 MCP 서버를 열어 두면, Claude Code · ChatGPT · Cursor 같은 여러 AI 도구가 같은 방식으로 그 서비스를 사용할 수 있습니다.

비유하자면 — USB-C 충전 단자와 같습니다. 예전에는 기기마다 충전기 모양이 달라서 기기 수만큼 충전기가 필요했지만, USB-C로 통일되자 하나의 케이블로 휴대폰 · 노트북 · 이어폰을 모두 충전합니다. MCP는 AI와 서비스 사이의 USB-C입니다.
MCP 연결 전

Claude Code는 내 컴퓨터의 파일만 다룰 수 있습니다. 서버에 올리려면 내가 직접 호스팅 업체 사이트에 들어가 메뉴를 찾아 누르고 파일을 올려야 합니다.

MCP 연결 후

"AI SPACE에 배포해줘"라고 말하면 Claude Code가 카페24의 MCP 서버에 직접 요청해서 서버 만들기 · 파일 올리기 · 주소 연결까지 처리합니다.

MCP를 연결할 때 주의할 점

  • • MCP를 연결하면 AI가 내 계정으로 그 서비스에서 행동할 수 있습니다. 회사에 출입증을 하나 더 만들어 주는 것과 같습니다.
  • • 공식 안내에 나온 MCP 서버만 연결합니다. 출처를 모르는 MCP 주소는 연결하지 않습니다.
  • • 연결하거나 중요한 작업을 할 때 뜨는 승인 창의 내용을 읽고 허용합니다.

12.도메인 · DNS · SSL — 주소와 자물쇠

배포를 하면 사이트 주소가 생기고, 주소 앞에 자물쇠 표시가 붙습니다. 이 둘이 무엇인지 알아봅니다.

도메인 (Domain)

서버마다 붙은 숫자 주소 대신 사람이 기억하기 쉽게 붙인 이름 주소. 예: mellowbean.com

비유 — 가게 상호

DNS (Domain Name System)

도메인을 입력하면 그 서버의 숫자 주소를 찾아 주는 시스템

비유 — 상호로 전화번호를 찾는 전화번호부

종류 예 특징
기본 주소내사이트.업체주소호스팅 업체가 무료로 주는 주소. 업체 이름 앞에 내 이름이 붙음. 오늘 받을 주소가 이것
내 도메인mellowbean.com도메인 판매 업체에서 1년 단위로 사서 연결. 보통 1년에 1~3만 원 정도

SSL · HTTPS — 주소창의 자물쇠

HTTPS는 브라우저와 서버가 주고받는 내용을 암호화해서 중간에 누가 엿봐도 알아볼 수 없게 하는 통신 방식입니다. 이 암호화 기술을 SSL이라고 부릅니다.

SSL 인증서는 "이 사이트가 이 도메인의 진짜 주인"이라는 것을 인증 기관이 확인해 준 증명서입니다. 가게에 걸린 사업자등록증과 같습니다. 유효 기간이 있어서 주기적으로 갱신해야 하고, 요즘 호스팅은 대부분 무료로 자동 발급 · 갱신해 줍니다.

http:// — 엽서

배달하는 사람 누구나 내용을 읽을 수 있습니다. 브라우저가 "주의 요함", "안전하지 않음" 경고를 띄웁니다. 로그인 비밀번호가 그대로 보일 수 있습니다.

https:// — 봉인된 편지

받는 사람만 열 수 있게 봉인되어 있습니다. 주소창에 자물쇠가 표시됩니다. 오늘 만든 로그인처럼 비밀번호를 입력받는 사이트는 반드시 HTTPS여야 합니다.

오늘 쓸 AI SPACE와 DAY 08에 쓸 GitHub Pages는 모두 SSL을 무료로 자동 적용해 줍니다. 배포한 뒤 주소창의 자물쇠를 직접 확인해 보세요.
