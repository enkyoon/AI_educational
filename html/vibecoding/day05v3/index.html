3.인증 · 권한 — 출입증과 들어갈 수 있는 방

DAY 04에서는 "누구나 메뉴를 볼 수 있다"는 규칙(RLS)만 만들었습니다. 그런데 실제 서비스는 "회원만 주문할 수 있다", "내 주문 내역은 나만 볼 수 있다"처럼 사람마다 할 수 있는 일이 다릅니다. 이걸 가능하게 하는 두 개념이 인증과 권한입니다.

인증 (Authentication · 로그인)

"당신은 누구인가?"를 확인하는 것. 이메일과 비밀번호가 맞는지 확인해서 이 사람이 누구인지 알아냅니다.

비유 — 회사 입구에서 사원증을 찍는 것

권한 (Authorization)

"당신은 무엇을 할 수 있는가?"를 정하는 것. 누구인지 확인된 사람이 어떤 데이터를 보고, 쓰고, 지울 수 있는지 정합니다.

비유 — 사원증으로 열리는 방이 사람마다 다른 것

MELLOW BEAN에 적용하면

누가 메뉴 보기 주문하기 다른 사람 주문 보기
로그인 안 한 방문자OXX
로그인한 회원OO (DAY 06에서 만듦)X

순서가 중요합니다. 인증이 먼저 있어야 권한을 정할 수 있습니다. 서버가 "이 요청은 김민지 님이 보낸 것"이라는 걸 알아야 "김민지 님의 데이터만 보여 준다"는 규칙을 적용할 수 있기 때문입니다.

핵심 — 인증 = 누구인지 확인(로그인), 권한 = 무엇을 할 수 있는지 결정(RLS 규칙)

4.로그인은 어떻게 작동할까? — 비밀번호 저장과 로그인 유지

로그인 버튼 하나 뒤에는 생각보다 많은 일이 숨어 있습니다. 이걸 직접 만들면 몇 주가 걸리지만, Supabase의 Auth(인증) 기능이 대신 처리해 줍니다. 그래도 무슨 일이 일어나는지 알아야 문제가 생겼을 때 AI에게 정확히 물어볼 수 있습니다.

① 회원 정보는 어디에 저장될까?

회원가입을 하면 Supabase 안의 회원 전용 표(auth.users)에 이메일과 가입 시간 등이 저장됩니다. 메뉴를 저장한 menus 표와는 따로 관리되고, Supabase 화면의 Authentication → Users에서 볼 수 있습니다.

② 비밀번호는 그대로 저장하지 않는다

비밀번호는 되돌릴 수 없는 암호문으로 바꿔서 저장합니다. 고기를 갈아 다짐육으로 만들면 다시 원래 고기 덩어리로 되돌릴 수 없는 것과 같습니다. 로그인할 때는 입력한 비밀번호를 똑같이 갈아 보고, 결과가 같으면 맞는 비밀번호로 판단합니다. 그래서 관리자도 회원의 비밀번호를 볼 수 없습니다.

③ 로그인 상태는 어떻게 유지될까? — 임시 출입증

로그인에 성공하면 서버가 임시 출입증을 발급하고, 브라우저가 이것을 보관합니다. 그 뒤로는 요청할 때마다 출입증을 함께 보내서 페이지를 옮겨도 다시 로그인하지 않아도 됩니다. 놀이공원 입구에서 받는 손목 밴드와 같습니다. 출입증에는 유효 시간이 있어서 시간이 지나면 자동으로 새로 발급되거나, 로그아웃하면 버려집니다.

이메일 · 비밀번호 입력

맞으면 임시 출입증 발급

요청마다 출입증을 보여 주고 내 데이터 받기

메뉴 이름과 위치는 Supabase 업데이트에 따라 조금 다를 수 있습니다. 찾기 어려우면 Claude Code에게 "Supabase에서 이메일 가입 확인(Confirm email)을 끄는 메뉴 위치를 알려줘"라고 물어보세요.

왜 가입 확인 메일을 끄나요?

실제 서비스에서는 "이 이메일이 진짜 내 것"임을 확인하려고 가입 확인 메일을 보냅니다. 그런데 Supabase의 기본 메일 발송은 시간당 보낼 수 있는 수가 아주 적어서, 반 전체가 동시에 가입하면 메일이 오지 않아 수업이 멈춥니다.

그래서 수업에서는 끄고 진행합니다. 실제로 서비스를 운영할 때는 다시 켜고, 별도 메일 발송 서비스를 연결해야 합니다.

9.STEP 05. Google Cloud에서 로그인 열쇠 만들기

구글에 "MELLOW BEAN이 구글 로그인을 요청해도 된다"고 등록하고, 열쇠 두 개(클라이언트 ID · 클라이언트 보안 비밀)를 받습니다. 결제 정보는 필요 없습니다.

① 프로젝트 만들기
  1. console.cloud.google.com에 들어가 내 구글 계정으로 로그인합니다. 처음이면 약관 동의와 국가 선택이 나옵니다.
  2. 화면 위쪽의 프로젝트 선택을 누릅니다.
  3. 새 프로젝트를 누릅니다.
  4. 프로젝트 이름에 mellow-bean-login을 입력하고 만들기를 누릅니다. 조직을 물으면 "조직 없음"으로 둡니다.
  5. 다시 프로젝트 선택을 눌러 방금 만든 프로젝트를 고릅니다.
② 로그인 화면 정보 · 대상
  1. 위쪽 검색창에 Google Auth Platform을 입력해 들어갑니다.
  2. 시작하기를 누릅니다.
  3. 앱 이름에 MELLOW BEAN, 사용자 지원 이메일에 내 Gmail을 고르고 다음을 누릅니다.
  4. 대상(Audience)에서 외부를 고르고 다음을 누릅니다.
  5. 연락처 이메일에 내 Gmail을 입력하고 다음을 누릅니다.
  6. 정책 동의에 체크하고 만들기를 누릅니다.
  7. 왼쪽 메뉴 대상 → 테스트 사용자의 사용자 추가를 누르고 내 Gmail을 넣어 저장합니다.

지금 앱은 "테스트 중" 상태라서 테스트 사용자에 적은 계정만 구글 로그인을 할 수 있습니다. 수업용으로는 이것으로 충분합니다.

③ 클라이언트(열쇠) 만들기
  1. 왼쪽 메뉴 클라이언트(Clients) → 클라이언트 만들기를 누릅니다.
  2. 애플리케이션 유형에서 웹 애플리케이션을 고릅니다.
  3. 이름에 mellow-bean-web을 입력합니다.
  4. 승인된 JavaScript 원본의 URI 추가를 누르고 http://127.0.0.1:5500을 넣습니다. 한 번 더 눌러 http://localhost:5500도 넣습니다.
  5. 새 탭에서 Supabase → Authentication → Sign In / Providers → Google을 펼치고 Callback URL을 복사합니다.
  6. 구글 화면으로 돌아와 승인된 리디렉션 URI의 URI 추가를 누르고 복사한 주소를 붙여 넣습니다.
  7. 만들기를 누릅니다.
  8. 나타난 클라이언트 ID와 클라이언트 보안 비밀을 복사해 메모장에 잠깐 붙여 둡니다.

클라이언트 보안 비밀은 비밀용 키입니다

DAY 04의 Secret Key와 같습니다. 코드 · GitHub · 카톡 · 캡처 어디에도 올리지 말고 Supabase 화면에만 넣습니다. 수업이 끝나면 메모장의 내용도 지우세요.

Google Cloud 화면은 자주 바뀝니다. 메뉴가 안 보이면 Claude Code에게 "Google Cloud에서 Supabase 구글 로그인용 OAuth 클라이언트를 만드는 순서를 지금 화면 기준으로 알려줘"라고 물어보세요.

11.STEP 07. [Google로 계속하기] 버튼 붙이고 확인하기

확인하기

  1. Header의 로그아웃을 눌러 로그아웃합니다.
  2. login.html에서 Google로 계속하기를 누릅니다.
  3. 테스트 사용자로 등록한 구글 계정을 고릅니다.
  4. index.html로 돌아와 Header에 내 이름이 보이는지 확인합니다.
  5. Supabase → Authentication → Users를 새로고침하고, 새 줄의 로그인 방법(Provider)이 google인지 봅니다.
관찰해 보기 — 정답 찾기가 아닙니다

같은 Gmail로 이메일 가입도 했다면, Users에서 한 회원으로 합쳐졌는지 따로 생겼는지 보세요. 설정에 따라 다릅니다.

안 될 때 — 화면에 나오는 말로 원인 찾기

이렇게 나오면원인
redirect_uri_mismatch구글에 넣은 리디렉션 URI가 Supabase Callback URL과 한 글자라도 다름
403 access_denied · "앱이 테스트 중"대상 → 테스트 사용자에 그 Gmail이 없음
로그인은 됐는데 엉뚱한 주소로 돌아감Supabase URL Configuration의 Redirect URLs에 127.0.0.1:5500/**가 없음
Unsupported providerSupabase에서 Google을 켜고 Save를 누르지 않음

세이브 포인트 — 구글 로그인이 되면 Commit해 두세요 (메시지 예: "구글 로그인").

12.혼자 해 보기 — 카카오 로그인

구조는 구글과 같습니다. 그 회사 개발자 사이트에 앱 등록 → 열쇠 받기 → Supabase에 넣기 → 버튼. 카카오는 Supabase가 기본으로 지원하지만, 등록 화면과 동의항목이 까다로워 수업에서는 순서만 안내합니다.

  1. developers.kakao.com에 카카오 계정으로 로그인합니다.
  2. 앱 → 앱 만들기로 앱을 만듭니다.
  3. 앱 설정 → 앱 → 플랫폼 키에서 REST API 키를 확인합니다. 이것이 Client ID입니다.
  4. 같은 화면에서 카카오 로그인 Client Secret을 확인하고 활성화합니다.
  5. 카카오 로그인 Redirect URI에 Supabase의 Callback URL을 넣습니다 (Supabase → Sign In / Providers → Kakao에서 복사).
  6. 제품 설정 → 카카오 로그인 → 일반에서 사용 설정을 ON으로 바꿉니다.
  7. 동의항목에서 닉네임 · 프로필 사진을 설정합니다.
  8. Supabase → Sign In / Providers → Kakao를 켜고, REST API 키와 Client Secret을 넣고 저장합니다.
  9. 버튼 요청은 STEP 07 프롬프트에서 "구글"을 "카카오"로, provider를 kakao로 바꿔 씁니다.

이메일 동의항목은 비즈 앱에서만

카카오 계정 이메일(account_email)은 사업자 정보를 등록한 비즈 앱에서만 받을 수 있습니다. 개인 연습이라면 이메일 없이 진행하고, Supabase의 Kakao 설정에서 Allow users without an email을 켜 주세요. 메뉴 이름은 카카오 업데이트에 따라 다를 수 있습니다.

13.네이버 로그인은? — 알아만 두기

구글 · 카카오

Supabase의 기본 목록에 있음 → 켜고 열쇠만 넣으면 됨

네이버

기본 목록에 없음 → 사용자 지정 로그인으로 붙일 수 있지만, 네이버가 돌려주는 정보 모양이 표준과 달라 중간에서 바꿔 주는 서버 코드가 필요

이 과정의 범위를 넘습니다. 실제 서비스에서 네이버 로그인이 꼭 필요하다면 개발자에게 맡기는 부분이라고 알아 두세요. 도전해 보고 싶다면 이렇게 물어보는 것부터 시작합니다.

14.빨리 끝났다면 — 내 정보 페이지

로그인한 회원만 볼 수 있는 mypage.html을 만들어줘. 보여줄 것: 이메일, 가입한 날짜, 로그인 방법(email / google) 로그인하지 않고 들어오면: login.html로 보내기 Header에 로그인했을 때만 "내 정보" 링크를 추가해줘. 다른 Section은 바꾸지 마.

확인 — 시크릿 창에서 mypage.html 주소를 바로 열면 login.html로 넘어가야 합니다.
