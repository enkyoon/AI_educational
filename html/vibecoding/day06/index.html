최종 프로젝트 제작 ①

DAY 05에서 만든 User Flow(흐름)와 Wireframe(화면 설계도)을 실제 웹페이지로 만듭니다. 오늘부터는 모두 서로 다른 개인 프로젝트를 만들지만, 기획 확인 → 구조 → 콘텐츠 → 핵심기능이라는 작업순서는 동일합니다.

1.수업 구성 · 오늘부터 달라지는 점

수업방식

핵심목표

DAY 05의 User Flow(흐름)와 Wireframe(화면 설계도)을 실제 웹페이지로 만들고, 꼭 필요한 기능의 기본 형태 완성하기

DAY 03·04

모두 MELLOW BEAN이라는 같은 프로젝트를 제작

DAY 06부터

각자 서로 다른 개인 프로젝트 제작 — 하지만 기획 확인 → 구조 만들기 → 콘텐츠 적용 → 핵심기능 만들기 → 결과 확인 → 수정이라는 작업순서는 동일

핵심 — 결과물은 다르지만 개발과정은 함께 진행합니다.

2.UI 용어 ① Header · Navigation

"위에 있는 거 조금 작게 해줘"보다 "Header의 높이를 줄여줘"가 훨씬 정확합니다. 오늘의 목표는 코드를 외우는 것이 아니라 화면에서 수정하고 싶은 부분의 이름을 알고 말할 수 있는 것입니다. 이렇게 화면을 이루는 부분들을 UI(사용자가 보고 누르는 화면 요소)라고 부릅니다.

Header (헤더)

웹페이지 가장 위쪽 영역. 주로 로고, Navigation(메뉴), 로그인·문의·메뉴 버튼이 위치

"Header의 높이를 조금 줄여줘."

Navigation (내비게이션, Nav)

사용자가 주요 페이지나 Section으로 이동할 수 있도록 만든 메뉴

"모바일에서 Navigation이 화면 밖으로 벗어나지 않게 해줘."

3.UI 용어 ② Hero Section · Section · CTA · Button

Hero Section (히어로 섹션)

웹사이트에 들어왔을 때 가장 먼저 크게 보이는 대표 영역. 주로 메인 제목, 설명, 대표 이미지, CTA Button으로 구성

Section (섹션)

웹페이지 안에서 하나의 목적을 가지고 구성된 영역. 예: About, Portfolio, Menu, Contact Section

CTA (Call To Action)

사용자에게 다음 행동을 유도하는 버튼·링크. 예: [문의하기] [프로젝트 보기] [신청하기]

Button

클릭하면 특정 행동이 실행되는 화면 요소. Button은 클릭 가능한 요소 자체, CTA는 그중 중요한 행동을 유도하는 역할

4.UI 용어 ③ Card · Form · Footer

Card (카드)

관련 정보를 하나로 묶어 보여주는 화면 요소. 상품, 메뉴, 포트폴리오, 게시글 등에 활용

Form / Input / Textarea

사용자의 정보를 입력받는 영역. Input(한 줄 입력창)은 이름·이메일, Textarea(여러 줄)는 문의내용·후기 등에 사용

Footer (푸터)

웹사이트 가장 아래에 위치. 회사정보, 연락처, 저작권 표시, SNS, 관련 링크 등이 위치

웹페이지 기본 구조 한 번에 보기 — Header → Navigation → Hero → Content Section → Card/Image/Text → CTA → Form → Footer

5.용어를 알면 프롬프트가 달라진다

용어를 모를 때

"맨 위에 메뉴 있는 부분이 너무 커. 조금 줄여줘." / "가운데 네모 3개 사이를 좀 벌려줘."

용어를 알고 있을 때

"Header의 높이를 조금 줄여줘. Navigation 글자 크기는 유지하고 위아래 여백만 줄여줘." / "Portfolio Section의 Card 3개 사이 간격을 넓혀줘. Card 크기는 유지해줘."

오늘의 공통 미션 — 개인 프로젝트를 제작하면서 오늘 배운 용어(Header, Navigation, Hero, Section, CTA, Button, Card, Form, Footer) 중 최소 3개 이상을 직접 프롬프트에 사용하기

6.STEP 01~03. Wireframe 점검 · 콘텐츠 정리 · BUILD_SPEC

STEP 01

Wireframe 최종 점검하기

새 기능 추가 제안이 나와도 "정말 필요한가?"를 먼저 판단하고, 필요하지 않다면 추가하지 않습니다.

STEP 02

실제 콘텐츠 준비상태 확인하기

오늘 모든 콘텐츠를 완벽히 준비하지 않아도 됩니다. 부족한 부분은 임시 콘텐츠를 쓰고 나중에 교체 가능하지만, 대표 이미지·프로젝트명·핵심문구 정도는 가능하면 준비합니다.

STEP 03

BUILD_SPEC 만들기

BUILD_SPEC (제작 설명서) — PROJECT_PLAN(무엇을 만들까) → Wireframe(어디에 무엇을 둘까) → BUILD_SPEC(실제로 무엇을 어떻게 만들까)

핵심 — BUILD_SPEC가 완성된 뒤 개발을 시작합니다.

8.STEP 05~06. 프로젝트 기본구조 · Header/Navigation 만들기

중요한 규칙 — 한 단계 요청 → 결과 확인 → 정상작동 → 다음 단계. 프로젝트 내용은 이미 BUILD_SPEC에 있으므로 긴 설명을 다시 입력하지 않습니다.
STEP 05

프로젝트 기본구조 만들기

결과 확인 — 지금은 디자인이 아니라 필요한 Page/Section, Header, Footer가 있는지, 순서가 Wireframe과 맞는지 뼈대만 확인합니다.

STEP 06

Header와 Navigation 만들기

확인 — 메뉴 직접 클릭 → 정확한 위치로 이동하는지. 예시 수정 프롬프트: "Header의 높이가 조금 커 보여. Navigation의 글자 크기는 유지하고 Header의 위아래 여백만 조금 줄여줘. 다른 Section은 변경하지 마."

9.STEP 07. Hero Section 만들기

결과 확인하기
사이트 목적이 첫 화면에 보이는가? 제목이 적절한가? 설명이 너무 길지 않은가? CTA가 필요한 위치에 있는가? CTA가 실제 행동으로 연결되는가?

수정 예시 — "Hero Section의 메인 제목을 현재보다 조금 크게 만들어줘. 설명과 CTA의 크기는 유지해줘. 다른 Section은 수정하지 마." 또는 "Hero Section의 이미지 영역이 너무 커 보여. 전체 배치는 유지하고 이미지 영역의 너비만 조금 줄여줘."

10.STEP 08~09. 핵심 콘텐츠 · 나머지 주요 Section 만들기

STEP 08

핵심 콘텐츠 Section 만들기

프로젝트마다 다릅니다 — Portfolio, Product, Menu, Class, Travel, Gallery 등. 공통점은 프로젝트의 핵심정보를 보여주는 영역이라는 것입니다.

Card가 있다면 — "Product Section의 Card 3개 높이를 동일하게 맞춰줘. Card 안의 이미지 영역 크기도 동일하게 만들어줘. Card 사이 간격은 일정하게 유지해줘."

STEP 09

나머지 주요 Section 만들기

프로젝트마다 Section 이름만 다릅니다 — About, Menu, Product, Location, Portfolio, Class, Contact 등

11.STEP 10. 실제 콘텐츠 적용하기

기본 구조가 만들어졌다면 임시 콘텐츠를 실제 콘텐츠로 변경합니다.

실제 이미지를 넣을 경우 — images 폴더에 파일 추가 후: "images 폴더에 실제 이미지를 추가했어. [파일명]은 [Section 이름]에 사용해줘. 이미지가 찌그러지지 않도록 비율을 유지해줘. 기존 배치와 콘텐츠는 변경하지 마."

12.STEP 11. 꼭 필요한 기능 만들기 시작하기

화면만 완성되어도 프로젝트가 끝난 것은 아닙니다 — 문의하기 Button이 있어도 실제로 작동하는지, 신청 Form이 데이터를 저장하는지 확인이 필요합니다. 보이는 것과 작동하는 것은 다릅니다.

Database 기능이 필요하다면 DAY 04에서 배운 방식을 그대로 활용합니다 — 현재 Database 구조 + 필요한 작업 + 저장할 데이터 + 수정하면 안 되는 범위를 AI에게 설명 → SQL 생성 → 역할 확인 → Supabase에서 실행. 바로 SQL 만들기 전에 데이터 구조부터 확인하는 것이 핵심입니다.

13.STEP 12. 현재 진행상태 점검하기

DAY 06에서 모든 기능을 완성할 필요는 없습니다. 오늘의 목표는 기본구조, 주요 Section, 실제 콘텐츠 일부, 첫 번째 꼭 필요한 기능까지입니다.

지금 하지 않을 것 — 화려한 움직임 효과, 복잡한 사진 슬라이드, 추가 페이지, 좋아요 기능, 새로운 Database Table, 불필요한 팝업창. 꼭 필요한 기능이 완성되지 않은 상태에서 기능을 계속 추가하면 프로젝트가 완성되지 않을 가능성이 높아집니다.

기본 반복 — 계획 → 요청 → 만들기 → 확인 → 다음 단계
