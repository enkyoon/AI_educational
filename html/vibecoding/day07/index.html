02
Layout Terms

Layout 용어 ① Container · Max Width

"내용이 너무 넓게 퍼져 보여요", "이미지가 너무 커요" 같은 문제는 코드를 외우는 것이 아니라 어떤 배치 문제가 발생하고 있는지 정확하게 표현하면 해결에 가까워집니다. (Margin·Padding은 DAY 03·06에서 이미 배운 개념)

Container (컨테이너)

화면이 넓어져도 콘텐츠가 끝없이 좌우로 퍼지지 않도록 전체 범위를 잡아주는 영역

"주요 Section의 Container에 적절한 Max Width를 적용해줘."

Max Width (최대 너비)

요소가 커질 수 있는 최대 크기. 예: max-width: 1200px — 화면이 2000px로 커져도 콘텐츠는 최대 1200px까지만 확장

03
Layout Terms

Layout 용어 ② Flexbox · Grid · Gap

Flexbox (한 방향 배치)

요소를 가로 또는 세로로 정렬. 활용: Logo+Navigation, Text+Image, 여러 Button, 좌우 2열 구조

"Hero Section을 Flexbox로 왼쪽 텍스트/오른쪽 이미지 2열로 만들어줘."

Grid (행과 열 배치)

반복되는 Card를 여러 열로 정리할 때 유용. Portfolio, Product, Menu, Gallery Card 등

초보자 기준 — 좌우로 크게 나누기 → Flexbox, 카드 여러 개 정렬하기 → Grid 정도로 이해해도 충분합니다.
Gap (갭, 요소 사이 간격)

Card와 Card 사이, 또는 Flexbox 요소 사이의 간격. Gap = 요소와 요소 사이, Padding = 요소 내부

"Portfolio Section의 Card 사이 Gap을 조금 넓혀줘. Card 내부 Padding은 유지해줘."

04
Layout Terms

Layout 용어 ③ Alignment · Width/Height · Aspect Ratio · Overflow

Alignment (정렬)

왼쪽·가운데·오른쪽·세로 중앙 정렬. "Hero의 텍스트와 이미지가 세로 중앙에 맞도록 조정해줘."

Width / Height

요소의 가로/세로 크기. Button이 너무 넓다면 Width, Hero가 너무 높다면 Height 수정

Aspect Ratio (화면 비율)

이미지의 가로:세로 비율(1:1, 16:9, 4:3). "모든 이미지 영역을 동일한 Aspect Ratio로 맞춰줘. object-fit: cover 사용해줘."

Overflow (오버플로)

콘텐츠가 지정된 영역을 넘어가는 현상. Mobile에서 가로 Scroll이 생기는 원인 중 하나

05
Responsive

Responsive · Breakpoint · 용어 사용 미션

Responsive Web / Breakpoint

같은 웹사이트라도 Desktop·Tablet·Mobile에서 화면 구조를 다르게 보여주는 방식이 Responsive이고, Layout이 변경되는 화면 크기 기준점이 Breakpoint입니다. "모바일 사이트를 따로 만드는 것"이 아니라 화면 크기에 따라 기존 Layout을 조정하는 것입니다.

Desktop: 3열 Grid
Tablet: 2열 Grid
Mobile: 1열 Grid
오늘의 용어 사용 미션 — Container, Max Width, Flexbox, Grid, Gap, Alignment, Aspect Ratio, Overflow, Responsive, Breakpoint 중 최소 3개 이상을 실제 프롬프트에 사용하기

Testing (기능이 의도한 대로 작동하는지 확인하는 과정)

화면에 Button이 있다고 작동하는 것은 아닙니다. 실제로 클릭 → 결과 확인까지 해야 합니다.

Navigation — 메뉴 클릭 → 정확한 Section 이동?
CTA — Button 클릭 → 의도한 행동 발생?
Form — 입력 → 등록 → 정상 처리?
Database — 등록 → Supabase 확인 → Row 생성?
프롬프트 04 — 테스트 항목 만들기
상자를 클릭하면 바로 복사돼요

BUILD_SPEC와 현재 프로젝트를 기준으로 Must Have 기능 테스트 체크리스트를 만들어줘. 각 기능마다 1.무엇을 테스트해야 하는지 2.사용자가 어떤 행동을 해야 하는지 3.정상이라면 어떤 결과가 나와야 하는지를 정리해줘. 새로운 기능은 제안하지 마. 현재 구현된 기능을 검증하기 위한 항목만 만들어줘.

AI가 "정상입니다"라고 말하는 것이 아니라, 학생이 브라우저에서 직접 클릭·입력·확인해야 합니다.

Debugging · STEP 05

Debugging (오류의 원인을 찾아 수정하는 과정)

문제가 발생하면 전체 코드를 다시 만드는 것이 아니라, 문제가 발생한 위치와 원인을 찾아 수정합니다. 테스트 중 문제가 생기는 것은 자연스러운 개발과정입니다.

X 좋지 않은 오류 요청

"안 돼. 고쳐줘."

문제 — 어디가 안 되는지, 어떤 결과가 필요한지 AI가 알기 어려움

O 좋은 오류 요청 구조

1.문제가 발생한 기능 2.내가 한 행동 3.기대한 결과 4.실제 결과 5.수정범위

오류 프롬프트 기본형
상자를 클릭하면 바로 복사돼요

현재 [기능 이름]에서 문제가 발생하고 있어. 내가 [사용자 행동]을 하면 원래는 [기대 결과]가 되어야 하는데 현재는 [실제 결과]가 발생하고 있어. [관련 기능]과 관련된 코드만 확인해줘. 먼저 문제의 원인을 설명하고, 확인된 원인과 관련된 부분만 수정해줘. 정상적으로 작동하는 다른 기능이나 디자인은 변경하지 마.

Console도 확인하기 — 화면만으로 원인을 찾기 어렵다면 Browser Developer Tools의 Console 오류 메시지를 그대로 Claude Code에게 전달합니다. 여러 오류를 한꺼번에 요청하지 않고 오류 하나 → 원인 확인 → 수정 → 테스트 순서로 진행합니다.

Overflow 점검하기

프롬프트 08
상자를 클릭하면 바로 복사돼요

Mobile 화면에서 불필요한 가로 Scroll이나 Overflow가 발생하는지 확인해줘. 발생한다면 어떤 요소가 화면 너비를 초과하는지 먼저 찾아줘. 원인을 설명한 후 해당 요소만 수정해줘. 문제를 숨기기 위해 전체 페이지에 단순히 overflow: hidden을 적용하지 말고 실제 원인을 찾아서 수정해줘.

중요 — 문제를 숨기는 것(X)이 아니라 원인을 수정하는 것(O)입니다.

15
Key Terms

오늘의 핵심 용어

Container / Max Width

콘텐츠 전체 너비 제한 영역 / 요소가 커질 수 있는 최대 너비

Flexbox / Grid

한 방향 정렬 방식 / 행과 열을 이용하는 배치 방식

Gap / Alignment

요소 사이 간격 / 요소를 일정한 기준에 맞추는 방식

Aspect Ratio / Overflow

이미지 가로세로 비율 / 콘텐츠가 영역을 벗어나는 현상

Responsive / Breakpoint

화면 크기별 Layout 변화 / Layout이 바뀌는 화면 크기 기준점

Testing / Debugging / Regression

정상작동 확인 / 오류 원인 찾아 수정 / 수정 후 생기는 새 문제

Wrap Up

DAY 07 정리 & 다음 수업
