3.STEP 02~03. 남은 꼭 필요한 기능 완성 · Database 마무리

STEP 02

남은 꼭 필요한 기능 완성하기

프로젝트마다 기능은 다릅니다 — 작업물 상세보기, 클래스 신청 입력창, 문의 입력창, 카페 메뉴 Database, 자료 목록 등

한 기능 완성 → 직접 확인 → 다음 작업. 바로 다음 기능으로 넘어가지 않습니다.

STEP 03

Database 기능 마무리하기

Database를 쓰지 않는 프로젝트는 건너뜁니다. 사용하는 경우 DAY 04에서 배운 방식(어떤 Table? 어떤 Column? 어떤 데이터? 어떤 작업으로?)을 그대로 활용합니다. 로그인이 필요한 프로젝트는 DAY 05에서 만든 이메일 로그인 방식과 "내 데이터만" 규칙을 그대로 씁니다.

핵심 — SQL 작성 능력보다 Database 작업을 정확하게 설명하는 능력이 중요합니다.

4.STEP 04. 직접 눌러 보며 확인하기

기능이 정말 작동하는지 확인하기

화면에 버튼이 있다고 작동하는 것은 아닙니다. 실제로 누르고 → 결과까지 확인해야 합니다. 개발자들은 이 과정을 Testing(테스트)이라고 부릅니다.

메뉴바 — 메뉴 누르기 → 정확한 Section으로 이동?
행동 버튼 — 버튼 누르기 → 원하는 행동이 일어나는가?
입력창 — 입력 → 보내기 → 정상 처리?
Database — 보내기 → Supabase에서 새 Row 확인?

AI가 "정상입니다"라고 말하는 것이 아니라, 내가 브라우저에서 직접 누르고 · 입력하고 · 확인해야 합니다.

5.STEP 05. 원인 찾아 오류 고치기

오류는 원인을 찾아 그 부분만 고치기

문제가 생기면 전체를 다시 만드는 것이 아니라, 문제가 생긴 위치와 원인을 찾아 고칩니다. 확인하다가 문제가 생기는 것은 자연스러운 과정입니다. 개발자들은 이 과정을 Debugging(디버깅)이라고 부릅니다.

X 좋지 않은 오류 요청

"안 돼. 고쳐줘."

문제 — 어디가 안 되는지, 어떤 결과가 필요한지 AI가 알기 어려움

O 좋은 오류 요청 구조

1.문제가 생긴 기능 2.내가 한 행동 3.기대한 결과 4.실제 결과 5.고칠 범위

말보다 캡처 한 장

화면이 이상하면 Win + Shift + S로 그 부분을 캡처한 뒤, Claude Code 입력창에 Ctrl + V로 붙여 넣고 위 오류 요청과 함께 보내세요. "Card가 이상해요"보다 훨씬 정확하게 알아듣습니다.

붙여 넣기가 안 되면 — 캡처를 프로젝트 폴더에 저장하고 "[파일 이름] 이미지를 보고 문제를 찾아줘"

오류 메시지 보는 법
  1. 내 사이트를 연 브라우저에서 F12
  2. 위쪽 탭에서 Console 누르기
  3. 빨간 글씨 오류 줄을 드래그해 복사 (또는 캡처)
  4. Claude Code에 붙여 넣고 "이 오류의 원인을 먼저 설명해줘"

여러 오류를 한꺼번에 요청하지 않고 오류 하나 → 원인 확인 → 고치기 → 다시 확인 순서로 진행합니다.

세이브 포인트 ① — 지금 Commit 하기

게임에서 보스 방에 들어가기 전에 저장하듯, 기능이 제대로 돌아가는 지금 저장해 둡니다. 이제부터 화면 배치를 여러 곳 고치게 되는데, 그러다 망가져도 이 지점으로 돌아올 수 있습니다.

Stage → Commit (메시지 예: "핵심 기능 완성"). Push는 수업 끝에 한 번 해도 됩니다. 방법은 DAY 03의 Git 저장 과정 참고

6.화면 배치, 이렇게 말해도 돼요 — 개발자 용어 대신 우리말로

기능이 제대로 돌아가면 이제 화면 배치를 정리할 차례입니다. 예전에는 화면 배치를 고치려면 개발자들이 쓰는 영어 용어를 먼저 외워야 했습니다. 하지만 AI와 함께 만드는 지금은 무엇이 어떻게 보이기를 원하는지 우리말로 정확히 말하면 충분합니다. AI는 두 가지 말을 모두 알아듣습니다.

예전 — 개발자들은 이렇게 말했어요

"Portfolio Section의 Card를 Grid 3열로 바꾸고 Gap을 넓혀줘. 이미지는 Aspect Ratio를 4:3으로 맞춰줘."

지금 — 우리는 이렇게 말해도 돼요

"작업물 Section의 카드를 한 줄에 3개씩 놓고, 카드 사이 간격을 넓혀줘. 사진은 모두 가로 4, 세로 3 비율로 맞춰줘."

개발자들은 무슨 뜻인가요? 우리는 이렇게 말해요
Container · Max Width넓은 화면에서 내용이 끝없이 퍼지지 않게 너비를 제한하기"PC에서 내용이 너무 넓게 퍼져. 가운데로 모아서 최대 너비를 정해줘."
Flexbox요소를 가로로 나란히(또는 세로로) 놓기"첫 화면을 왼쪽은 글, 오른쪽은 사진으로 나란히 놓아줘."
Grid카드 여러 개를 줄과 칸에 맞춰 놓기"카드를 한 줄에 3개씩 줄 맞춰 놓아줘."
Gap요소와 요소 사이 간격"카드 사이 간격을 조금 넓혀줘."
Alignment왼쪽 · 가운데 · 오른쪽 · 위아래 가운데에 맞추기"글과 사진의 높이 가운데를 맞춰줘."
Width · Height가로 크기 · 세로 크기"버튼이 너무 넓어. 가로를 줄여줘." / "첫 화면 높이를 줄여줘."
Aspect Ratio사진의 가로 : 세로 비율 (1:1, 4:3, 16:9)"카드 사진을 모두 같은 비율로 맞추고, 찌그러지지 않게 잘라서 보여줘."
Overflow내용이 정해진 칸이나 화면 밖으로 넘치는 것"휴대폰에서 화면 밖으로 넘치는 곳이 있어. 찾아서 고쳐줘."
영어 용어는 외우지 않아도 됩니다. 다만 AI가 답할 때 "Grid로 바꿨어요", "Gap을 넓혔어요"처럼 이 단어를 쓸 수 있습니다. 그때 왼쪽 칸을 보고 "아, 카드 줄 맞춤을 바꿨구나" 하고 알아보면 충분합니다.

8.휴대폰 화면 맞추기, 이렇게 말해도 돼요

화면 크기에 따라 배치가 바뀌게 하기

같은 웹사이트라도 PC · 태블릿 · 휴대폰에서 배치를 다르게 보여 주는 것입니다. 휴대폰용 사이트를 따로 만드는 것이 아니라, 화면 크기에 맞춰 지금 배치를 조정하는 것입니다.

PC: 카드 한 줄에 3개
태블릿: 한 줄에 2개
휴대폰: 한 줄에 1개
개발자들은 무슨 뜻인가요? 우리는 이렇게 말해요
Responsive (반응형)화면 크기에 맞춰 배치가 바뀌게 하기"휴대폰에서도 보기 좋게 화면을 맞춰줘."
Breakpoint배치가 바뀌는 화면 너비 기준"화면이 휴대폰만큼 좁아지면 카드를 한 줄에 1개씩 보여줘."
Desktop · MobilePC 화면 · 휴대폰 화면"PC 화면은 그대로 두고 휴대폰 화면만 고쳐줘."

9.STEP 09~11. 휴대폰 문제 찾기 · 화면 맞추기 · 넘침 점검

STEP 09

휴대폰 화면에서 먼저 문제 찾기

AI에게 바로 "휴대폰 화면 맞춰줘"라고 하지 않고, 내 눈으로 먼저 휴대폰 화면을 확인합니다. 컴퓨터에서 휴대폰 화면을 흉내 내 볼 수 있습니다.

PC에서 휴대폰 화면 보는 법 (Chrome)
  1. Live Server로 내 사이트를 열고 F12
  2. 왼쪽 위의 휴대폰·태블릿 모양 아이콘 누르기 (단축키 Ctrl + Shift + M)
  3. 화면 위쪽 기종 목록에서 iPhone 같은 휴대폰 하나 고르기
  4. 위에서 아래까지 끝까지 스크롤하며 아래 문제를 찾고, 보이면 바로 캡처
  5. 다 봤으면 같은 아이콘을 다시 눌러 PC 화면으로 돌아오기

화면이 어색하게 보이면 새로고침(F5) 한 번. 여유가 되면 실제 휴대폰으로도 확인해 보세요.

바꿀 곳이 많은 요청이라 DAY 02에서 배운 Plan 모드로 보내면 좋습니다. 고치기 전에 계획을 먼저 보여 주니, 읽어 보고 괜찮을 때 진행하세요.

10.STEP 12. 고친 뒤 다시 확인하기

고쳤더니 다른 곳이 망가지는 문제

한 곳을 고친 뒤 잘 되던 다른 곳에 새 문제가 생기는 경우가 있습니다. 예: 휴대폰 메뉴바를 고쳤더니 PC 메뉴바가 깨짐, 문의 입력창을 고쳤더니 Database 불러오기가 안 됨. 개발자들은 이것을 Regression(회귀)이라고 부르지만, 우리는 "고친 뒤 다시 확인하기"만 기억하면 됩니다.

핵심 — "고쳤다"가 끝이 아니라 "다른 것이 안 망가졌는지"까지 확인. AI 확인과 내가 직접 눌러 보기를 함께 합니다.

도저히 안 고쳐지면 — 세이브 포인트로 돌아가기

같은 문제를 세 번 넘게 고쳐도 안 되면, 붙잡고 있기보다 마지막 Commit으로 돌아가 다른 방법으로 다시 요청하는 편이 빠릅니다.

내 휴대폰으로 주소 열기 가로로 밀리는 곳이 없는가? 메뉴 · 버튼이 손가락으로 누르기 편한가? 이상한 곳은 캡처해서 DAY 08 작업목록에 추가

13.오늘 배운 말 한눈에 보기

왼쪽은 개발자들이 쓰는 말, 오른쪽은 우리가 AI에게 쓰면 되는 말입니다. 왼쪽은 AI 답에 나오면 알아보는 정도면 충분합니다.

Testing → 직접 눌러 보며 확인하기
Debugging → 원인 찾아 오류 고치기
Container · Max Width → 가운데로 모으고 최대 너비 정하기
Flexbox · Grid → 나란히 놓기 · 줄 맞춰 놓기
Gap · Alignment → 사이 간격 · 가운데 맞추기
Aspect Ratio · Overflow → 사진 비율 · 화면 밖으로 넘침
Responsive · Breakpoint → 휴대폰 화면 맞추기 · 배치가 바뀌는 너비
Regression → 고친 뒤 다시 확인하기
