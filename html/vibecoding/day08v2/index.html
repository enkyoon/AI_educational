DAY 08바이브코딩 · 최종 완성 · 공개 · 제출

최종 프로젝트 완성 — 다듬기 · 공개 · 제출 · 피드백

오늘은 새 기능을 만드는 날이 아니라 지금까지 만든 것을 완성하는 날입니다. 화면을 다듬고 최종 점검한 뒤, GitHub Pages로 누구나 볼 수 있게 공개하고 주소를 학원 카페에 제출합니다. 강사 피드백을 받아 바로 고쳐서 다시 반영하는 것까지가 오늘의 마무리입니다.

수업방식

3.디자인 다듬기, 이렇게 말해도 돼요 — 디자이너 용어 대신 우리말로

DAY 07에서 화면 배치를 우리말로 요청했듯이, 디자인을 다듬을 때도 마찬가지입니다. 예전에는 디자이너 · 개발자들이 쓰는 용어를 알아야 했지만, 지금은 어떻게 보이기를 원하는지 우리말로 구체적으로 말하면 AI가 알아서 처리합니다.

예전 — 디자이너들은 이렇게 말했어요

"Typography 정리하고 Visual Hierarchy 살려줘. Card는 Border Radius 12px에 Shadow 약하게, 버튼은 Hover에 Transition 넣어줘."

지금 — 우리는 이렇게 말해도 돼요

"글꼴을 두 가지로 줄이고, 중요한 제목일수록 크게 해줘. 카드 모서리를 조금 둥글게 하고 그림자는 연하게, 버튼은 마우스를 올리면 색이 부드럽게 진해지게 해줘."

디자이너 · 개발자들은 무슨 뜻인가요? 우리는 이렇게 말해요
Typography글꼴 · 크기 · 굵기 · 줄 간격을 일정하게 정리하기"글꼴은 제목용 하나, 본문용 하나만 써줘."
Visual Hierarchy중요한 것일수록 크고 굵고 눈에 띄게. 첫 화면 5초 안에 무엇을 하는 곳인지 보여야 함"첫 화면 제목 → 행동 버튼 → Section 제목 → 본문 순서로 크기 차이를 분명하게 해줘."
Border Radius모서리의 둥근 정도. 작으면 단정, 크면 부드러운 느낌"카드와 버튼의 모서리 둥글기를 똑같이 맞춰줘."
Shadow요소를 배경과 구분해 주는 그림자"카드 그림자를 더 연하게 해줘."
Hover · Transition마우스를 올렸을 때 바뀌는 모습 · 그 변화가 부드럽게 이어지는 것"버튼에 마우스를 올리면 색이 부드럽게 진해지게 해줘."
QA공개 전에 처음 온 사람의 눈으로 모두 확인하기"공개 전에 최종 점검해줘."
Feature Freeze마무리 단계에서 새 기능 추가 멈추기"이제 새 기능은 넣지 말고 다듬기만 해줘."

왼쪽 용어는 외우지 않아도 됩니다. AI가 답에서 "Shadow를 줄였어요"처럼 말하면 "그림자를 연하게 했구나" 하고 알아보면 충분합니다.

좋은 마우스 효과

버튼 색이 조금 진해짐, Card가 살짝 올라옴, 메뉴 글자 색이 바뀜

좋지 않은 마우스 효과

Card가 지나치게 커짐, 버튼이 크게 흔들림, 주변 배치까지 밀려남

6.GitHub Pages란? — 최종 제출은 왜 GitHub Pages일까

2교시

GitHub Pages

GitHub Repository에 저장한 HTML · CSS · JavaScript 파일을 무료로 인터넷에 공개해 주는 호스팅입니다. DAY 02부터 계속 Push해 온 그 Repository를 설정 한 번으로 사이트로 바꿀 수 있습니다. SSL도 자동으로 적용됩니다.

카페24 AI SPACE (DAY 05~07) GitHub Pages (DAY 08)
배포 방법MCP로 연결해서 "배포해줘"라고 말하기Git으로 Push하면 자동 반영
비용 · 기간무료 체험 14일, 이후 유료공개 Repository는 무료로 계속
할 수 있는 일웹사이트 + 서버에서 돌아가는 프로그램 · 자체 DatabaseHTML · CSS · JavaScript 파일로 된 사이트만. Database와 로그인은 Supabase가 담당
잘 맞는 경우서버 기능이 필요한 실제 서비스 운영포트폴리오 · 소개 사이트를 오래 공개

AI SPACE는 체험이 끝나면 사이트가 멈춥니다. 피드백을 받고, 수업이 끝난 뒤에도 포트폴리오로 계속 보여 주려면 오래 유지되는 주소가 필요하므로 최종 제출은 GitHub Pages로 합니다.

7.STEP 05. 공개 전 안전 점검 — 비밀 정보 · 경로 · 공개 설정

GitHub Pages로 공개하면 사이트뿐 아니라 Repository의 모든 파일을 누구나 볼 수 있게 됩니다. 공개 버튼을 누르기 전에 아래를 꼭 확인합니다.

① 비밀 정보가 없는가?

Supabase Secret Key, 비밀번호, 내 전화번호 · 주소 같은 개인정보가 코드나 md 파일에 없는지 확인합니다. Publishable Key는 공개되어도 되는 키입니다 (DAY 04).

② 첫 페이지 이름이 index.html인가?

GitHub Pages는 Repository 맨 위 폴더의 index.html을 첫 화면으로 엽니다.

③ 파일 경로가 /로 시작하지 않는가?

GitHub Pages 주소는 아이디.github.io/저장소이름/처럼 폴더 안에 있습니다. /images/a.jpg처럼 /로 시작하는 경로는 사진이 깨집니다. images/a.jpg처럼 써야 합니다.

④ 파일 이름의 대소문자가 맞는가?

Windows에서는 Photo.JPG와 photo.jpg를 같은 파일로 보지만, 서버는 다른 파일로 봅니다. 내 컴퓨터에선 보이던 사진이 공개 후 깨지는 흔한 원인입니다.

Repository를 Public(공개)으로 바꾸기

무료 계정은 Public Repository만 GitHub Pages를 쓸 수 있습니다. DAY 02에서 Private으로 만들었다면 위 점검을 마친 뒤 바꿉니다.

GitHub의 Repository → Settings → 맨 아래 Danger Zone → Change visibility → Public. (메뉴 위치는 바뀔 수 있습니다)

8.STEP 06. GitHub Pages로 공개하기

먼저 오늘 고친 내용을 모두 Commit → Push해서 GitHub에 올려 둡니다. GitHub Pages는 GitHub에 올라간 파일로 사이트를 만듭니다.

GitHub에서 내 Repository 열기 → Settings
왼쪽 메뉴 Pages
Source: Deploy from a branch
Branch: main · 폴더: / (root) → Save
1~3분 뒤 새로고침 → 위쪽에 주소와 Visit site 버튼
내 사이트 주소 모양 
https://내GitHub아이디.github.io/저장소이름/

이 주소가 오늘 제출할 최종 주소입니다. 메모장에 복사해 두세요.

공개된 주소에서 다시 확인하기

□ 주소가 https://로 시작하고 자물쇠가 보이는가?
□ 사진이 모두 보이는가? (깨지면 STEP 05의 ③ · ④ 확인)
□ Supabase 데이터 불러오기 · 저장이 되는가?
□ 내 휴대폰으로 열어도 잘 보이는가?

로그인 기능이 있다면 — Supabase → Authentication → URL Configuration의 Site URL을 GitHub Pages 주소로 바꿔 두세요. 비밀번호 찾기 메일 같은 링크가 이 주소로 연결됩니다. 이메일 · 비밀번호 로그인 자체는 바꾸지 않아도 작동합니다.

9.STEP 07. 학원 카페에 제출하기

학원 카페의 제출 게시판에 아래 양식으로 글을 올립니다. 강사가 주소로 들어가 직접 사이트를 써 보고 댓글로 피드백을 드립니다. 피드백 받고 싶은 부분을 구체적으로 적을수록 도움이 되는 답을 받을 수 있습니다.

[바이브코딩 최종 프로젝트 제출] 이름: 김민지 프로젝트 이름: SOOM 필라테스 한 줄 소개: 동네 직장인이 수업 종류를 보고 체험 수업을 바로 신청하는 사이트 사이트 주소: https://minji-kim.github.io/soom-pilates/ 꼭 필요한 기능: 1. 수업 목록(Supabase에서 불러오기) 2. 체험 신청 저장 3. 위치·운영 시간 안내 테스트 방법: 메인 → [수업 보기] → 원하는 수업의 [신청하기] → 이름·연락처 입력 후 보내기 테스트 계정: 없음 (로그인 기능 없음) AI와 만들면서 가장 어려웠던 점: 신청 버튼을 눌러도 저장이 안 됐는데, RLS에 INSERT 규칙이 없어서였다 피드백 받고 싶은 부분: 수업 Card의 정보가 한눈에 들어오는지, 신청 입력창이 너무 길지 않은지

10.STEP 08. 피드백 반영하기 — 고치고, Push하고, 알리기

피드백은 끝이 아니라 다음 수정의 출발점입니다. GitHub Pages는 Push하면 자동으로 다시 공개되므로, 같은 주소에서 바로 고친 결과를 보여 줄 수 있습니다.

1카페 댓글의 피드백 읽기
2하나씩 Claude Code에 요청 · 확인
3Commit → Push
41~3분 뒤 주소에서 Ctrl + F5로 확인
5카페 댓글로 "반영했습니다"

피드백이 여러 개면 한 번에 하나씩 고치고 확인합니다. 주소를 다시 열었는데 바뀌지 않았다면, 브라우저가 예전 화면을 기억(캐시)하고 있는 것이니 Ctrl + F5(Mac은 Cmd + Shift + R)로 강력 새로고침하세요.

핵심 — 만들고 → 공개하고 → 의견을 받고 → 고치는 것. 실제 웹사이트도 이렇게 계속 나아집니다.

11.AI SPACE 체험 정리하기

DAY 05에 시작한 카페24 AI SPACE 무료 체험은 곧 끝납니다. 카드를 등록하지 않았기 때문에 그냥 두어도 돈이 나가지 않습니다.

그냥 두면

체험 기간이 끝나면 AI SPACE에 올린 사이트가 멈추고, 일정 기간이 지나면 데이터가 지워집니다. 프로젝트 원본은 내 컴퓨터와 GitHub에 있으니 걱정하지 않아도 됩니다.

계속 쓰고 싶다면
