# 1교시
# 업무 요청의 구조


# 01. 짧은 요청 vs 구체적인 요청

① "워크숍 안내 메일 써줘."
② "해오름상사 총무팀이야. 전 직원 60명에게 보낼 11월 사내 워크숍 안내 메일을 써줘.
   일정·장소·준비물이 한눈에 보이게, 5문장 이내로, 제목도 함께."

→ 두 결과를 비교합니다. ①에서는 AI가 날짜·장소·분위기를 마음대로 정합니다.
AI는 내 머릿속을 모릅니다.


# 02. 업무 요청의 5칸 구조

역할     : 나는 누구인가 (직무·입장)
목적     : 무엇을 하려는가 / 무엇을 결정하려는가
대상     : 누가 읽는가 / 누구를 위한 결과인가
조건     : 꼭 지킬 것 (분량, 말투, 반드시 넣을 내용, 넣지 말 것)
결과 형식 : 어떤 형태로 받을까 (표, 목록, 이메일, 5줄 요약 …)

처음부터 다 채울 필요는 없습니다.
짧게 요청 → 결과 보기 → 부족한 칸 채우기 를 반복해도 됩니다.


# 실습 SET 01
# 하나의 요청을 칸 하나씩 채우며 발전시키기

새 채팅에서 STEP 01, 이후는 같은 대화에서 이어서.

STEP 01 가장 짧게
"사내 워크숍 프로그램을 기획해줘."

STEP 02 역할·대상 추가 (작성 틀)
나는 [역할]이야. 참석자는 [누가, 몇 명, 어떤 특징]이야.

STEP 03 목적 추가
이번 워크숍의 가장 중요한 목적은 [무엇]이야. 이 목적에 맞게 다시 구성해줘.

STEP 04 조건 추가
다음 조건을 지켜줘.
- [조건 1 — 예: 하루 일정, 오후 6시 전 종료]
- [조건 2 — 예: 1인 예산 5만 원 이내]
- [조건 3 — 예: 몸을 많이 쓰는 활동은 빼기]

STEP 05 결과 형식
[형식 — 예: 시간 / 프로그램 / 목적 / 준비물] 형태의 표로 정리해줘.

→ 처음 결과와 마지막 결과 비교 : "AI에게 판단 기준을 알려주면 결과가 달라진다"


# 03. 조건은 구체적으로

"짧게"        → "5문장 이내로"
"많이"        → "10개"
"쉽게"        → "전문용어 없이, 개념마다 예시 하나씩"
"보기 좋게"    → "제목 + 항목 3개 + 마지막에 요청사항 한 줄"

조건이 많으면 항목으로 나눠 쓰면 나도 확인하기 쉽고 고치기도 쉽습니다.

# 2교시
# 요청 기법과 AI 오류 줄이기


# 04. 역할 주기

"너는 [어떤 경험을 가진 누구]야. [그 입장에서 무엇을] 해줘."
예) "너는 10년 차 인사팀장이야. 신입 사원 입장에서 이 안내문에 빠진 정보를 찾아줘."

핵심은 "전문가처럼" 한 줄이 아니라 어떤 관점에서 무엇을 볼지 알려주는 것


# 05. 예시 보여주기

말로 설명하기 어려운 형식·말투는 예시 한두 개로 보여줍니다.

작성 틀
[만들 것 — 예: 사내 공지 제목]을 만들어줘.
내가 원하는 형태는 다음과 같아.
예시 1: [예시]
예시 2: [예시]
예시의 문장을 그대로 반복하지 말고 구조와 분위기만 참고해줘.
[대상·개수 — 예: 11월 워크숍 공지 제목 5개]


# 06. 복잡한 일은 단계로 나누기

"신규 사업 기획해줘" (한 번에) 대신
문제 찾기 → 아이디어 → 하나 골라 구체화 → 이름·홍보
중간중간 사람이 방향을 고릅니다. (7일차 기획안에서 다시 사용)


# 07. 할루시네이션(AI의 그럴듯한 거짓말)

- 없는 통계, 없는 연구, 없는 기능을 자신 있게 말함
- 이유 : 정답을 찾아오는 게 아니라 "그럴듯한 다음 말"을 만들기 때문
- 특히 조심 : 법률·세금·계약·통계·최신 정책·회사 규정

프롬프트로 줄일 수는 있지만 없앨 수는 없습니다. 최종 확인은 사람이.


# 실습 SET 02
# 오류를 줄이는 요청 방법

상황 ① 정보가 없는 질문 — 먼저 묻게 하기
"우리 회사 연차 규정을 알려줘." (AI는 우리 회사를 모름)
작성 틀
[알고 싶은 것]을 정리하고 싶어.
내가 자료를 아직 주지 않았다면 추측하지 말고,
정확한 답을 위해 내가 어떤 자료를 줘야 하는지 먼저 알려줘.

상황 ② 준 정보만 쓰게 하기
작성 틀
아래 정보만 사용해서 [문서 종류]를 작성해줘.
[정보 붙여넣기]
주어지지 않은 [예: 담당자 이름 / 금액 / 신청 방법]은 만들지 말고, 없는 내용은 빼줘.

상황 ③ 사실과 의견 나눠 받기
작성 틀
[주제]에 대해 설명해줘.
1. 확인 가능한 사실  2. 그에 대한 해석  3. 아이디어
를 나눠서 쓰고, 확인되지 않은 숫자는 만들지 말아줘.

상황 ④ 출처 요청
"중요한 숫자에는 출처와 작성 시점을 함께 적어줘." → 링크를 직접 눌러 확인


# 실습 SET 03
# 나만의 업무 요청 틀 만들기

내가 자주 하는 업무 하나를 골라 5칸을 채우고, 결과를 보며 한 가지씩 고칩니다.

작성 틀
역할: [나는 누구인지]
목적: [이 요청으로 무엇을 하려는지]
대상: [누가 읽거나 쓸 결과인지]
조건:
- [조건 1]
- [조건 2]
결과 형식: [어떤 형태로 받을지]

고치는 요청
너무 길다 → "핵심만 남겨 절반으로"
어렵다   → "전문용어 줄이고 쉬운 말로"
형식이 불편 → "표로"
정보 부족 → "답하기 전에 필요한 정보를 먼저 질문해줘"

잘 된 틀은 메모장에 저장해 두고 다음에 칸만 바꿔 다시 씁니다.
