4. Canvas란?

Canvas

 결과물을 오른쪽 화면에 문서처럼 띄워 두고, 대화로 계속 고치거나 원하는 부분만 골라 수정할 수 있는 기능입니다.

켜는 곳 — Gemini 입력창 아래 도구 → Canvas (메뉴 이름은 업데이트에 따라 다를 수 있음)

채팅
 고칠 때마다 전체가 새로 나옴 → 어디가 바뀌었는지 찾기 어려움

Canvas
 문서 하나를 계속 고쳐 나감 → 바뀐 곳만 바뀜, 직접 타이핑도 가능

5. 자료를 읽고 목차부터 설계하기
 제품 카드 · 수업용 가상 자료
 상품: 해오름 다회용 컵, 스테인리스 350ml.
공급가: 개당 4,500원(부가세 별도). 로고 인쇄 최소 100개, 인쇄비 별도 견적.
최소 주문: 50개. 배송비·정확한 납기는 주문 수량별 확인 필요.
확인된 것: 손세척 가능. 식기세척기 사용 가능 여부는 시험 중.
친환경 인증은 받지 않음. 경쟁사 대비 절감액을 계산한 자료는 없음.

 위 제품 카드와 아래 요청문을 함께 복사해 Gemini 새 채팅에 입력하세요. 제품 카드에 적힌 확정 정보와 아직 확인이 필요한 내용을 바탕으로 소개서를 준비합니다.
 나는 해오름상사 영업지원 담당자야. 첫 거래를 검토하는 기업 총무 담당자에게 다회용 컵 소개서를 보내려고 해.
위 제품 카드만 근거로 사용해줘.
아직 본문을 쓰지 말고, 구매 담당자가 결정 전에 궁금해할 질문 6개를 정리해줘.
그중 자료로 답할 수 있는 것과 추가 확인이 필요한 것을 나눠줘.
그다음 A4 두 쪽 이내 소개서 목차를 제안해줘. 각 항목에 넣을 사실과 비워 둘 정보를 적어줘.
과장된 환경 효과·인증·절감률을 만들지 말고, 견적 조건과 제품 설명을 구분해줘.

 목차를 읽고 고객에게 필요한 순서로 바꾸세요. 선택한 목차와 제품 카드를 같은 대화에 두고 Canvas를 켜서 다음 요청을 보냅니다.
 방금 확정한 목차로 기업 구매 담당자용 상품 소개서를 써줘.
목적은 바로 계약을 약속하는 것이 아니라, 샘플·견적 상담을 요청할지 판단하도록 돕는 것이야.
구매 조건은 항목 / 확인된 내용 / 별도 확인으로 표로 정리해줘.
가격의 부가세 여부, 최소 주문과 인쇄 최소 수량의 차이를 분명히 해줘.
시험 중인 식기세척기 사용은 확정 기능으로 쓰지 말고, 문의 전화는 실제 번호를 만들지 말아줘.
본문 뒤에 보내기 전 확인 목록을 따로 붙여줘.

6. 실습: 부분만 골라 고치기

 Canvas에서 문장이나 문단을 마우스로 드래그해 선택 하면 그 부분에 대해서만 요청할 수 있습니다.

연습 — 한 번에 한 곳씩

① "왜 친환경 사무용품인가" 문단 선택 → "거래처 담당자 입장에서 얻는 이익 중심으로"

 ② 상품 소개 부분 선택 → "상품마다 특징 / 이런 회사에 추천 / 주문 단위 표로"

 ③ 첫 인사 선택 → "더 짧고 부드럽게"

 ④ 회사 연락처는 AI에게 시키지 않고 직접 타이핑 으로 넣기

왜 한 곳씩? 여러 곳을 한 번에 고치면 어디가 바뀌었는지 놓치고, 고치지 말아야 할 곳까지 바뀝니다.

고칠 부분: 구매 조건 표와 문의 안내.
변경: 인쇄 최소 수량 100개와 일반 최소 주문 50개를 서로 다른 행으로 분리해줘.
추가: 배송·납기·인쇄비는 수량 확인 후 별도 견적이라는 안내를 한 줄 넣어줘.
유지: 제품 규격, 공급가 4,500원, 부가세 별도, 미확정 기능의 표시.
다른 본문과 제목은 바꾸지 말고, 수정 후 바뀐 항목을 목록으로 알려줘.

고칠 곳: 상품별 소개 부분
이렇게 바꿔줘: 상품마다 특징 / 이런 회사에 추천 / 주문 단위를 칸으로 나눈 표로
그대로 둘 것: 상품 이름과 [가격 확인 필요] 표시

7. 문서 종류별 구조

 문서는 "읽는 사람이 가장 먼저 알고 싶은 것" 이 앞에 옵니다.

문서 순서

보고서 결론(한 줄) → 근거 → 제안

 안내문 무엇을 → 언제·어디서 → 해야 할 일 → 문의처

 업무 매뉴얼 목적 → 준비물 → 순서(1, 2, 3…) → 자주 하는 실수 → 담당자

 결과 보고 계획 → 실제 결과 → 잘된 점·아쉬운 점 → 다음 계획

[문서 종류] 문서를 쓰려고 해. 읽을 사람은 [누구]이고 가장 궁금한 것은 [무엇]이야.
본문을 쓰기 전에 목차와 목차별 들어갈 내용 한 줄씩만 먼저 제안해줘.

거래처 주문 접수 업무 매뉴얼을 쓰려고 해. 읽을 사람은 새로 들어온 영업지원팀 직원이고 가장 궁금한 것은 주문이 들어왔을 때 무엇부터 해야 하는지야.
본문을 쓰기 전에 목차와 목차별 들어갈 내용 한 줄씩만 먼저 제안해줘.

목차를 보고 순서를 바꾸거나 뺀 다음 "이 목차로 본문을 써줘" 라고 요청합니다. 긴 문서는 목차부터 받는 것이 가장 빠릅니다.

 선택 실습 — 같은 방법으로 "거래처 주문 접수 업무 매뉴얼" 목차 받아 보기

[소개서 붙이기]

12. 프롬프트 역설계 — 자료와 판단까지 설계하기
 원하는 결과의 일부와 원자료를 보고 요청을 거꾸로 설계합니다. 예시와 문장을 똑같이 만드는 것이 아니라, 근거·조건·판단 한계를 빠뜨리지 않는 것이 목표입니다.
 역설계 1 · 충돌하는 제품 정보로 문서 설계
 받은 자료 · 수업용 가상 자료
 승인 카드: 컵 350ml, 4,500원 부가세 별도, 인쇄 최소 100개. 옛 소개서: 400ml, 4,000원, 인쇄 50개. 영업 메모: 다음 달 할인 검토 중.

 만들어야 할 결과의 일부 · 나머지는 직접 설계하기
 구매 담당자용 목차와 확인 목록이 먼저 나옵니다. 옛 가격·용량과 검토 중 할인은 확정 상품 정보로 들어가지 않습니다.

 결과를 그대로 받아쓰지 말고, 자료에서 쓸 것과 제외할 것·부족한 정보·확인 방법을 먼저 판단하세요. 필요한 요청을 직접 쓰고 실행한 뒤 한 번 이상 고칩니다.

막히면 생각할 지점 보기
 자료 우선순위와 승인 상태를 어떻게 지정하겠어요?
 나는 기업 총무 담당자에게 컵 소개서를 보낼 영업지원 사원이야.
자료를 먼저 대조해 값이 다른 항목과 승인 상태를 표로 정리해줘.
승인 카드를 현재 기준으로 삼고 옛 소개서의 수치를 섞지 마.
할인은 검토 중이므로 확정 조건으로 쓰지 마.
본문 전에 구매 판단에 필요한 목차와 각 항목의 근거·누락 정보를 제안해줘.
자료의 최신 승인 여부를 확인할 질문을 남겨줘.
내가 목차를 고른 뒤에만 본문을 써줘.
