4. 기획안이란? — 차이는 "근거"

 "왜(문제·목표) → 무엇을(내용) → 어떻게(실행) → 얼마나(예산·일정) → 그래서(기대효과)"를 읽는 사람이 한 번에 이해하고 결정할 수 있게 정리한 문서입니다.

아쉬운 기획안 "친환경이 대세이므로 판매를 늘리자"

좋은 기획안 "재생 용지가 매출의 절반 이상인데(판매 실적), 거래처들은 매번 주문하는 것을 번거로워한다(거래처 의견) → 재생 용지 정기 배송 상품 제안"

5. 확인 질문 → 문제 정의 → 대안 비교
 팀장 지시
 재생 용지가 매출의 큰 비중인데 주문할 때마다 번거롭다는 이야기가 있어요. 다음 분기에 해 볼 판매 확대 안을 가져오세요. 큰 투자 전에 작게 시험했으면 합니다.

 아직 해결책을 제안하지 마. 위 요청과 준비 자료로 기획 전에 확인할 질문을 정리해줘.
팀장에게 확인할 예산·기간·성공 기준·승인 범위와, 내부에서 조사할 반복 주문량·배송 여력·고객 불편을 나눠줘.
자료에 답이 있는 질문은 중복해서 묻지 말고 근거를 적어줘.
답이 없어도 가정으로 진행할 부분과 결정 전에 반드시 확인할 부분을 구분해줘.

 확인된 자료로 문제 또는 기회를 3개 정리하고 자료 위치를 적어줘. 아직 결론을 정하지 마.
내가 하나를 선택하면 서로 다른 실행 방식의 대안 3개를 제안해줘.
비교 기준은 고객 불편 해소·3개월 안에 시험 가능·추가 운영 부담·비용 확인 가능성이야.
점수는 객관적 통계가 아니라 현재 자료에 따른 가정임을 표시하고 근거가 약하면 판단 보류로 둬.
각 대안의 실패 조건과 확인할 비용을 적어줘. 추천을 그대로 확정하지 않고 내가 선택할게.

6. 실행 계획·예산·성공 기준 구체화하기
 선택한 대안: [내가 고른 대안과 이유]
확인된 제약: [인원·기간·예산 한도·고객 범위]
기획안 본문 전에 다음 표 세 개를 설계해줘.
1. 준비·모집·운영·평가 단계의 할 일 / 담당 역할 / 완료 기준 / 선행 작업.
2. 예산: 항목 / 단가 / 수량 / 확인된 금액 / 미확정 비용 / 확인할 곳.
3. 성과: 지표 / 현재 기준값 / 내가 정할 목표 / 측정 방법 / 확인 시점.
내가 주지 않은 목표나 단가를 확정하지 말고, 미확정 비용을 0원으로 계산하지 마.
합계는 확인된 소계와 미확정 항목을 따로 표시해줘. 일정·담당·비용이 충돌하면 본문을 쓰기 전에 알려줘.

 목표는 기대하는 희망 숫자와 현재 실적을 구분합니다. 근거가 부족한 목표는 시범 운영에서 측정할 지표로 남겨도 됩니다. 이후 기존 Canvas 작성·검토 단계에서 이 세 표를 근거로 사용하세요.

9. Apps Script란?

Apps Script

 Google 시트·문서·Gmail에 "이 일을 자동으로 해줘"라고 시킬 수 있는 기능입니다. 반복 작업을 해 주는 "매크로"와 비슷하고, 추가 비용이나 설치가 없습니다.

① Gemini에게 말로 요청

 ② 코드를 복사해 붙여넣기

 ③ 실행 버튼

안전 약속

· 받는 사람은 내 메일 주소 로만. 실제 동료·거래처에게 보내지 않습니다.

 · 개인 Google 계정은 자동 메일을 하루에 보낼 수 있는 수에 제한이 있습니다. 연습에는 충분합니다.

 · 코드를 이해할 필요는 없지만, 무엇을 하는 코드인지는 Gemini에게 물어 확인하고 실행합니다.

11. 실습: 예제 ② 시트 명단으로 맞춤 메일 보내기
 명단은 시트 아래 탭 이름을 명단으로 바꾸고 1행을 이름·이메일·부서·보낸 상태 순서로 만듭니다. 내주소는 모두 내 Gmail 아이디로 바꿉니다. 예비 코드는 TEST_EMAIL을 내 주소로 바꿔야 동작하며, 같은 Gmail의 +별칭만 허용합니다. previewMails의 로그를 확인한 뒤 sendMails를 한 번 실행하세요. 재실행에서 보냄은 건너뛰지만 발송 직후 기록 전에 중단되는 경우나 동시 실행까지 완전한 중복 방지를 보장하지는 않습니다.

김하늘 내주소+kim@gmail.com 영업팀

Gmail은 주소 뒤에 +글자 를 붙여도 모두 내 받은편지함으로 옵니다. 예) mymail@gmail.com → mymail+kim@gmail.com. 실제로는 나에게 3통이 오지만 3명에게 보낸 것처럼 연습할 수 있습니다. (회사 메일은 안 될 수 있으니 개인 Gmail로)

STEP 02 코드 요청

 Google 시트의 '명단' 탭으로 기획안 공유 메일을 보내는 Apps Script를 만들어줘.
첫 줄 제목, A 이름 / B 이메일 / C 부서 / D 보낸 상태. 함수 이름 sendMails.
처음에는 테스트 모드로 내 Gmail 주소 한 개만 허용하고, 내 주소는 코드 맨 위에서 지정하게 해줘.
공백 이메일·주소 형식 오류·허용 주소 외 수신자는 발송하지 말고 이유를 로그에 남겨줘.
상태가 '보냄'인 줄은 건너뛰고, 발송 성공 후에만 보냄을 기록해줘. 실패는 오류로 표시하고 다음 줄을 처리해줘.
본문에는 이름·부서·내가 준 문서 링크를 넣고, 제목·본문·수신 주소를 실행 전에 미리볼 별도 함수를 만들어줘.

// 내 Gmail 주소로 바꾼 뒤 previewMails부터 실행하세요.
const TEST_EMAIL = '내주소@gmail.com';
function mailRows_() {
 const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('명단');
 if (!sheet) throw new Error('명단 탭이 없습니다.');
 const rows = sheet.getDataRange().getValues();
 if (rows[0].slice(0, 4).join('|') !== '이름|이메일|부서|보낸 상태') {
 throw new Error('1행의 열 순서를 확인하세요.');
 }
 if (!/^[^@\s]+@gmail\.com$/i.test(TEST_EMAIL) || TEST_EMAIL === '내주소@gmail.com') {
 throw new Error('TEST_EMAIL을 내 Gmail 주소로 바꾸세요.');
 }
 return {sheet, rows};
}
function baseGmail_(email) {
 const parts = String(email).trim().toLowerCase().split('@');
 return parts[0].split('+')[0].replace(/\./g, '') + '@' + parts[1];
}
function processMails_(send) {
 const {sheet, rows} = mailRows_();
 for (let i = 1; i < rows.length; i++) {
 const [name, rawEmail, dept, state] = rows[i];
 if (String(state).trim() === '보냄') continue;
 const email = String(rawEmail).trim();
 if (!/^[^@\s]+@gmail\.com$/i.test(email) || baseGmail_(email) !== baseGmail_(TEST_EMAIL)) {
 console.log('건너뜀: ' + (i + 1) + '행, 주소 확인 필요');
 continue;
 }
 const subject = '[해오름상사] 판매 기획안 검토 요청';
 const body = name + '님(' + dept + ') 안녕하세요.\n공유한 기획안을 검토해 주세요.\n문서 링크: 확인 필요';
 if (!send) { console.log(JSON.stringify({row:i+1, email, subject, body})); continue; }
 try {
 MailApp.sendEmail(email, subject, body);
 sheet.getRange(i+1, 4).setValue('보냄');
 } catch (e) {
 sheet.getRange(i+1, 4).setValue('오류');
 console.log((i+1) + '행 실패: ' + e.message);
 }
 }
}
function previewMails() { processMails_(false); }
function sendMails() { processMails_(true); }

13. 프롬프트 역설계 — 자료와 판단까지 설계하기
 원하는 결과의 일부와 원자료를 보고 요청을 거꾸로 설계합니다. 예시와 문장을 똑같이 만드는 것이 아니라, 근거·조건·판단 한계를 빠뜨리지 않는 것이 목표입니다.
 역설계 1 · 점수표의 기준을 사람이 정하기
 받은 자료 · 수업용 가상 자료
 대안 A 샘플 발송, B 정기 배송, C 대폭 할인. 확인된 조건: 기존 직원 2명, 3개월 시범, 추가 인력 불가. 예산 미정. AI는 비용을 모두 낮음으로 평가해 C를 추천.

 만들어야 할 결과의 일부 · 나머지는 직접 설계하기
 비용 근거 없는 점수는 보류하고 운영 부담·고객 문제·실험 가능성으로 다시 비교합니다. 가장 높은 점수를 자동 확정하지 않습니다.
