2. 팀장 요청 — 모호한 부분은 확인하고 시작하기

9월 영업회의 메모 — 박 팀장, 서울점 최 과장, 부산점 정 대리, 대구점 한 주임

서울점 - 다회용 컵 잘 나감. 강남 IT 회사 두 곳이 단체 주문. "컵 세척은 어떻게 하냐"는 문의 많음.
부산점 - 6~7월 물류센터 이전으로 재고가 자주 비었음. 수요가 준 건 아닌 것 같다고 함. 8월부터 정상.
대구점 - 거래처가 대부분 오래된 제조업체. 친환경 상품에 관심 적음.
기타 - 경쟁사 A사가 "컵 + 세척 대행" 묶음 상품을 준비 중이라는 소문. 확인 안 됨.
팀장 - 처음엔 3개월 시범으로 작게. 다음 회의 때 방안 들어 보자.

자료 C · 시범 운영 조건 — 수업용 가상 자료
 기존 직원으로 운영하며 신규 채용은 이번 검토에서 제외.
컵 샘플 20세트 제작 단가 8,000원, 안내 인쇄 30,000원은 견적 확인 완료.
배송비·추가 작업시간·세척 대행 비용은 아직 확인하지 않음.
컵은 인증 미취득. 샘플 발송과 재주문 의향 확인은 가능하지만 성공률 자료는 없음.

 자료 D · 거래처 의견 — 수업용 가상 자료
 서울: IT 기업 두 곳의 단체 주문. 추가 문의는 세척 방식.
부산: 물류 정상화 후 거래 재개. 수요가 늘었다는 별도 조사 자료는 없음.
대구: 기존 공급 계약이 남았다는 고객 의견. 계약 만료일과 대상 수는 미조사.
경쟁사 세척 대행은 확인되지 않은 소문. 원문 기사·가격표 없음.

 스스로 지킬 기준

5. 분석 요약 — 비교 기준과 판단 한계
 자료 A의 판매 흐름과 B의 메모를 함께 사용합니다. 비교 기간·판매 수량·절대 변화·증감률 중 필요한 지표를 선택하세요. 담당자의 의견을 원인 확정으로 바꾸지 않습니다.

완성 기준
 반 쪽 분량의 핵심 결론과 숫자 근거.
비교 기간·단위·증감률 계산 기준이 명시됨.
표로 계산한 사실 / 메모에 근거한 설명 / 추측이 구분됨.
적어도 숫자 두 개를 직접 검산하고, 무엇을 확인했는지 기록함.

 막혔을 때 — 질문만 보기
 처음과 끝만 비교하면 놓치는 중간 변화는 무엇인가요? 지점의 규모와 성장률은 같은 순위를 보이나요? 메모의 “같다”는 표현은 사실인가요?

6. 기획 1쪽 — 대안과 근거를 연결하기
 분석에서 확인한 문제를 하나 선택하고 서로 다른 실행 방식의 대안 세 개를 비교합니다. 선택 이유·담당·기간·확인된 비용·미확정 비용·성과 측정 방법을 정한 뒤 1쪽으로 정리하세요.

중간 변경 요청 — 첫 초안이 나온 뒤 읽기
 팀장: 전 지점 동시 시범은 어렵겠어요. 한 지점에서 먼저 하고, 현금 지출 한도는 50만 원으로 검토해 주세요. 이 금액은 승인 예산이 아니라 검토 한도입니다. 기존 직원의 추가 업무도 비용과 별개로 적어 주세요. 경쟁사의 세척 대행은 확인되지 않았으니 따라 하자는 근거로 쓰지 마세요.

새 조건이 기존 대안과 맞지 않으면 대안을 다시 고를 수 있습니다. 초안을 억지로 유지하지 말고, 바뀐 부분과 선택 이유를 기록하세요.

7. 슬라이드 3장 — 결론·근거·결정 요청
 1장은 결론과 근거, 2장은 판매 흐름을 보여 주는 실제 데이터 차트, 3장은 시범 운영안과 결정 요청으로 구성합니다. 제목·차트·발표자 메모가 같은 주장을 뒷받침해야 합니다.

완성 기준
 매출 금액이 아닌 판매 수량 자료라는 점을 정확히 표시.
분석 요약과 같은 기간·단위·숫자를 사용.
한 지점 시범과 검토 한도 50만 원이 반영됨.
확인되지 않은 효과를 확정 수익으로 표현하지 않음.
예상 질문 3개 중 답이 없는 것은 확인할 자료와 담당을 남김.

 Canvas에서 슬라이드를 만든 뒤 Google 슬라이드로 내보냅니다. 내보내기가 없다면 구성과 문장을 새 슬라이드에 옮겨 완성합니다. 차트는 자료 A를 Google 시트에 넣어 생성하고 연결해 붙여넣습니다.

8. 제출과 최종 검토
 제출 기준
 08_제출_이름 폴더에 분석·기획·슬라이드 세 파일을 저장하고 강사 계정에 뷰어 공유.
세 파일의 비교 기간·단위·숫자·선택 지점·검토 예산 조건이 일치하는지 확인.
자료 A~D에서 가져온 근거와 내가 정한 가정을 구분.
중간 변경 전후 무엇을 바꿨고 무엇을 유지했는지 별도 메모.
처음 요청과 수정 요청 각 하나, 직접 검산한 숫자 두 개를 분석 문서 마지막에 기록.

 빠르게 끝났다면 기획을 거래처 안내로 바꿔 보세요. 내부 예산·가정·경쟁사 소문을 빼고 고객에게 확정적으로 말할 수 있는 정보만 남깁니다. 발표는 하지 않으며 강사의 검토 의견을 받아 필요한 부분을 고칩니다.

좋은 프롬프트는 외운 공식이 아니라 생각의 결과입니다. 어떤 결과가 필요한지 그려 보고 → 그 결과에 필요한 것을 요청하고 → 확인하고 고치는 것 은 사람의 몫입니다.

 회사 파일 작업은 Gemini로, 다른 도구를 쓰더라도 같은 자료와 조건으로 비교. 도구는 계속 바뀌어도 "목적을 정하고, 근거를 대고, 확인하는 습관"은 그대로 통합니다.
