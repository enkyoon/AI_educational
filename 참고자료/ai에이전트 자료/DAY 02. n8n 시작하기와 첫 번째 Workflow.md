# 02. n8n이란?

n8n은 여러 서비스와 기능을 **Node 단위로 연결하여 Workflow를 만드는 자동화 도구**입니다.

예를 들어 다음과 같은 작업을 연결할 수 있습니다.

**이메일 도착**

↓

**내용 가져오기**

↓

**AI가 내용 분석**

↓

**Google Sheets 저장**

↓

**담당자에게 이메일 전송**

또는

**사용자 문의**

↓

**AI가 문의 종류 판단**

↓

**고객 정보 검색**

↓

**적절한 답변 작성**

↓

**이메일 발송**

앞으로 하나씩 배우게 될 기능들을 연결하면 더 복잡한 자동화와 AI Agent를 만들 수 있습니다.

# 04. n8n을 사용하는 두 가지 방법

n8n은 크게 두 가지 형태로 사용할 수 있습니다.

## n8n Cloud

n8n이 운영하는 서버에서 사용하는 방식입니다.

웹브라우저에서 로그인하여 바로 사용할 수 있기 때문에 별도의 서버 관리가 필요하지 않습니다.

이번 과정의 대부분의 실습은 **n8n Cloud**를 이용합니다.

---

## Self-hosted n8n

n8n을 자신의 컴퓨터 또는 서버에 직접 설치하여 사용하는 방식입니다.

직접 운영하기 때문에 서버, 업데이트, 저장 공간 등의 관리가 필요할 수 있습니다.

### 이번 과정에서는

**Cloud**

→ 주요 실습 환경

**Self-hosted**

→ 설치 방식과 작동 원리 체험

으로 구분합니다.

---

# 05. Cloud와 Self-hosted 비교

| 구분 | n8n Cloud | Self-hosted |
|---|---|---|
| 설치 | 필요 없음 | 직접 설치 |
| 서버 관리 | n8n에서 관리 | 직접 관리 |
| 시작 난이도 | 낮음 | 상대적으로 높음 |
| 접근 | 웹브라우저 | 설치한 서버 주소 |
| 관리 부담 | 적음 | 서버 관리 필요 |
| 이번 수업 | 주 사용 환경 | 설치 체험 |

처음 n8n을 배우는 단계에서는 Cloud를 이용하면 Workflow 자체를 학습하는 데 집중하기 쉽습니다.

# 08. Workflow는 어디에서 시작될까?

Workflow에는 시작점이 필요합니다.

이 시작점을 **Trigger**라고 합니다.

예를 들어 다음과 같은 Trigger가 있습니다.

- 특정 시간이 되었을 때
- 이메일이 도착했을 때
- Form이 제출되었을 때
- Webhook으로 데이터가 들어왔을 때
- 사용자가 직접 실행했을 때

오늘은 외부 서비스 연결 없이 연습하기 위해 **Manual Trigger**를 사용합니다.

---

# 12. Data Mapping

이전 Node의 데이터를 다음 Node에서 가져와 사용하는 것을 **Data Mapping**이라고 생각할 수 있습니다.

예를 들어 앞 Node의 Output에 다음 정보가 있습니다.

```text
name : 홍길동
tool : n8n
```

다음 Node에서는 이 데이터를 가져와

```text
홍길동님이 n8n을 사용하고 있습니다.
```

처럼 새로운 결과를 만들 수 있습니다.

즉,

**이전 Node의 Output**

↓

**다음 Node의 Input**

↓

**새로운 Output**

이라는 구조입니다.

---

# 13. 데이터를 직접 입력하지 않는 이유

다음과 같이 작성할 수도 있습니다.

```text
홍길동님이 n8n을 배우고 있습니다.
```

하지만 이 경우 이름이 변경되면 직접 수정해야 합니다.

반대로 이전 Node의 데이터를 연결하면

```text
김민수
```

가 들어왔을 때는

```text
김민수님이 n8n을 배우고 있습니다.
```

로 자동으로 변경됩니다.

이것이 자동화에서 데이터를 연결하는 이유입니다.

# 16. Execution이란?

Workflow가 한 번 실행된 것을 **Execution**이라고 합니다.

예를 들어 Workflow를 세 번 테스트하면 세 번의 실행이 발생합니다.

Execution을 확인하면 다음 내용을 파악할 수 있습니다.

- Workflow가 정상적으로 실행되었는가?
- 어떤 Node까지 실행되었는가?
- 어떤 데이터가 전달되었는가?
- 어느 Node에서 문제가 발생했는가?

자동화를 만들 때는 단순히

**“된다 / 안 된다”**

로 판단하지 않습니다.

**어디까지 정상적으로 실행되었는가?**

를 확인하는 것이 중요합니다.

# 23. Self-hosted n8n 체험

- 자신의 컴퓨터에서 n8n이 실행되는 과정 경험

# 24. Docker란?

Self-hosted n8n을 실행하는 대표적인 방법 중 하나가 Docker입니다.

Docker는 프로그램과 프로그램 실행에 필요한 환경을 하나의 독립된 공간에 담아 실행할 수 있도록 도와줍니다.

간단하게 표현하면

**“n8n이 실행될 수 있는 준비된 상자를 컴퓨터에서 실행한다.”**

라고 생각할 수 있습니다.
