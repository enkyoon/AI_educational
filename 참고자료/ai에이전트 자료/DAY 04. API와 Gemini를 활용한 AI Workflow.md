# DAY 04  
# API와 Gemini를 활용한 AI Workflow

## 오늘의 학습 목표

DAY 03에서는 n8n과 Google Sheets, Gmail을 연결하여 실제 외부 서비스가 포함된 Workflow를 만들었습니다.

오늘은 이 Workflow 안에 **AI를 추가합니다.**

지금까지는 사람이 미리 정한 데이터를 저장하고 전달했다면, 오늘부터는 AI가 입력된 내용을 읽고 다음과 같은 작업을 수행합니다.

- 내용 요약
- 내용 분류
- 필요한 정보 추출
- 새로운 문장 작성
- 지정한 형식으로 결과 생성

오늘 수업이 끝나면 다음 내용을 이해할 수 있습니다.

- API의 기본 개념
- API Key가 필요한 이유
- API와 일반 웹서비스 사용의 차이
- Google AI Studio와 Gemini API의 관계
- Gemini API Key 발급 및 관리 방법
- n8n과 Gemini 연결 방법
- AI Model에 Prompt를 전달하는 방법
- 이전 Node의 데이터를 AI에게 전달하는 방법
- AI의 결과를 다음 Node에서 활용하는 방법
- 요약·분류·정보 추출·문장 생성 Workflow 제작
- AI 결과가 항상 동일하지 않을 수 있다는 점
- AI가 이해하기 쉬운 Prompt를 작성하는 기본 방법

# 02. 오늘부터 AI가 Workflow에 들어온다

오늘 만들 Workflow는 다음과 같습니다.

**고객 문의**

↓

**Gemini**

↓

**문의 내용 분석**

↓

**결과 생성**

↓

**Google Sheets 저장**

AI가 Workflow의 중간 단계에서 데이터를 읽고 새로운 결과를 만들어냅니다.

예를 들어 고객 문의가 다음과 같다고 가정합니다.

```text
수업을 신청했는데 개인 사정으로 취소하고 싶습니다.
환불은 어떻게 받을 수 있을까요?
```

Gemini에게 다음 작업을 요청할 수 있습니다.

```text
이 문의의 종류를 분류하세요.
```

결과:

```text
환불 문의
```

# 03. AI가 들어가면 무엇이 달라질까?

기존 자동화는 사람이 모든 조건을 미리 만들어야 합니다.

예를 들어

```text
문의 내용에 "환불"이라는 단어가 있으면
→ 환불 문의
```

라고 지정할 수 있습니다.

하지만 고객이 다음과 같이 작성한다면 어떨까요?

```text
수업을 더 이상 들을 수 없는데
결제한 금액을 돌려받을 수 있을까요?
```

문장에 `환불`이라는 단어가 없지만 의미는 환불 문의입니다.

AI는 문장의 **의미를 분석하여 처리**할 수 있습니다.

# 04. AI Workflow란?

AI Workflow는 일반적인 Workflow 안에 AI 처리가 포함된 구조입니다.

예:

```text
Input
  ↓

  ↓

```

```text
Google Sheets 저장
   ↓
이메일 작성
   ↓
Gmail 발송
```

처럼 사용할 수 있습니다.

# 05. API란?

API는 서로 다른 프로그램이 **정해진 방식으로 요청과 결과를 주고받을 수 있도록 만든 연결 방식**입니다.

API는 다음과 같이 생각할 수 있습니다.

### 사람이 Gemini를 사용하는 경우

```text
사람
 ↓
Gemini 웹사이트
 ↓
질문 입력
 ↓
Gemini 답변
```

### 프로그램이 Gemini를 사용하는 경우

```text
n8n
 ↓
Gemini API
 ↓
요청 전달
 ↓
Gemini 처리
 ↓
결과 반환
 ↓
n8n
```

즉, 사람이 직접 Gemini 웹페이지를 열지 않아도 **프로그램이 Gemini에게 작업을 요청할 수 있습니다.**

---

# 06. API를 음식점에 비유하기

API의 구조를 간단한 음식점으로 생각해볼 수 있습니다.

### 사용자

음식을 주문하는 사람

### API

주문을 전달하는 직원

### 서비스

음식을 만드는 주방

### Response

완성된 음식

구조는 다음과 같습니다.

```text
요청
 ↓
API
 ↓
서비스
 ↓
처리
 ↓
API
 ↓
결과
```

프로그램끼리도 비슷한 방식으로 요청과 결과를 주고받습니다.

---

# 07. API Request와 Response

API에서는 크게 두 가지 흐름을 이해하면 됩니다.

## Request

서비스에게 보내는 요청

예:

```text
다음 고객 문의를 3줄로 요약해주세요.
```

↓

Gemini

↓

## Response

서비스가 돌려주는 결과

```text
고객은 수업 취소를 원하고 있습니다.
결제 금액 환불 방법을 문의하고 있습니다.
환불 절차에 대한 안내가 필요합니다.
```

n8n에서는 이 Response를 다음 Node의 데이터로 사용할 수 있습니다.

# 08. API Key란?

API 서비스를 아무 프로그램이나 자유롭게 사용할 수 있다면 누가 얼마나 사용했는지 확인하기 어렵습니다.

그래서 많은 API에서는 **API Key**와 같은 인증 수단을 사용합니다.

API Key는 간단하게 다음과 같이 생각할 수 있습니다.

> API를 사용할 수 있도록 발급되는 고유한 인증 정보

구조:

```text
n8n
 ↓
API Key 확인
 ↓
Gemini API
 ↓
요청 처리
```

Google은 Gemini API 요청을 인증하기 위해 API Key를 사용할 수 있도록 제공하고 있습니다.

---

# 09. API Key는 비밀번호처럼 관리하기

API Key는 다른 사람에게 공개하지 않습니다.

피해야 할 행동:

```text
API Key를 SNS에 올리기
```

```text
공개 GitHub 저장소에 API Key 저장하기
```

```text
화면 캡처에 API Key가 보이도록 공유하기
```

```text
다른 사람에게 자신의 Key 전달하기
```

API Key가 노출되면 다른 사람이 내 계정의 API를 사용할 가능성이 있습니다.

# 12. 무료 사용과 비용

API는 웹사이트에서 AI를 사용하는 것과 과금 구조가 다를 수 있습니다.

Gemini API는 사용 가능한 무료 구간과 유료 사용 방식이 제공되며, 사용량과 모델에 따라 제한이나 비용 구조가 달라질 수 있습니다. 유료 등급을 사용하는 경우 Google Cloud Billing 설정이 필요할 수 있습니다.

실습에서는 항상 다음을 확인합니다.

- 현재 사용 중인 모델
- 무료 사용 가능 여부
- 사용량
- Rate Limit
- Billing 설정 여부

가격이나 무료 제공량은 변경될 수 있으므로 **현재 공식 페이지를 기준으로 확인합니다.**

# 15. Prompt란?

Prompt는 AI에게 전달하는 **지시사항**입니다.

예:

```text
요약해주세요.
```

도 Prompt입니다.

하지만 더 구체적인 Prompt를 사용할 수도 있습니다.

```text
다음 내용을 AI를 처음 배우는 사람도 이해할 수 있도록
2문장으로 요약하세요.

전문용어는 가능한 한 쉬운 단어로 바꾸세요.
```

Prompt가 구체적일수록 원하는 결과를 얻기 쉬워집니다.

---

# 16. Prompt의 기본 구조

처음에는 다음 네 가지를 기준으로 작성합니다.

### ① 역할

AI가 어떤 역할을 해야 하는가?

### ② 작업

무엇을 해야 하는가?

### ③ 데이터

무엇을 보고 작업해야 하는가?

### ④ 출력 형식

어떤 형태로 답해야 하는가?

---

# 17. Input → AI → Output

Gemini Node도 다른 Node와 기본 원리는 같습니다.

### Input

```text
고객 문의
```

↓

### Process

```text
Gemini가 내용을 분석
```

↓

### Output

```text
요약 결과
```

즉, AI라고 해서 n8n의 기본 데이터 구조가 달라지는 것은 아닙니다.

**앞 Node의 Output이 Gemini의 Input이 되고**

**Gemini의 Output이 다음 Node의 Input이 됩니다.**

# 21. 카테고리를 명확하게 지정하기

다음 Prompt와 비교합니다.

### 좋지 않은 Prompt

```text
이 문의가 뭔지 알려줘.
```

AI가 자유롭게 답하기 때문에 결과가 일정하지 않을 수 있습니다.

### 개선된 Prompt

```text
다음 문의를 반드시 아래 카테고리 중 하나로만 분류하세요.

- 수업문의
```

예:

```text

}
```

오늘은 JSON 문법을 암기하는 것이 목적이 아닙니다.

핵심은

> **AI의 결과를 다음 Node에서 사용하려면 결과의 형태도 설계해야 한다.**

는 점입니다.

- 문제가 발생한 위치를 확인하기 어려울 수 있음
- 출력 구조가 복잡해질 수 있음

## 여러 단계로 분리

장점:
- 각 결과 확인 가능
- 수정하기 쉬움
- 기능 재사용 가능

단점:
- Workflow가 길어짐
- AI 호출이 증가할 수 있음

무조건 Node를 많이 만드는 것이 좋은 것은 아닙니다.

# 46. API 호출도 사용량이 발생한다

Gemini Node가 실행될 때마다 Gemini API에 요청을 보낼 수 있습니다.

예를 들어

```text
Gemini 요약
 ↓
Gemini 분류
 ↓
Gemini 이메일 작성
```

구조에서는 하나의 데이터에 대해 여러 번 AI를 호출하게 됩니다.

따라서 실제 자동화를 운영할 때는

- 호출 횟수
- 처리할 데이터의 양
- 사용할 모델
- 속도
- 비용
- API 제한

을 함께 고려해야 합니다.

# 48. 오늘 배운 용어 정리

| 용어 | 의미 |
|---|---|
| API | 서로 다른 프로그램이 요청과 결과를 주고받는 연결 방식 |
| Request | API 서비스에 보내는 요청 |
| Response | API 서비스가 반환하는 결과 |
| API Key | API 사용을 인증하는 정보 |
| Gemini API | 프로그램에서 Gemini 기능을 사용할 수 있도록 제공되는 API |
| Google AI Studio | Gemini 모델과 API 관련 기능을 관리하고 테스트할 수 있는 환경 |
| Prompt | AI에게 전달하는 지시사항 |
| AI Model | 입력을 분석하고 결과를 생성하는 AI |
| Classification | 입력을 정해진 종류로 분류하는 작업 |
| Summarization | 긴 내용을 짧게 요약하는 작업 |
| Information Extraction | 입력에서 필요한 정보만 추출하는 작업 |
| Generation | 새로운 문장이나 콘텐츠를 생성하는 작업 |
| Structured Output | 다음 단계에서 사용하기 쉽도록 정해진 구조로 만든 AI 결과 |
