# DAY 05
# 조건과 분기로 똑똑한 Workflow 만들기

## 오늘의 학습 목표

DAY 04에서는 Gemini를 n8n에 연결하여 입력된 내용을 요약하고, 분류하고, 필요한 정보를 추출하는 AI Workflow를 만들었습니다.

오늘은 AI가 만든 결과에 따라 **Workflow가 서로 다른 경로로 움직이도록 구성합니다.**

예를 들어 Gemini가 고객 문의를 분석한 결과가 다음과 같다고 가정합니다.

```text
환불문의
```

그러면 Workflow는 환불 문의를 처리하는 경로로 이동합니다.

```text
고객 문의
   ↓
Gemini 분류
   ↓
환불문의인가?
   ↓
YES
   ↓
환불 처리 Workflow
```

오늘 수업이 끝나면 다음 내용을 이해할 수 있습니다.

- 조건 Condition의 기본 개념
- 참 True / 거짓 False 이해
- IF Node의 역할
- Switch Node의 역할
- 숫자, 문자, Boolean 값 비교
- 여러 조건을 이용한 Workflow 분기
- Gemini의 분류 결과를 조건으로 활용
- AI 판단과 규칙 기반 판단의 차이
- Edit Fields를 이용한 데이터 정리
- 조건에 따라 다른 Google Sheets / Gmail 작업 실행
- 복잡해진 Workflow를 읽고 테스트하는 방법
- AI 결과가 예상과 다를 때 문제를 찾는 방법

---

# 1교시
# 조건과 분기 이해하기

## 01. 지금까지의 Workflow

지금까지 만든 Workflow는 대부분 한 방향으로 이동했습니다.

```text
Trigger
   ↓
데이터 입력
   ↓
Gemini
   ↓
Google Sheets
   ↓
Gmail
```

어떤 데이터가 들어와도 동일한 길을 따라갑니다.

하지만 실제 업무에서는 모든 데이터를 동일하게 처리하지 않습니다.

---

# 02. 실제 업무에는 판단이 필요하다

다음과 같은 문의가 들어온다고 가정합니다.

### 문의 A

```text
수업 시간이 몇 시인가요?
```

### 문의 B

```text
결제를 취소하고 환불받고 싶습니다.
```

### 문의 C

```text
카드 결제가 가능한가요?
```

세 문의를 모두 똑같이 처리하는 것보다 문의 종류에 따라 다른 작업을 하는 것이 좋습니다.

```text
수업문의
→ 수업 안내

결제문의
→ 결제 안내

환불문의
→ 환불 담당자 전달
```

이처럼 특정 조건에 따라 Workflow의 경로를 나누는 것을 **분기 Branching**라고 생각할 수 있습니다.

---

# 03. 조건 Condition

조건은 다음 질문과 같습니다.

> 현재 데이터가 내가 정한 기준에 해당하는가?

예를 들어 다음과 같은 조건을 만들 수 있습니다.

```text
category가 "환불문의"인가?
```

결과는 두 가지입니다.

```text
YES
```

또는

```text
NO
```

컴퓨터에서는 이러한 상태를 흔히 다음과 같이 표현합니다.

```text
True
False
```

---

# 04. True와 False

조건이 맞으면

```text
True
```

조건이 맞지 않으면

```text
False
```

가 됩니다.

예:

```text
price > 100000
```

가격이

```text
150000
```

이라면

```text
True
```

가격이

```text
50000
```

이라면

```text
False
```

입니다.

---

# 05. 일상생활도 조건으로 움직인다

조건은 프로그래밍에서만 사용하는 개념이 아닙니다.

일상에서도 계속 조건을 판단합니다.

### 예시 01

```text
비가 오는가?
```

YES

↓

```text

```

NO

↓

```text
그냥 나간다.
```

---

### 예시 02

```text
회원인가?
```

YES

↓

```text
회원 할인 적용
```

NO

↓

```text
일반 가격 적용
```

---

### 예시 03

```text
결제가 완료되었는가?
```

YES

↓

```text
신청 완료 이메일
```

NO

↓

```text
결제 안내 이메일
```

자동화에서도 같은 방식으로 판단합니다.

# 06. IF Node

조건을 이용해 Workflow를 나누는 대표적인 Node가 **IF Node**입니다.

기본 구조:

```text
데이터
  ↓
 IF
↙   ↘
True False
```

IF Node에서는 하나 이상의 조건을 확인하여 데이터가 조건에 맞는 경로와 맞지 않는 경로로 나누어 처리할 수 있습니다.

# 11. 한 개 이상의 조건

경우에 따라 하나의 조건만으로 부족할 수 있습니다.

예를 들어 다음 조건을 생각합니다.

```text
결제가 완료되었고
금액이 100000원 이상인가?
```

두 조건이 모두 맞아야 특정 작업을 실행할 수 있습니다.

---

# 12. AND 조건

AND는 **모든 조건이 맞아야 하는 경우**입니다.

예:

```text
paid = true

AND

price >= 100000
```

두 조건이 모두 맞아야 True입니다.

---

# 13. OR 조건

OR는 **여러 조건 중 하나 이상이 맞으면 되는 경우**입니다.

예:

```text
category = 환불문의

OR

category = 결제문의
```

둘 중 하나에 해당하면 조건을 만족합니다.

---

# 14. AND와 OR 비교

## AND

```text
조건 A
그리고
조건 B
```

둘 다 필요

---

## OR

```text
조건 A
또는
조건 B
```

둘 중 하나만 맞아도 가능

# 15. IF Node가 적합한 경우

IF는 다음과 같이 **두 방향으로 나누고 싶은 경우**에 이해하기 쉽습니다.

```text
조건 만족
vs
조건 불만족
```

예:

```text
결제 완료 / 미완료
```

```text
성공 / 실패
```

```text
VIP / 일반
```

```text
환불문의 / 그 외 문의
```

하지만 경로가 많아지면 다른 방법이 필요합니다.

# 16. 문의 종류가 네 가지라면?

DAY 04에서 문의를 다음과 같이 분류했습니다.

```text
수업문의

결제문의

환불문의

기타
```

```text

     ↓ NO
결제문의인가?
     ↓ NO
수업문의인가?
     ↓ NO
기타
```

가능하지만 Workflow가 길어질 수 있습니다.

# 17. Switch Node

여러 값에 따라 여러 경로로 나누고 싶을 때 **Switch Node**를 활용할 수 있습니다.

개념:

```text
          ┌→ 수업문의
          │
category ─┼→ 결제문의
          │
          ├→ 환불문의
          │
          └→ 기타
```

하나의 값을 기준으로 여러 출력 경로를 만들 수 있습니다.

# 18. IF와 Switch의 차이

| 상황 | 사용 예 |
|---|---|
| 조건이 맞는지 아닌지 구분 | IF |
| 두 방향 중심 | IF |
| 하나의 값을 여러 종류로 분류 | Switch |
| 여러 카테고리 처리 | Switch |

중요한 것은 Node 이름을 외우는 것이 아니라

**“내 Workflow는 몇 가지 경로로 나뉘어야 하는가?”**

를 먼저 생각하는 것입니다.

# 21. AI와 조건의 역할은 다르다

여기서 중요한 차이가 있습니다.

### Gemini

문의 내용을 읽고 **의미를 판단**

↓

```text
category : 환불문의
```

### Switch

이미 만들어진 category 값을 기준으로 **실행 경로를 결정**

즉,

```text
AI = 의미 판단

조건 Node = 실행 경로 결정
```

이라고 생각할 수 있습니다.

---

# 22. AI에게 모든 것을 맡길 필요는 없다

예를 들어 다음 판단은 AI가 필요할 수 있습니다.

> 이 문의의 의미가 환불문의인가?

하지만 다음 판단은 AI가 필요하지 않을 수 있습니다.

> category 값이 `환불문의`인가?

이미 category라는 데이터가 존재한다면 단순한 조건으로 처리할 수 있습니다.

# 25. Prompt 다시 설계하기

조건 Node에서 사용해야 하기 때문에 Gemini의 Output이 일정해야 합니다.

### 좋지 않은 결과

```text
이 고객은 아마 환불 관련 문의를 하고 있는 것 같습니다.
```

### 좋은 결과

```text
환불문의
```

또는 구조화된 형태:

```text
category : 환불문의
```

자동화에서는 사람이 읽기 좋은 문장보다 **다음 Node가 사용하기 좋은 데이터**가 중요할 수 있습니다.

---

# 26. AI Output이 일정해야 하는 이유

Switch가 다음 값을 기다리고 있다고 가정합니다.

```text
환불문의
```

하지만 Gemini가

```text
환불 문의
```

또는

```text
환불
```

또는

```text
이 문의는 환불문의입니다.
```

라고 출력한다면 예상한 경로로 가지 않을 수 있습니다.

따라서 Prompt에서 결과 형식을 명확하게 지정해야 합니다.

---

# Prompt 예시

```text
다음 고객 문의를 아래 네 가지 중 하나로 분류하세요.
```

# 50. 오늘 배운 용어 정리

| 용어 | 의미 |
|---|---|
| Condition | 특정 기준에 해당하는지 확인하는 조건 |
| Branch | 조건에 따라 나뉘는 Workflow 경로 |
| True | 조건을 만족하는 상태 |
| False | 조건을 만족하지 않는 상태 |
| IF | 조건 결과에 따라 주로 두 방향으로 분기할 때 사용하는 방식 |
| Switch | 하나의 값을 여러 경우로 나누어 처리할 때 사용하는 방식 |
| AND | 여러 조건이 모두 맞아야 하는 조건 |
| OR | 여러 조건 중 하나 이상이 맞으면 되는 조건 |
| Boolean | true 또는 false 두 값을 가지는 데이터 형태 |
| Classification | AI가 내용을 정해진 종류로 분류하는 작업 |
| Mapping | 다른 Node의 데이터를 현재 Node에서 연결하여 사용하는 것 |

# 51. 오늘의 핵심 개념

## 첫 번째

**Workflow는 항상 한 방향으로만 움직일 필요가 없다.**

---

## 두 번째

**조건에 따라 서로 다른 경로로 움직일 수 있다.**

---

## 세 번째

**AI는 의미를 판단하고 조건 Node는 그 결과를 이용해 실행 경로를 결정할 수 있다.**

---

## 네 번째

**AI가 필요하지 않은 단순 비교까지 AI에게 맡길 필요는 없다.**

---

## 다섯 번째

```text
summary
```

```text
수업문의

환불문의
```

```text
기타
→ 일반문의
```
