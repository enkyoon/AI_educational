# 1교시  
# AI Agent와 Workflow의 기본 원리

## 01. AI가 다 해주는데 왜 배워야 할까?

ChatGPT와 같은 생성형 AI에게 질문하면 프로그램 사용법을 알려주고, 코드를 작성해주고, 오류 해결 방법까지 설명해줍니다.

그렇다면 이런 의문이 생길 수 있습니다.

**“GPT가 다 알려주는데 굳이 자동화를 배울 필요가 있을까?”**

하지만 AI에게 질문하는 것과 실제로 동작하는 자동화 시스템을 만드는 것은 서로 다른 능력입니다.

예를 들어 다음과 같은 자동화를 만들고 싶다고 가정해봅니다.

> 홈페이지에 고객 문의가 들어오면  
> 문의 내용을 AI가 읽고  
> 문의 종류를 판단한 뒤  
> Google Sheets에 저장하고  
> 담당자에게 이메일을 보내고 싶다.

GPT는 각각의 기능을 구현하는 방법을 설명할 수 있습니다.

하지만 자동화를 만들기 위해서는 먼저 사람이 다음 내용을 결정해야 합니다.

**어떤 정보가 들어오는가?**

↓

**어떤 작업을 해야 하는가?**

↓

**어디에서 AI의 판단이 필요한가?**

↓

**어떤 서비스와 연결해야 하는가?**

↓

**최종 결과는 무엇이어야 하는가?**

AI는 강력한 도구이지만, **무엇을 만들지 정의하고 전체 흐름을 설계하는 역할**은 여전히 중요합니다.

# 02. 이 수업에서 배우는 것은 특정 프로그램이 아니다

이번 과정에서는 n8n과 Google Opal을 사용합니다.

하지만 수업의 최종 목표가 **n8n 사용법을 암기하는 것**은 아닙니다.

AI 자동화 도구는 계속 변화합니다.

현재 사용하는 도구가 몇 년 후에는 다른 서비스로 바뀔 수도 있습니다.

중요한 것은 특정 버튼의 위치를 외우는 것이 아니라 다음과 같은 능력을 가지는 것입니다.

**문제를 발견한다.**

↓

**원하는 결과를 정의한다.**

↓

**작업을 작은 단계로 분리한다.**

↓

**각 단계에 필요한 도구를 선택한다.**

↓

**단계를 연결한다.**

↓

**결과를 테스트한다.**

↓

**문제가 발생하면 수정한다.**

이 흐름을 이해하면 사용하는 도구가 변경되어도 새로운 환경에 다시 적용할 수 있습니다.

# 03. 생성형 AI와 AI Agent는 무엇이 다를까?

## 생성형 AI

ChatGPT나 Gemini와 같은 생성형 AI는 사용자의 요청을 받아 새로운 내용을 생성합니다.

예를 들어 다음과 같은 작업을 할 수 있습니다.

| 입력 | AI의 처리 | 결과 |
|---|---|---|
| 긴 문서 | 핵심 내용 분석 | 문서 요약 |
| 상품 정보 | 문장 생성 | 상품 소개문 |
| 이메일 내용 | 내용 분석 | 답변 초안 |
| 아이디어 | 내용 확장 | 기획안 |
| 데이터 | 의미 분석 | 분류 결과 |

기본적인 구조는 다음과 같습니다.

**사용자 질문 → AI → 답변**

---

## 자동화 Automation

자동화는 반복해서 수행하는 작업을 정해진 규칙에 따라 실행하는 것입니다.

예를 들어 매일 같은 보고서를 이메일로 보내야 한다면 다음과 같이 자동화할 수 있습니다.

**오전 9시**

↓

**Google Sheets 데이터 가져오기**

↓

**보고서 작성**

↓

**담당자 이메일로 전송**

사용자가 매번 직접 작업하지 않아도 시스템이 정해진 순서대로 작업합니다.

---

## Workflow

Workflow는 하나의 목표를 처리하기 위해 여러 작업을 순서대로 연결한 **작업 흐름**입니다.

예를 들어 온라인 신청서를 처리하는 Workflow는 다음과 같이 표현할 수 있습니다.

**신청서 접수**

↓

**신청자 정보 확인**

↓

**Google Sheets 저장**

↓

**확인 이메일 발송**

각 단계가 연결되어 하나의 업무를 완성합니다.

---

## AI Workflow

Workflow 안에 AI가 포함되면 단순한 데이터 이동뿐만 아니라 내용을 분석하거나 생성할 수 있습니다.

예를 들어 다음과 같습니다.

**고객 문의 접수**

↓

**AI가 문의 내용 분석**

↓

**문의 유형 분류**

↓

**Google Sheets 저장**

↓

**답변 이메일 작성**

↓

**이메일 발송**

AI가 Workflow의 특정 단계에서 하나의 역할을 담당합니다.

# 04. AI Agent란?

AI Agent는 AI가 단순히 문장을 생성하는 것을 넘어 **주어진 목표를 달성하기 위해 필요한 행동을 판단하고 도구를 사용할 수 있는 구조**를 말합니다.

예를 들어 다음과 같은 AI Agent가 있다고 가정합니다.

> “이번 주 미처리 고객 문의를 확인하고 필요한 사람에게 답변을 보내줘.”

이 요청을 처리하려면 Agent는 여러 행동을 수행해야 합니다.

**사용자의 요청 이해**

↓

**고객 문의 데이터 확인**

↓

**미처리 문의 검색**

↓

**문의 내용 분석**

↓

**필요한 답변 작성**

↓

**이메일 발송**

↓

**처리 결과 기록**

단순 생성형 AI와 가장 큰 차이는 **답변만 만드는 것이 아니라 필요한 행동까지 연결할 수 있다는 점**입니다.

---

# 05. 자동화와 AI Agent 비교

| 구분 | 일반 자동화 | AI Agent |
|---|---|---|
| 실행 방식 | 미리 정해진 순서 | 상황에 따라 판단 가능 |
| 판단 | 사람이 조건 설정 | AI가 일부 판단 가능 |
| 실행 경로 | 비교적 고정 | 요청에 따라 달라질 수 있음 |
| AI 역할 | 선택적 | 핵심 역할 |
| Tool 사용 | 정해진 서비스 실행 | 필요한 Tool을 선택하여 실행 가능 |
| 예시 | 신청서가 오면 저장 후 이메일 발송 | 요청 내용을 분석하고 필요한 업무를 판단하여 처리 |

모든 자동화를 AI Agent로 만들 필요는 없습니다.

단순하고 반복적인 작업은 일반 Workflow가 더 적합할 수 있습니다.

반대로 여러 정보를 확인하고 상황에 따라 행동을 선택해야 한다면 AI Agent가 유용합니다.

# 06. Node란 무엇인가?

앞으로 사용할 자동화 도구에서는 **Node**라는 개념이 매우 중요합니다.

Node는 하나의 Workflow 안에서 **특정 역할 하나를 담당하는 작업 단위**라고 생각하면 됩니다.

예를 들어 다음 Workflow를 살펴봅니다.

**고객 문의**

↓

**AI 분석**

↓

**Google Sheets 저장**

↓

**이메일 전송**

이 Workflow에는 각각 다른 역할을 가진 Node가 존재합니다.

| Node | 역할 |
|---|---|
| 고객 문의 | 데이터를 받아옴 |
| AI | 문의 내용을 분석 |
| Google Sheets | 결과를 저장 |
| Email | 담당자에게 전달 |

Node 하나가 모든 일을 처리하는 것이 아니라 **각 Node가 자신의 역할을 담당하고 서로 연결됩니다.**

---

# 07. Trigger

Trigger는 Workflow가 **언제 시작되는지 결정하는 시작점**입니다.

Trigger는 Workflow를 작동시키는 신호라고 생각할 수 있습니다.

예를 들어 다음과 같은 Trigger가 있을 수 있습니다.

| Trigger | 의미 |
|---|---|
| 사용자가 버튼 클릭 | 버튼을 누르면 실행 |
| 이메일 도착 | 새로운 이메일이 오면 실행 |
| 신청서 제출 | 새로운 신청이 들어오면 실행 |
| 오전 9시 | 정해진 시간에 실행 |
| 새로운 데이터 등록 | 데이터가 추가되면 실행 |

Workflow를 설계할 때 가장 먼저 생각할 질문 중 하나는 다음입니다.

**“이 자동화는 언제 시작되어야 하는가?”**

---

# 08. Input과 Output

Node는 혼자 움직이지 않습니다.

대부분의 Node는 앞 단계에서 데이터를 받고, 작업을 처리한 뒤 다음 단계로 결과를 전달합니다.

이를 **Input과 Output**이라고 합니다.

### Input

Node로 들어오는 데이터

### Process

Node가 수행하는 작업

### Output

Node가 작업을 완료한 뒤 만들어낸 결과

예를 들어 AI 요약 Node가 있다고 가정합니다.

**Input**

> AI Agent는 다양한 Tool을 이용하여 사용자의 목표를 수행할 수 있습니다...

↓

**Process**

> 내용을 분석하고 핵심만 요약

↓

**Output**

> AI Agent는 목표 달성을 위해 여러 Tool을 활용하는 AI 시스템입니다.

이 Output은 다시 다음 Node의 Input이 될 수 있습니다.

---

# 09. 데이터는 Node를 따라 이동한다

Workflow를 이해할 때 가장 중요한 개념 중 하나입니다.

**앞 Node의 Output이 다음 Node의 Input이 됩니다.**

예를 들어 다음과 같습니다.

### STEP 01

사용자가 글을 입력합니다.

**Output**

> 자동화에 관한 긴 글

↓

### STEP 02

AI가 글을 요약합니다.

**Input**

> 자동화에 관한 긴 글

**Output**

> 요약된 글

↓

### STEP 03

다른 AI가 제목을 생성합니다.

**Input**

> 요약된 글

**Output**

> 자동화로 업무 시간을 줄이는 방법

↓

### STEP 04

결과를 사용자에게 보여줍니다.

하나의 데이터가 Node를 이동하면서 계속 변화합니다.

# 10. Node를 여러 개로 나누는 이유

다음과 같이 AI에게 한 번에 요청할 수도 있습니다.

> “이 글을 요약하고 제목을 만들고 SNS 게시글까지 작성해줘.”

하지만 Workflow에서는 작업을 여러 단계로 나누는 경우가 많습니다.

**글 입력**

↓

**내용 요약**

↓

**제목 생성**

↓

**SNS 게시글 작성**

↓

**Google Sheets 저장**

단계를 분리하면 각 단계 사이에 새로운 기능을 추가하거나 특정 작업만 수정하기 쉬워집니다.

예를 들어 나중에 다음과 같이 확장할 수 있습니다.

**내용 요약**

↓

**내용이 광고인지 판단**

↓

YES → SNS 게시글 작성

NO → 별도 저장

↓

**Google Sheets 저장**

↓

**담당자 이메일 전송**

작업이 복잡해질수록 **작은 기능으로 나누어 생각하는 능력**이 중요해집니다.

예를 들어 다음과 같은 목표가 있습니다.

↓

↓

↓

**담당자 결정**

↓

**담당자에게 전달**

# 24. 오늘 배운 개념 정리

| 용어 | 의미 |
|---|---|
| AI | 데이터를 바탕으로 분석·생성·판단 등을 수행하는 기술 |
| Automation | 반복 작업을 자동으로 실행하는 것 |
| Workflow | 여러 작업을 하나의 흐름으로 연결한 구조 |
| AI Workflow | Workflow의 일부 단계에서 AI를 활용하는 구조 |
| AI Agent | 목표를 이해하고 필요한 행동이나 Tool을 선택하여 작업을 수행하는 구조 |
| Node | 하나의 역할을 담당하는 작업 단위 |
| Trigger | Workflow를 시작시키는 조건 |
| Input | Node로 들어오는 데이터 |
| Process | Node에서 수행하는 작업 |
| Output | Node가 처리한 결과 |
| Flow | 작업이 진행되는 전체 순서 |
