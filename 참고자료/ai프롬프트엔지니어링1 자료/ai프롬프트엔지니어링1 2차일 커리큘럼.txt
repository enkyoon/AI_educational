# 1교시
# 프롬프트의 원리와 구조


# 01. 프롬프트란?

프롬프트는

AI에게 입력하는

질문 /
요청 /
조건 /
지시사항

을 의미합니다.


예를 들어


"이메일 써줘."


도 프롬프트이고


"거래처에 일정 변경을 안내하는
정중한 이메일을 작성해줘.

메일은 너무 길지 않게 하고
제목도 함께 만들어줘."


도 프롬프트입니다.


둘 다 틀린 요청은 아닙니다.


다만

AI가 알고 있는 정보의 양

이 다르기 때문에
결과도 달라질 수 있습니다.



# 02. AI는 내가 생각한 내용을 자동으로 알지 못한다

사람끼리 대화할 때는

상황을 어느 정도 알고 있기 때문에
짧게 이야기해도 이해할 수 있습니다.


예


"아까 그 자료 조금 줄여줘."


같은 표현도
상대방이 상황을 알고 있다면 이해할 수 있습니다.


하지만 AI에게 처음 요청할 때


누구에게 필요한지

무엇을 만들고 싶은지

어떤 상황인지

어떤 형태로 필요한지


정보가 없다면

AI가 많은 부분을
스스로 결정하게 됩니다.



# 03. 짧은 프롬프트부터 비교하기

먼저 아주 간단하게 요청해봅니다.


## 실습 프롬프트 ①

여행 계획 만들어줘.


결과를 확인합니다.


다음 내용을 생각해봅니다.


어디로 가는가?

몇 명이 가는가?

몇 박인가?

어떤 여행을 좋아하는가?

이동수단은 무엇인가?

예산은 어느 정도인가?


AI가 모르는 내용이 많습니다.


따라서 AI가
여러 조건을 임의로 정할 수 있습니다.



# 04. 정보를 조금 추가해보기

## 실습 프롬프트 ②

부산으로 2박 3일 여행을 갈 거야.

대중교통을 이용할 예정이야.

맛집과 카페를 좋아하고

첫 번째 결과와 비교합니다.


같은

'여행 계획'

이지만

상황과 조건을 알려주면
결과가 달라집니다.

# 08. 프롬프트를 길게 쓰는 것이 목적은 아니다

좋은 프롬프트라고 해서
반드시 길 필요는 없습니다.


예를 들어


"다음 문장을 자연스럽게 수정해줘.

작업 자체가 단순하다면
짧은 프롬프트로도 충분합니다.


반대로


기획 /
분석 /
비교 /

처럼 조건이 많은 작업에서는

조금 더 구체적인 정보가 필요할 수 있습니다.


즉,

프롬프트의 길이

보다

가 중요합니다.

① 역할 부여하기

② 예시 보여주기

③ 작업을 단계로 나누기

④ 선택지를 여러 개 받기

⑤ 결과를 평가하고 수정하기

⑥ 모르는 정보는 확인하도록 요청하기



# 23. 방법 ①
# 역할을 지정하기

AI에게 특정 관점이나 역할을 지정하면
어떤 기준으로 답해야 하는지
더 명확하게 전달할 수 있습니다.


예


"아이디어를 추천해줘."


보다


"너는 신제품을 기획하는
마케팅 담당자라고 생각하고
아이디어를 추천해줘."


처럼 사용할 수 있습니다.



# 24. 역할을 활용해보기

## 실습 프롬프트 ⑧

너는 SNS 콘텐츠를 기획하는
마케팅 담당자야.

20대 직장인을 대상으로 하는
신규 텀블러 제품을 홍보하려고 해.

인스타그램에서 활용할 수 있는
콘텐츠 아이디어를 8개 제안해줘.

각각

콘텐츠 주제 /
보여줄 내용 /
기대하는 반응

형태로 정리해줘.


여기서 중요한 것은

'전문가처럼 행동해.'

라는 말 자체보다

어떤 관점에서
무슨 일을 해야 하는지

구체적으로 알려주는 것입니다.



# 25. 방법 ②
# 예시를 보여주기

원하는 결과를 설명하기 어렵다면
예시를 보여줄 수 있습니다.


예를 들어
상품 제목을 만들고 싶다고 생각해봅니다.


원하는 형태가


"하루를 가볍게, 데일리 텀블러"

"작지만 충분한, 미니 파우치"

처럼

짧은 문구 + 제품명

형태라고 한다면

AI에게 예시를 보여줄 수 있습니다.

# 28. 방법 ③

# 29. STEP 01

# 30. STEP 02

## 수정 요청

'책상 위가 쉽게 어지러워진다'

라는 문제를 해결할 수 있는
제품 아이디어를 5개 제안해줘.

기존 제품과 완전히 새로운 발명품이 아니어도 괜찮아.

실제로 제작하거나 판매할 수 있을 정도로
현실적인 아이디어를 제안해줘.



# 31. STEP 03
# 제품 콘셉트 구체화하기

아이디어 하나를 선택합니다.


## 수정 요청

3번째 아이디어를 선택할게.

이 제품을 구체적으로 기획해줘.

다음 내용을 정리해줘.

- 제품의 핵심 기능
- 주요 사용자
- 사용상황
- 기존 제품과 차별화할 수 있는 점
- 예상되는 단점


좋은 점만 요청하지 않고

단점

도 함께 확인합니다.



# 32. STEP 04
# 이름과 홍보 아이디어 만들기

## 수정 요청

이 제품의 이름을 10개 제안해줘.

그다음

SNS에서 제품을 처음 소개할 때 사용할

↓

↓
이름
↓
홍보

순서로 진행했습니다.



# 33. 단계별로 진행하면 좋은 점

단계별로 작업하면


AI가 잘못 이해한 부분을
중간에 수정할 수 있고

마음에 들지 않는 아이디어를
초기에 제외할 수 있고

앞 단계의 결과를 활용해
다음 단계로 발전시킬 수 있습니다.


즉,

AI에게 한 번에 완성품을 요구하는 것보다

사람이 중간중간 방향을 결정하면서
함께 만드는 방식

으로 활용할 수 있습니다.



# 34. 방법 ④
# 하나가 아니라 여러 선택지를 받기

# 35. 서로 다른 방향으로 요청하기

## 실습 프롬프트 ⑪

신규 독서모임의 이름을 만들려고 해.

비슷한 이름을 여러 개 만드는 것이 아니라

서로 다른 방향으로 제안해줘.

1. 따뜻한 느낌
2. 전문적인 느낌
3. 재미있는 느낌
4. 감성적인 느낌
5. 미니멀한 느낌

각 방향마다 이름을 3개씩 제안해줘.


여러 선택지를 받고
사람이 좋은 방향을 선택합니다.

문장이 자연스럽다고 해서
내용까지 정확하다는 의미는 아닙니다.

# 57. 오늘의 핵심

좋은 프롬프트는

'길고 어려운 명령문'

이 아닙니다.


AI가 작업을 이해하는 데 필요한 정보를
명확하게 전달하는 것이 중요합니다.


오늘 배운 기본 구조는


목적

무엇을 원하는가?


상황

어떤 상황인가?


대상

누구를 위한 결과인가?


조건

무엇을 지켜야 하는가?


결과형식

어떻게 보여줄 것인가?


입니다.


하지만 처음부터
모든 내용을 완벽하게 작성할 필요는 없습니다.


간단하게 요청
↓
결과 확인
↓
부족한 부분 발견
↓
조건 추가
↓
결과 수정
↓
필요하면 다시 발전


과정을 반복하면 됩니다.
