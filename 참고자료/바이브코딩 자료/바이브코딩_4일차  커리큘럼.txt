# PART 서버 기본 개념 — 서버를 다루기 시작하면 알아야 할 단어

오늘부터 Supabase라는 "서버"를 사용한다.
코드를 몰라도 되지만, 단어의 뜻은 알아야 AI에게 정확히 요청하고 요금표 · 오류 메시지를 읽을 수 있다.
수준 — 웹을 모르는 고등학생 · 성인. 비유는 생활 속 장면(식당 · 장부 · 창고)으로.

# 서버 · 호스팅 · 배포 (8분)

### 서버 (Server)

요청을 받으면 필요한 것(웹페이지 파일, 데이터)을 보내 주는 컴퓨터.
누가 언제 접속할지 모르기 때문에 24시간 켜져 있고 인터넷에 연결되어 있다.
요청하는 쪽(내 휴대폰 · PC의 브라우저)은 클라이언트(Client).

### 웹사이트가 내 화면에 보이기까지

주소 입력 (클라이언트)
↓
서버에 "이 페이지 주세요" 요청
↓
서버가 HTML · CSS · JavaScript · 이미지 파일을 보내 줌
↓
브라우저가 받은 파일로 화면을 그림

비유 — 식당. 손님(클라이언트)이 주문하면 주방(서버)이 음식(파일 · 데이터)을 내보낸다.

### 지금 내 사이트는 누가 볼 수 있을까?

- 지금 : 파일이 내 컴퓨터 안에만 있음. 주소창이 file:/// 나 127.0.0.1 → 나만 볼 수 있음
- 배포한 뒤 : 파일이 서버에 있음. https:// 주소만 알면 누구나 볼 수 있음

### 호스팅 (Hosting)

서버를 직접 사서 관리하는 대신 업체의 서버 공간을 빌려 쓰는 것. 비유 — 상가 임대.

### 배포 (Deploy)

내 컴퓨터에서 만든 파일을 서버에 올려 공개하는 일. 비유 — 개업.

### 이 과정에서 만날 서버들

- Supabase : 데이터(메뉴, 회원 정보) 서버 — DAY 04 · 05 · 최종 프로젝트
- 카페24 AI SPACE : AI에게 말로 요청해서 웹사이트를 올리는 호스팅 (14일 무료 체험) — DAY 05~07
- GitHub Pages : GitHub에 저장한 웹사이트를 무료로 공개하는 호스팅 — DAY 08 최종 제출

# 데이터베이스 · 스토리지 · 메모리 (8분)

요금표에 "Database 500MB", "Storage 1GB", "메모리 256MB"처럼 저장 공간이 나뉘어 있다. 하는 일이 다르다.

- 데이터베이스 : 글자 · 숫자를 표 형태로 정리해 두는 곳. 비유 — 가게 장부. 예 — 메뉴 이름, 가격, 회원 이메일
- 스토리지 (저장공간) : 사진 · 영상 · PDF 같은 파일 자체를 보관. 비유 — 창고. 예 — 메뉴 사진 파일
- 메모리 (RAM) : 서버가 지금 처리 중인 일을 잠깐 올려 두는 곳. 꺼지면 사라짐. 비유 — 주방 작업대

### 메뉴 하나는 어디에 저장될까?

- Cream Latte, 6500, 설명 글 → 데이터베이스 (menus 표)
- cream-latte.jpg 사진 파일 → 스토리지 (오늘은 프로젝트의 images 폴더)
- 그 사진의 위치(주소) → 데이터베이스의 image_url 칸

장부에는 사진을 붙이지 않고 "창고 몇 번 선반"처럼 위치만 적는다.

### 용량 단위 감 잡기

KB < MB < GB (각각 약 1,000배)
- 메뉴 한 줄 — 1KB도 안 됨
- 웹용 사진 한 장 — 약 0.2MB / 휴대폰 원본 사진 — 3~5MB
- 용량을 차지하는 것은 대부분 사진과 영상 → 사진은 줄여서 쓰는 습관

# 트래픽 · 동시접속 (6분)

### 트래픽 (Traffic · 데이터 전송량)

서버와 방문자 사이에 오고 간 데이터의 양. 원래 뜻은 도로 위 교통량.
요금표에서는 전송량, 대역폭(Bandwidth), Egress라고도 쓴다.

### 계산해 보기

- 원본 사진 사이트 : 한 번 열 때 15MB × 하루 1,000번 = 하루 약 15GB
- 웹용 사진 사이트 : 한 번 열 때 1MB × 하루 1,000번 = 하루 약 1GB
→ 사진 크기만으로 10배 넘게 차이. 사진을 줄이면 빨라지고 비용도 줄어듦

### 동시접속 (Concurrent Users)

같은 순간에 사이트를 쓰고 있는 사람 수. 하루 방문자와 다르다. 비유 — 식당 좌석 수.

### 한도를 넘으면 — 서비스마다 다름

추가 요금 / 속도 제한 / 대기열 / 일시 정지
예 — AI SPACE 무료 체험은 동시접속 25명, 넘으면 대기열로 안내된다고 소개됨.
서비스를 고를 때 "트래픽 · 동시접속 한도와 넘었을 때 어떻게 되는지" 확인하기.

# API · API 키 (6분)

### API

프로그램끼리 정해진 방식으로 요청하고 답을 받는 창구. 비유 — 은행 창구.
내 웹사이트의 JavaScript → Supabase API에 "menus 보여줘" → 메뉴 데이터 응답.

### API 키

창구에 요청할 때 함께 내미는 출입증.

- 공개용 키 (Publishable Key) : 손님용 출입증. 웹사이트 코드에 들어가므로 누구나 볼 수 있다는 전제. 할 수 있는 일은 RLS(접근 규칙)로 제한 → STEP 05
- 비밀용 키 (Secret Key) : 사장님 마스터키. 모든 규칙을 무시. 코드 · GitHub · 채팅방 · 캡처 어디에도 올리지 않기. 노출되면 Supabase에서 새 키로 바꾸기

기억할 것 — AI에게 연결을 요청할 때도 "Secret Key는 사용하지 마"를 꼭 붙인다.

# 오늘의 핵심 용어

### Database (데이터베이스, 데이터를 체계적으로 저장하고 관리하는 공간)

웹사이트에서 지속적으로 사용할 데이터를 보관하는 공간

### Supabase (웹서비스용 Database와 Backend 기능을 제공하는 플랫폼)

웹사이트에서 사용할 데이터를 저장하고 연결할 수 있도록 도와주는 서비스

### Table (테이블, 같은 종류의 데이터를 저장하는 표)

메뉴처럼 같은 종류의 데이터를 모아 관리하는 구조

### Column (열, 데이터의 항목)

name, price처럼 어떤 정보를 저장할지 결정

### Row (행, 실제 데이터 한 건)

Cream Latte 하나와 같은 실제 데이터

### SQL (Structured Query Language, 구조화 질의 언어)

Database에 데이터를 추가·조회·수정·삭제하도록 요청하는 언어

### RLS (Row Level Security, 행 단위 보안)

Database의 데이터에 누가 어떤 작업을 할 수 있는지 제한하는 기능

### Publishable Key (공개용 연결 키)

브라우저에서 Supabase 프로젝트에 연결할 때 사용하는 Key
