인증이 먼저 있어야 권한을 정할 수 있다. 권한은 DAY 04에서 배운 RLS(접근 규칙)로 정한다.

# 03. 로그인은 어떻게 작동할까? (7분)

① 회원 정보는 Supabase의 회원 전용 표에 — Authentication → Users에서 보임
② 비밀번호는 되돌릴 수 없는 암호문으로 저장 — 고기를 갈면 덩어리로 못 돌아감. 관리자도 비밀번호를 볼 수 없다
③ 로그인하면 임시 출입증 발급 → 브라우저가 보관 → 요청마다 함께 보냄 — 놀이공원 손목 밴드. 새로고침해도 로그인이 유지되는 이유
흐름 : 이메일 · 비밀번호 입력 → 암호문 비교 → 임시 출입증 발급 → 브라우저 보관 → 요청마다 보여 주고 내 데이터 받기
Supabase가 대신 해 주는 일 : 회원 표 관리, 암호문 저장, 출입증 발급 · 갱신, 비밀번호 찾기 메일, 소셜 로그인
우리가 할 일 : 가입 · 로그인 화면, 로그인 상태에 따라 화면 바꾸기, 규칙 정하기

# 실습 STEP 01
# Supabase에서 이메일 로그인 준비 (5분)

Authentication → Sign In / Providers → Email이 켜져 있는지 확인 → Confirm email(가입 확인 메일) 끄기 → Save → Users 메뉴 열어 두기
강사 메모 — Supabase 기본 메일 발송은 시간당 보낼 수 있는 수가 아주 적어 반 전체가 동시에 가입하면 확인 메일이 오지 않는다. 수업에서는 반드시 끈다. 실제 운영 때는 다시 켜고 별도 메일 발송 서비스를 연결해야 한다고 한 줄 언급.
메뉴 이름은 업데이트로 바뀔 수 있음 — 막히면 Claude Code에게 메뉴 위치를 묻게 한다.

# 실습 STEP 02
# 회원가입 · 로그인 화면 만들기 (13분)

### 프롬프트 01 — Claude Code에 입력하기
MELLOW BEAN 사이트에 Supabase Auth로 이메일 회원가입과 로그인을 만들고 싶어. login.html을 새로 만들어줘.
1. 회원가입: 이메일, 비밀번호(6자 이상) 입력칸과 [회원가입] 버튼
2. 로그인: 같은 입력칸으로 [로그인] 버튼
3. 성공 · 실패 결과를 화면에 한국어로 보여줘 (예: 비밀번호가 틀렸습니다)
4. 로그인에 성공하면 index.html로 이동
Supabase 연결은 기존 supabase-client.js를 쓰고, Publishable Key만 써. Secret Key는 절대 쓰지 마.
디자인은 디자인노트.md의 색과 글꼴에 맞춰 단순하게. index.html은 아직 건드리지 마.
끝나면 만든 파일과, 쓴 Supabase 기능 이름을 알려줘.

눈으로만 확인할 기능 이름 : signUp(가입) / signInWithPassword(로그인) / signOut(로그아웃) / getSession · onAuthStateChange(지금 로그인 상태)

### 프롬프트 02
index.html의 Header 오른쪽에 로그인 상태를 보여줘.

# 04. 소셜 로그인이란 (5분)

"Google로 계속하기" = 구글이 "이 사람 우리 회원 맞아요"라고 대신 확인해 주는 것
비유 — 호텔 체크인 때 여권 대신 회사 사원증을 보여 주고, 호텔이 그 회사에 전화로 확인하는 것
좋은 점 : 비밀번호를 새로 만들 필요 없음, 이메일이 이미 확인된 계정
필요한 것 : 구글에 "내 사이트가 로그인을 요청해도 된다"고 등록 → 열쇠 두 개(Client ID · Client Secret)를 받아 Supabase에 넣기
흐름 : [Google로 계속하기] → 구글 로그인 창 → 구글이 Supabase로 결과 전달 → Supabase가 회원 만들기 · 출입증 발급 → 내 사이트로 돌아옴

헷갈리는 주소 두 개 (표로 보여 주기)
| 주소 | 어디에 적나 | 뜻 |
| 내 사이트 주소 http://127.0.0.1:5500 | 구글(승인된 JavaScript 원본) · Supabase(URL Configuration) | 로그인을 시작하고 돌아올 곳 |
| Supabase Callback URL https://프로젝트.supabase.co/auth/v1/callback | 구글(승인된 리디렉션 URI) | 구글이 결과를 보내는 곳 |
Live Server 기본 주소는 http://127.0.0.1:5500. 주소창에 localhost:5500이 보이면 그것도 함께 등록.

# 실습 STEP 05
# Google Cloud에서 로그인 열쇠 만들기 (15분)

console.cloud.google.com → 구글 계정 로그인 (처음이면 약관 동의 · 국가 선택) — 결제 정보는 필요 없음
① 위쪽 프로젝트 선택 → 새 프로젝트 → 이름 mellow-bean-login → 만들기 → 만든 프로젝트 선택
② 왼쪽 메뉴(또는 검색창) Google Auth Platform → 시작하기
③ 앱 정보 : 앱 이름 MELLOW BEAN, 사용자 지원 이메일 = 내 Gmail → 다음
④ 대상(Audience) : 외부 → 다음 → 연락처 이메일 = 내 Gmail → 동의 → 만들기
⑤ 대상 메뉴 → 테스트 사용자 → 사용자 추가 → 내 Gmail (테스트 중인 앱은 여기에 적은 계정만 로그인할 수 있음)
⑥ 클라이언트(Clients) → 클라이언트 만들기 → 애플리케이션 유형 "웹 애플리케이션" → 이름 mellow-bean-web
⑦ 승인된 JavaScript 원본 : http://127.0.0.1:5500 (그리고 http://localhost:5500)
⑧ 승인된 리디렉션 URI : Supabase → Authentication → Sign In / Providers → Google을 펼치면 보이는 Callback URL 복사해서 붙여넣기
⑨ 만들기 → 클라이언트 ID와 클라이언트 보안 비밀 복사 (메모장에 잠깐, 수업 끝나면 지우기)
주의 — 클라이언트 보안 비밀은 비밀용 키와 같다. 코드 · GitHub · 카톡 · 캡처에 올리지 않는다. Supabase 화면에만 넣는다.
화면 이름은 자주 바뀜 → 막히면 Claude Code에게 "Google Cloud에서 Supabase 구글 로그인용 OAuth 클라이언트를 만드는 순서를 지금 화면 기준으로 알려줘"

# 실습 STEP 06
# Supabase에 구글 연결 · 주소 등록 (8분)

① Authentication → Sign In / Providers → Google → Enable Sign in with Google 켜기
② Client IDs 칸에 클라이언트 ID, Client Secret 칸에 보안 비밀 붙여넣기 → Save
③ Authentication → URL Configuration
   - Site URL : http://127.0.0.1:5500 (수업 중) — DAY 08에 GitHub Pages 주소로 바꿈
   - Redirect URLs → Add URL : http://127.0.0.1:5500/** (그리고 http://localhost:5500/**)

# 실습 STEP 07
# [Google로 계속하기] 버튼 붙이고 확인하기 (10분)

### 프롬프트 03
login.html에 [Google로 계속하기] 버튼을 추가해줘.
Supabase Auth의 signInWithOAuth로 구글 로그인을 하고, 로그인이 끝나면 index.html로 돌아오게 해줘.
돌아오는 주소는 지금 열려 있는 사이트 주소를 기준으로 만들어줘. (Live Server와 나중에 공개할 주소에서 모두 동작하게)
Google Cloud와 Supabase 설정은 내가 이미 끝냈어. Client Secret은 코드에 넣지 마.
기존 이메일 가입 · 로그인과 디자인은 그대로 둬.

확인하기
① 로그아웃 → login.html → [Google로 계속하기] → 구글 계정 선택 → index.html로 돌아오고 Header에 내 이름
② Supabase → Users → 새 줄의 Provider(로그인 방법)가 google
③ 같은 Gmail로 이메일 가입도 했다면 한 회원으로 합쳐지는지, 따로 생기는지 확인 (설정에 따라 다름 — 정답 찾기가 아니라 관찰)
안 될 때 가장 흔한 원인 (화면에 나오는 말 → 원인)
- redirect_uri_mismatch → 구글에 적은 리디렉션 URI가 Supabase Callback URL과 한 글자라도 다름
- 403 access_denied / 앱이 테스트 중 → 대상 → 테스트 사용자에 내 Gmail이 없음
- 로그인은 됐는데 이상한 주소로 돌아감 → Supabase URL Configuration의 Redirect URLs에 127.0.0.1:5500/** 가 없음
- Unsupported provider → Supabase에서 Google을 켜고 Save를 안 누름
세이브 포인트 : Commit ("구글 로그인")

# 05. 카카오 · 네이버 — 혼자 해 보기 (5분 안내)

수업에서는 안내만 한다. 구조는 구글과 같다 : 그 회사 개발자 사이트에 앱 등록 → 열쇠 받기 → Supabase에 넣기 → 버튼

카카오 (Supabase 기본 지원)
① developers.kakao.com → 로그인 → 앱 → 앱 만들기
② 앱 설정 → 앱 → 플랫폼 키 → REST API 키 = Client ID, 같은 화면에서 카카오 로그인 Client Secret 확인 · 활성화
③ 카카오 로그인 Redirect URI에 Supabase Callback URL 등록
④ 제품 설정 → 카카오 로그인 → 사용 설정 ON
⑤ 동의항목 : 닉네임 · 프로필 사진. 이메일(account_email)은 비즈 앱(사업자 정보 등록)에서만 받을 수 있음
⑥ 이메일을 못 받으면 Supabase Kakao 설정에서 "Allow users without an email" 켜기
⑦ Supabase → Sign In / Providers → Kakao 켜기 → 키 넣기 → Save → 버튼 프롬프트는 구글과 같고 provider만 kakao

네이버 (Supabase 기본 목록에 없음)
- 기본으로 연결되는 목록에 네이버가 없다. 사용자 지정 로그인(Custom OAuth)으로 붙일 수 있지만, 네이버가 돌려주는 정보 모양이 표준과 달라 중간에서 바꿔 주는 서버 코드(Edge Function)가 필요하다
- 초보자 수업 범위를 넘는다. 도전하고 싶으면 Claude Code에게 : "Supabase에 네이버 로그인을 붙이는 방법을 단계별로 알려줘. 내가 직접 해야 하는 설정과 코드가 필요한 부분을 나눠서"
- 실제 서비스에서 네이버 로그인이 꼭 필요하면 개발자에게 맡기는 부분이라고 알려 둔다

강사 확인 필요 — 카카오 메뉴 이름(플랫폼 키 위치), 비즈 앱 조건, Supabase 사용자 지정 로그인 기능의 무료 플랜 제공 여부는 수업 전에 확인

# 강사용 — 자주 막히는 곳

- 가입은 됐는데 로그인이 안 됨 → Confirm email이 켜져 있음
- "Invalid API key" → supabase-client.js의 URL · Publishable key
- 새로고침하면 로그아웃됨 → 시작할 때 getSession으로 상태를 확인하는지 AI에게 점검 요청
- Google Cloud 프로젝트 만들기에서 조직 선택이 나옴 → "조직 없음"
- 구글 로그인 후 127.0.0.1이 아니라 localhost로 돌아옴(또는 반대) → 두 주소 모두 등록
- 학원 PC 크롬에 다른 사람 구글 계정이 로그인돼 있음 → 시크릿 창에서 진행
