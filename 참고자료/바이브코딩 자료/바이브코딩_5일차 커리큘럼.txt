# 02. 인증 · 권한 — 출입증과 들어갈 수 있는 방 (8분)

- 인증(Authentication · 로그인) : "당신은 누구인가?" 확인. 비유 — 회사 입구에서 사원증 찍기
- 권한(Authorization) : "당신은 무엇을 할 수 있는가?" 결정. 비유 — 사원증으로 열리는 방이 사람마다 다름

MELLOW BEAN에 적용하면
- 로그인 안 한 방문자 : 메뉴 보기 O / 단골 메뉴 저장 X / 다른 사람 단골 보기 X
- 로그인한 회원 : 메뉴 보기 O / 단골 메뉴 저장 O(내 것만) / 다른 사람 단골 보기 X

인증이 먼저 있어야 권한을 정할 수 있다.
핵심 — 인증 = 누구인지 확인(로그인), 권한 = 무엇을 할 수 있는지 결정(RLS 규칙)

# 03. 로그인은 어떻게 작동할까? (8분)

① 회원 정보 저장 위치 — Supabase의 회원 전용 표(auth.users). Authentication → Users에서 보임
② 해시(Hash) — 비밀번호를 되돌릴 수 없는 암호문으로 바꿔 저장. 비유 — 고기를 갈면 덩어리로 못 돌아감. 관리자도 비밀번호를 볼 수 없다
③ 토큰 · 세션 — 로그인하면 임시 출입증(토큰) 발급 → 브라우저가 보관 → 요청마다 함께 보냄. 비유 — 놀이공원 손목 밴드. 로그인되어 있는 기간 = 세션

흐름 : 이메일 · 비밀번호 입력 → 해시 비교 → 토큰 발급 → 브라우저 보관 → 요청마다 토큰 보여 주고 내 데이터 받기

Supabase Auth가 대신 해 주는 일 : 회원 표 관리, 해시, 토큰 발급 · 갱신, 비밀번호 찾기 메일, 소셜 로그인
우리가 할 일 : 회원가입 · 로그인 화면, 로그인 상태에 따라 화면 바꾸기, 규칙 정하기

# 04. 하네스란? (7분)

- 하네스(Harness · AI 작업 환경) : AI 모델을 둘러싸고 실제로 일을 할 수 있게 만드는 작업 환경 전체. 원래 뜻은 말에 채우는 마구
- 모델 = 엔진 (Claude Opus, Sonnet) / 하네스 = 엔진을 얹은 자동차 (Claude Code)
- 같은 모델이라도 하네스를 어떻게 꾸미느냐에 따라 결과가 달라진다

Claude Code에서 꾸밀 수 있는 것
- CLAUDE.md : 항상 읽는 프로젝트 규칙 파일 — 사내 규칙집 (실습)
- 스킬(SKILL.md) : 필요할 때만 꺼내 읽는 작업 설명서 — 업무 매뉴얼 (실습)
- 권한 : 무엇을 묻고 할지 — 결재 규정 (소개)
- 훅 : 정해진 순간 자동 실행 — 자동 점검표 (소개)
- MCP : 외부 서비스 연결 — 업무용 전화선 (실습, 06번)

강사 메모 — 이 강의 사이트도 약 700줄짜리 규칙 문서(MD/skill.md)를 AI가 먼저 읽고 만든다는 실제 사례를 보여 준다. skill.md는 공식 "스킬" 형식은 아니고 하는 일로 보면 CLAUDE.md에 가깝다는 점도 짚어 준다.

# 05. MCP (5분)

- MCP(Model Context Protocol) : AI 도구가 외부 서비스(카페24, GitHub, 구글 드라이브, Notion)와 연결할 때 쓰는 공통 규격
- 비유 — USB-C 충전 단자. 하나의 규격으로 여러 기기를 연결
- 연결 전 : AI는 내 컴퓨터 파일만. 서버 업로드는 내가 직접 업체 사이트에서
- 연결 후 : "AI SPACE에 배포해줘" → AI가 카페24 MCP 서버에 직접 요청
- 주의 : AI가 내 계정으로 행동할 수 있음 → 공식 MCP 서버만, 승인 창 내용 읽고 허용

# 06. 도메인 · DNS · SSL (8분)

- IP 주소 : 서버의 숫자 주소 (예: 203.0.113.10) — 가게 전화번호
- 도메인 : 사람이 기억하기 쉬운 이름 주소 (mellowbean.com) — 가게 상호
- DNS : 도메인으로 IP를 찾아 주는 시스템 — 전화번호부
- 기본 주소(서브도메인) : 호스팅 업체가 무료로 주는 주소 / 내 도메인 : 1년 단위 구매, 보통 1년에 1~3만 원
- HTTPS : 주고받는 내용을 암호화. 암호화 기술 = SSL(요즘 이름 TLS)
- SSL 인증서 : 이 사이트가 그 도메인의 진짜 주인이라는 증명서 — 사업자등록증. 유효 기간 있음, 요즘 호스팅은 무료 자동 발급 · 갱신
- http = 엽서 (경고 표시, 비밀번호가 보일 수 있음) / https = 봉인된 편지 (자물쇠)
- 로그인을 받는 사이트는 반드시 HTTPS. AI SPACE · GitHub Pages 모두 SSL 자동 적용

# STEP 10. 로그인한 사람만 — 내 단골 메뉴 저장하기

### 프롬프트 05

로그인한 회원이 마음에 드는 메뉴를 "단골 메뉴"로 저장하는 기능을 만들고 싶어.
1. Supabase에 favorites Table을 만드는 SQL을 작성해줘. Column은 id, user_id(로그인한 회원의 ID), menu_id(menus Table의 id), created_at 이야.
2. RLS 규칙을 설정해줘. 회원은 자기 user_id의 단골 메뉴만 보고, 추가하고, 지울 수 있어야 해. 다른 사람의 단골 메뉴는 볼 수 없어야 해.
3. 로그인하지 않은 방문자는 favorites에 아무것도 할 수 없어야 해.
기존 menus Table과 데이터는 수정하지 마.
SQL을 실행하기 전에 어떤 규칙을 만드는지 초보자가 이해할 수 있게 먼저 설명해줘.

### 프롬프트 06

SQL 실행을 마쳤어. 이제 화면에 단골 메뉴 기능을 붙여줘.
1. 로그인한 상태에서는 Menu Card마다 [단골 추가] 버튼을 보여주고, 누르면 favorites에 저장해줘.
2. 이미 단골이면 버튼을 [단골 해제]로 바꿔줘.
3. 로그인하지 않았으면 버튼을 숨겨줘.
Menu Card의 기존 디자인과 다른 Section은 수정하지 마.

### 확인하기 — 계정 두 개로
계정 A로 단골 2개 → 로그아웃 → 계정 B로 가입 · 로그인 → A의 단골이 안 보이면 성공 → Table Editor에서 user_id가 서로 다른지 확인

# 강사용 — 자주 막히는 곳

- 가입은 됐는데 로그인이 안 됨 → Confirm email이 켜져 있는지 확인
- "Invalid API key" → supabase-client.js의 URL · Publishable Key 확인

- 스킬이 목록에 없음 → 폴더 위치(.claude/skills/site-check/SKILL.md)와 맨 위 name · description 확인, 재시작
