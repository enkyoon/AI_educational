# 1교시 — MELLOW BEAN에서 회원이 주문하기

# 01. 오늘 할 일 · 결제는 왜 안 하나 (4분)

오늘 만드는 흐름 : 메뉴에서 [담기] → 장바구니에서 수량 · 합계 확인 → [주문하기] → 주문 완료 화면 → Supabase orders 표에 한 줄
결제는 하지 않는다 — 실제 결제는 결제 대행사(PG) 계약 · 사업자 정보 · 결제 확인 서버가 필요하다. 오늘은 "주문 정보가 서버에 정확히 도착했는가"까지.
(토스페이먼츠 등은 테스트 키로 결제 화면을 연습해 볼 수 있다 — 관심 있으면 혼자 해 보기, 사업자 없이 실제 결제는 불가)
준비물 : DAY 05 프로젝트(로그인이 되는 상태). 없으면 DAY 03 완성 예시 + 프롬프트 01(DAY 05)로 이메일 로그인부터.

# 02. 주문 데이터는 어떻게 생겼나 (5분)

종이 주문서를 떠올리기 : 누가 · 무엇을 몇 개 · 합계 · 요청사항 · 언제 · 상태
| Column | 예 | 뜻 |
| id | 12 | 주문 번호 (자동) |
| user_id | 회원 번호 | 누가 — 로그인한 회원 (DAY 05의 User UID) |
| items | [{"name":"Cream Latte","price":6500,"qty":2}] | 무엇을 몇 개 — 목록을 한 칸에 |
| total_price | 13000 | 합계 |
| request | 얼음 적게 | 요청사항 (빈칸 가능) |
| status | 접수 | 상태 (접수 → 준비 중 → 완료) |
| created_at | 2026-11-20 14:03 | 주문 시각 (자동) |
권한(DAY 05에서 말한 것을 오늘 만든다)
- 로그인한 회원 : 내 주문 넣기 O / 내 주문 보기 O / 다른 사람 주문 보기 X / 주문 고치기 · 지우기 X
- 로그인 안 한 방문자 : 아무것도 X

# 실습 STEP 01
# orders 표 · 접근 규칙 만들기 (10분)

### 프롬프트 01 — Claude Code에 입력하기
MELLOW BEAN에 음료 주문 기능을 만들려고 해. 먼저 Supabase에 orders Table을 만드는 SQL을 써줘.
Column : id(자동 번호), user_id(주문한 회원, Supabase 회원 번호), items(주문 목록 — 메뉴 이름 · 가격 · 수량 목록), total_price(합계, 숫자), request(요청사항, 비어도 됨), status(기본값 '접수'), created_at(자동)
접근 규칙(RLS)도 함께 :
- 로그인한 회원은 user_id가 자기 회원 번호인 주문만 넣을 수 있고, 자기 주문만 볼 수 있다
- 주문을 고치거나 지우는 것은 웹사이트에서 할 수 없다
- 로그인하지 않은 사람은 아무것도 할 수 없다
menus Table은 건드리지 마. SQL을 보여 주기 전에 어떤 표와 규칙을 만드는지 쉽게 먼저 설명해줘.

→ SQL Editor에서 Run → Table Editor에 빈 orders 표
확인 질문 — "왜 user_id를 웹사이트가 아무 값이나 넣지 못하게 막을까?" → 남의 이름으로 주문하는 것을 막으려고

# 실습 STEP 02
# 장바구니 만들기 (12분)

### 프롬프트 02
메뉴 Section의 메뉴 한 줄마다 가격 옆에 [담기] 글자 버튼을 넣어줘.
1. 누르면 장바구니에 담기고, 같은 메뉴를 또 누르면 수량이 1 늘어나
2. 화면 오른쪽 아래에 "장바구니 2" 같은 작은 표시를 두고, 누르면 장바구니 창이 열려
3. 장바구니 창 : 메뉴 이름 · 가격 · 수량 [−][+] · 합계 · 요청사항 입력칸 · [주문하기]
4. 로그인하지 않은 상태에서 [담기]를 누르면 "주문은 로그인 후에 할 수 있어요"와 로그인 링크를 보여줘
메뉴 목록은 지금처럼 Supabase menus에서 불러온 것을 그대로 써. 장바구니는 아직 저장하지 말고 화면에서만 동작하게.
디자인노트.md의 색과 글꼴을 따르고, 메뉴 줄의 기존 모양과 다른 Section은 바꾸지 마.

확인 : 담기 3번 → 수량 · 합계가 맞는지 직접 계산 / [−]로 0이 되면 사라지는지 / 로그아웃 상태에서 담기 → 안내
판단 문제 — 장바구니 창에 그림자를 넣어도 될까? (DAY 03 "하지 않을 것") → 다른 내용 위에 떠 있는 창은 구분이 필요하므로 이유 있는 그림자 하나는 괜찮다. 결정은 이유가 있을 때 바꾼다

# 실습 STEP 03
# 주문하기 → 주문 완료 화면 (10분)

### 프롬프트 03
장바구니 창의 [주문하기]를 누르면 orders Table에 주문을 저장해줘.
- user_id는 지금 로그인한 회원 번호, items는 장바구니 목록, total_price는 합계, request는 요청사항
- 저장에 성공하면 장바구니를 비우고 "주문이 접수되었습니다 · 주문 번호 ○○" 화면을 보여줘
- 실패하면 이유를 한국어로 보여주고 장바구니는 그대로 둬
- 버튼을 두 번 눌러도 주문이 두 번 들어가지 않게 해줘
결제 기능은 넣지 마. 다른 기능은 바꾸지 마.

# Supabase에서 확인하기 · 계정 두 개로 확인하기 (7분)

① 주문 한 번 → Supabase Table Editor → orders → 새 줄 : items · total_price · user_id가 내가 고른 내용과 같은가
② user_id를 Authentication → Users의 내 회원 번호와 비교

④ 로그아웃 → DAY 05에서 만든 다른 계정(이메일 ↔ 구글)으로 로그인 → 주문 → 표에 user_id가 다른 두 줄
⑤ (선택) 브라우저 F12 Console에서 다른 사람 주문을 불러오라고 시켜 보면 빈 결과 — 규칙이 지켜진다

세이브 포인트 : Commit ("회원 주문 기능") → Push

# 04. 하네스와 엔진 (8분)

같은 AI인데 왜 ChatGPT 대화창과 Claude Code가 하는 일이 다를까?
층으로 보기 (그림)
| 층 | Anthropic | OpenAI |
| 회사 | Anthropic | OpenAI |
| 채팅 앱 | Claude | ChatGPT |
| 일하는 앱 (하네스) | Claude Code | Codex |
| 모델 (엔진 · 두뇌) | Claude Opus · Sonnet · Haiku | GPT 모델 |
- 모델 = 엔진. 글을 이해하고 답을 만드는 두뇌. 혼자서는 파일을 열지도, 명령을 실행하지도 못한다
- 하네스 = 엔진을 얹어 실제로 일하게 만드는 차체. 원래 뜻은 말에 채우는 마구. Claude Code가 하네스 — 파일 읽기 · 쓰기, 명령 실행, 규칙 파일 읽기
- 같은 엔진이라도 차체를 어떻게 꾸미느냐에 따라 결과가 달라진다 → 오늘 꾸밀 것 : CLAUDE.md
Claude Code에서 꾸밀 수 있는 것 (오늘 실습은 ①만)
① CLAUDE.md : 대화를 시작할 때마다 자동으로 읽는 프로젝트 메모 — 사내 규칙집
② 스킬 : 필요할 때만 꺼내 읽는 작업 설명서 — 업무 매뉴얼 (.claude/skills/이름/SKILL.md, /이름으로 실행)
③ 권한 · 훅 : 무엇을 묻고 할지 · 정해진 순간 자동 실행 (소개만)
④ MCP : 다른 서비스와 연결하는 통로 (DAY 08에서 개념)

게임을 만들고 싶은 사람에게 — 같은 구조가 게임에도 있다
- 게임 엔진(Unity · Godot · 웹 게임은 Phaser) : 화면 그리기 · 물리(충돌 · 중력) · 소리 · 입력을 대신 처리해 주는 엔진
- 그 위에 내가 얹는 것 : 게임 규칙 · 캐릭터 · 스테이지 — 하네스로 치면 CLAUDE.md에 적는 내용
- 그래서 AI로 게임을 만들 때 "엔진을 정하고(예: Phaser) → 게임 규칙을 CLAUDE.md에 적고 → 한 장면씩" 만드는 것이 오늘 웹사이트를 만드는 방식과 같다
- 이 과정에서는 웹 게임 하나 정도(예: 클릭 · 피하기 게임)를 최종 프로젝트로 해도 된다. 3D · 온라인 대전은 범위 밖
DAY 03의 디자인노트.md · 작업노트.md는 "내가 적고 내가 읽는 메모"였다. 같은 메모를 AI가 매번 자동으로 읽게 하면 CLAUDE.md다.

확인 : 새 대화 → "이 프로젝트에서 지켜야 할 규칙이 뭐야?" → 내가 적은 내용을 말하면 성공

### 작성 틀 ② — 첫 화면 (DAY 03 프롬프트 02와 같은 구조)
CLAUDE.md를 먼저 읽고 그 결정대로 첫 화면을 만들어줘. 파일은 index.html, style.css, script.js.
■ Header : [예: 왼쪽 가게 이름 글자 로고, 오른쪽 메뉴 3개 — 빵 · 예약 · 오시는 길]
■ 첫 화면 : [예: 왼쪽 큰 제목과 설명 두 줄, 오른쪽 대표 사진 / 또는 사진 위에 제목]
■ 들어갈 글 : [실제로 쓸 제목 · 설명 — 준비 안 된 글은 [임시]라고 표시]
