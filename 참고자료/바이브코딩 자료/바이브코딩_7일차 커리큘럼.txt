# Container란?

### Container (컨테이너, 콘텐츠의 전체 너비를 제한하는 영역)

화면이 넓어져도

콘텐츠가 끝없이 좌우로 퍼지지 않도록

전체 콘텐츠의 범위를 잡아주는 영역

### Container가 없는 경우

┌────────────────────────────────────────────┐

텍스트                                      이미지

└────────────────────────────────────────────┘

화면이 넓어질수록 콘텐츠가 너무 멀리 벌어질 수 있음

### Container를 사용하는 경우

      ┌────────────────────────────┐
      │ 텍스트             이미지 │
      └────────────────────────────┘

화면이 넓어도

콘텐츠는 일정한 범위 안에서 유지

---

# Max Width란?

### Max Width (최대 너비)

요소가 커질 수 있는 최대 크기

### 예시

Container

`max-width: 1200px`

### 의미

화면이

1400px

↓

1600px

↓

2000px

로 커져도

콘텐츠 자체는

최대 1200px 정도까지만 확장

### Claude Code 요청 예시

> 전체 콘텐츠가 넓은 화면에서 너무 퍼져 보여.
>
> 주요 Section의 Container에 적절한 Max Width를 적용해줘.
>
> 현재 Section 구조와 콘텐츠는 변경하지 마.

---

# Flexbox란?

### Flexbox (플렉스박스, 요소를 한 방향으로 정렬하는 배치 방식)

요소를

가로

또는

세로 방향으로

정렬할 때 많이 사용하는 방식

### 대표적인 사용

Header

Logo                         Navigation

### 또는

Hero

Text                         Image

### 활용하기 좋은 경우

- Logo + Navigation
- Text + Image
- Button 여러 개
- Card 내부 요소
- 좌우 2열 구조

---

### Mobile

│            IMAGE            │
└─────────────────────────────┘

# Width와 Height

### Width (너비)

요소의 가로 크기

### Height (높이)

요소의 세로 크기

### 예시

Button이 너무 넓음

↓

Width 수정

Hero가 너무 높음

↓

Height 수정

### 요청 예시

> Hero Section이 화면을 너무 많이 차지하고 있어.
>
> 현재 콘텐츠는 유지하면서 Hero의 Height를 조금 줄여줘.

---

# Aspect Ratio란?

### Aspect Ratio (화면 비율)

이미지나 영상의

가로 : 세로

비율

### 예시

1 : 1

정사각형

16 : 9

가로형

4 : 3

일반적인 이미지 비율

### 필요한 이유

Portfolio 이미지마다 크기가 다르면

Card가 들쭉날쭉해질 수 있음

### 요청 예시

> Portfolio Card의 모든 이미지 영역을 동일한 Aspect Ratio로 맞춰줘.
>
> 이미지가 찌그러지지 않도록 object-fit: cover를 사용해줘.

---

# Overflow란?

### Overflow (오버플로, 콘텐츠가 지정된 영역을 넘어가는 현상)

특히 Mobile에서 자주 발생

### 예시

화면

┌───────────────────┐
│               Card│──────────────→
└───────────────────┘

Card나 이미지가

화면보다 넓어짐

↓

가로 Scroll 발생

### 요청 예시

> Mobile 화면에서 가로 Overflow가 발생하고 있어.
>
> 어떤 요소가 화면 너비를 초과하는지 먼저 확인하고 해당 부분만 수정해줘.

---

# Responsive란?

### Responsive Web (반응형 웹, 화면 크기에 따라 Layout이 달라지는 웹페이지)

같은 웹사이트라도

Desktop

Tablet

Mobile

에서

화면 구조를 다르게 보여주는 방식

---

# Breakpoint란?

### Breakpoint (브레이크포인트, Layout이 변경되는 화면 크기의 기준점)

특정 화면 너비를 기준으로

Layout 변경

### 예시

Desktop

3열 Grid

↓

화면이 작아짐

↓

Tablet

2열 Grid

↓

더 작아짐

↓

Mobile

1열 Grid

### 핵심

Responsive는

“모바일 사이트를 따로 만드는 것”

이 아니라

**화면 크기에 따라 기존 Layout을 조정하는 것**

# 오늘의 핵심 용어

### Container (컨테이너, 콘텐츠의 전체 너비를 제한하는 영역)

넓은 화면에서도 콘텐츠가 일정한 범위 안에 있도록 만드는 영역

### Max Width (최대 너비)

요소가 커질 수 있는 최대 너비

### Flexbox (플렉스박스, 요소를 한 방향으로 정렬하는 배치 방식)

가로 또는 세로 방향으로 요소를 배치할 때 사용하는 방식

### Grid (그리드, 행과 열을 이용하는 배치 방식)

Card처럼 반복되는 콘텐츠를 정렬할 때 사용하는 방식

### Gap (갭, 요소 사이의 간격)

Grid나 Flexbox 안의 요소 사이 공간

### Alignment (정렬, 요소를 일정한 기준에 맞추는 방식)

왼쪽, 가운데, 오른쪽 또는 세로 방향으로 요소를 맞추는 방식

### Aspect Ratio (화면 비율)

이미지 등의 가로와 세로 비율

### Overflow (오버플로, 콘텐츠가 영역을 벗어나는 현상)

요소가 지정된 화면이나 영역보다 커져 밖으로 넘어가는 현상

### Responsive Web (반응형 웹, 화면 크기에 따라 구조가 달라지는 웹페이지)

Desktop, Tablet, Mobile에 맞게 Layout이 변화하는 방식

### Breakpoint (브레이크포인트, Layout이 변경되는 화면 크기의 기준점)

특정 화면 너비를 기준으로 Layout을 변경하는 지점

### Testing (테스팅, 기능이 의도대로 작동하는지 확인하는 과정)

구현한 기능의 정상작동 여부를 직접 확인하는 과정

### Debugging (디버깅, 오류의 원인을 찾아 수정하는 과정)

문제의 발생위치와 원인을 찾아 필요한 부분을 수정하는 과정

### Regression (회귀 오류, 수정 이후 기존 기능에 발생하는 새로운 문제)

하나의 기능을 수정한 결과 기존에 정상작동하던 다른 기능이 깨지는 현상
