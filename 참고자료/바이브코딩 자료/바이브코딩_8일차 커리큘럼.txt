# 03. GitHub Pages란? (5분)

GitHub Repository에 저장한 HTML · CSS · JS를 무료로 인터넷에 공개해 주는 호스팅. SSL 자동.

AI SPACE와 비교
- 배포 방법 : MCP로 "배포해줘" / Git Push하면 자동 반영
- 비용 · 기간 : 체험 14일 후 유료 / 공개 Repository는 무료로 계속
- 할 수 있는 일 : 정적 사이트 + 서버 프로그램(PHP · Node.js · Python) · 자체 Database / 정적 사이트만 (Database · 로그인은 Supabase)
- 잘 맞는 경우 : 서버 기능이 필요한 실제 서비스 / 포트폴리오 · 소개 사이트를 오래 공개

# 실습 STEP 05
# 공개 전 안전 점검 (8분)

공개하면 사이트뿐 아니라 Repository의 모든 파일을 누구나 볼 수 있다.
① 비밀 정보 — Secret Key, 비밀번호, 전화번호 · 주소 같은 개인정보 (Publishable Key는 공개되어도 되는 키)
② 첫 페이지가 맨 위 폴더의 index.html인가
③ 경로가 /로 시작하지 않는가 — 주소가 아이디.github.io/저장소이름/ 이라 /images/a.jpg는 깨짐 → images/a.jpg
④ 파일 이름 대소문자 — Windows는 Photo.JPG = photo.jpg, 서버는 다른 파일

### 프롬프트 05
이 프로젝트를 GitHub Pages로 공개하려고 해. 공개 전에 아래를 점검해줘.
1. Secret Key, 비밀번호, 개인정보가 들어 있는 파일이 있는지
2. 첫 페이지가 맨 위 폴더의 index.html인지
3. 이미지 · CSS · JS 경로 중 /로 시작하는 절대 경로가 있는지
4. 코드에 적힌 파일 이름과 실제 파일 이름의 대소문자가 다른 곳이 있는지
문제가 있으면 무엇을 어떻게 고칠지 먼저 알려주고, 내가 허락하면 고쳐줘.

Public 전환 — 무료 계정은 Public Repository만 GitHub Pages 가능. DAY 02에서 Private으로 만들었다면 점검 후 Settings → Danger Zone → Change visibility → Public.

# 실습 STEP 06
# GitHub Pages로 공개하기 (8분)

먼저 Commit → Push.
Repository → Settings → Pages → Source: Deploy from a branch → Branch: main, / (root) → Save → 1~3분 뒤 새로고침 → 주소와 Visit site
주소 모양 : https://내GitHub아이디.github.io/저장소이름/

확인하기 : https · 자물쇠 / 사진이 모두 보임(깨지면 STEP 05 ③ · ④) / Supabase 불러오기 · 저장 / 휴대폰
로그인 기능이 있다면 — Supabase → Authentication → URL Configuration의 Site URL을 GitHub Pages 주소로 (비밀번호 찾기 메일 링크용. 이메일 · 비밀번호 로그인 자체는 그대로 작동)

강사님께 아래 피드백을 받았어.

# 강사용 — 자주 막히는 곳

- Pages 주소가 404 → index.html 위치(맨 위 폴더), Branch · 폴더 설정, 1~3분 대기
- 사진만 깨짐 → / 로 시작하는 경로, 대소문자
- 데이터가 안 불러와짐 → F12 Console 오류 확인, RLS 규칙, Publishable Key
- Settings에 Pages가 없음 / 비활성 → Repository가 Private
- Push했는데 안 바뀜 → Actions 탭에서 배포 진행 중인지 확인, Ctrl + F5
