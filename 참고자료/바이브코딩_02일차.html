Claude에게 코딩을 요청할 때 중요한 점
X (추상적 표현) "홈페이지 예쁘게 만들어줘."
O (구체적 설명) "개인 포트폴리오 홈페이지를 만들어줘.
흰색 배경을 사용하고 상단에는 이름과 메뉴를 배치해줘.
중앙에는 자기소개와 작업물 3개를 카드 형태로 보여줘."
수정할 범위 함께 설명하기: "기존 코드와 디자인은 유지하고 버튼만 수정해줘." / "다른 기능은 변경하지 말고 메뉴 하나만 추가해줘."

  • • 코드를 수정했을 경우 어떤 부분을 변경했는지 설명해줘.

프롬프트 예시

개인 프로필을 소개하는 간단한 웹페이지를 만들어줘. 상단에는 이름과 자기소개를 넣고 아래에는 About, Portfolio, Contact 영역을 만들어줘. 전체적인 디자인은 흰색 배경의 미니멀한 스타일로 구성해줘. 메뉴를 누르면 해당 영역으로 이동할 수 있도록 만들어줘. HTML, CSS, JavaScript는 각각 index.html, style.css, script.js 파일로 분리해서 작성해줘.

Claude가 만들어준 코드 확인하기

모든 코드를 처음부터 이해하려고 하지 않기 — 코드를 받았을 때 파일별 역할 먼저 확인하기

index.html

화면의 구조와 콘텐츠

style.css

색상·폰트·크기·간격·레이아웃 등 디자인

script.js

버튼·메뉴·클릭 등 기능과 동작

코드가 이해되지 않을 때

검색부터 하기보다 Claude에게 코드 설명 요청하기

• "이 코드에서 초보자가 꼭 알아야 할 부분만 설명해줘."

• "이 코드가 화면에서 어떤 역할을 하는지 알려줘."

• "이 부분을 삭제하면 어떤 문제가 발생하는지 설명해줘."

• "어떤 파일을 수정해야 버튼 색상을 변경할 수 있는지 알려줘."

🎯 코드를 직접 모두 작성하는 능력보다 코드를 읽고 필요한 수정사항을 전달하는 능력 익히기

Local / Remote 이해하기

Local: 내 컴퓨터에 저장되어 있는 프로젝트 (VS Code를 이용하여 직접 파일 작성 및 수정하기)

Remote: GitHub에 저장되어 있는 온라인 프로젝트 (인터넷을 통해 프로젝트 보관 및 공유하기)

기본 구조

GitHub (Remote Repository) ↕ Git (내 컴퓨터 Local Repository) → VS Code 작업

💡 핵심 이해: 내 컴퓨터에서 수정했다고 GitHub가 자동으로 항상 변경되는 것은 아님.
Local에서 작업 → 변경내용 기록 → GitHub로 전송 과정 필요!

Pull GitHub에 있는 새로운 변경사항을 내 컴퓨터로 가져오기
GitHub Remote Repository → Pull → Local Repository

Pull : GitHub → 내 컴퓨터

꼭 기억해야 하는 Git 용어

Repository: 하나의 프로젝트와 변경이력을 관리하는 저장공간
Local: 내 컴퓨터에 존재하는 프로젝트
Remote: GitHub에 존재하는 온라인 프로젝트
Clone: GitHub 프로젝트를 내 컴퓨터로 가져오기
Stage: Commit할 변경사항 선택하기
Commit: 현재 작업내용 기록하기
Push: Local의 기록을 GitHub로 보내기
Pull: GitHub의 변경내용을 Local로 가져오기
Remote Repository → Clone → Local에서 작업하기 → Stage → Commit → Push → Remote Repository 업데이트
