# Database를 표로 이해하기

처음 Database를 배울 때는 Excel과 비슷한 표 형태로 생각하기

### Table

하나의 종류의 데이터를 모아두는 표

오늘 만들 Table

`guestbook`

### Column

어떤 정보를 저장할 것인지 정하는 항목

예시)

| id | name | message | created_at |
|---|---|---|---|

### Row

실제로 저장된 데이터 한 개

예시)

| id | name | message | created_at |
|---|---|---|---|
| ... | 김민지 | 포트폴리오 잘 봤어요! | 2026-09-21 |

### 간단하게 기억하기

**Table**

→ 하나의 데이터 묶음

**Column**

→ 어떤 정보를 저장할 것인가

**Row**

→ 실제 저장된 데이터 한 건

# Publishable Key와 Secret Key 이해하기

웹페이지와 Supabase를 연결하려면

Supabase 프로젝트의

**Project URL**

+

**Publishable Key**

필요

### Publishable Key

브라우저와 같은 Client 코드에서 사용할 수 있도록 만들어진 Key

### Secret Key

서버에서 높은 권한으로 사용하는 비밀 Key

### 반드시 기억하기

**Publishable Key**

→ 오늘 웹페이지에서 사용 가능

**Secret Key**

→ HTML / JavaScript 등 브라우저 코드에 절대 넣지 않기

### 중요한 이유

웹페이지의 JavaScript는 사용자가 확인할 수 있음

따라서

Secret Key를 넣으면

↓

**Project URL + Publishable Key**

# STEP 05. 방명록 접근 Policy 설정하기

### RLS가 활성화되어 있는지 확인하기

`guestbook`

Table

↓

RLS 확인

### SQL Editor 열기

아래 내용을 입력하여 실행하기

```sql
alter table public.guestbook enable row level security;

grant select, insert
on table public.guestbook
to anon, authenticated;

create policy "guestbook_public_read"
on public.guestbook
for select
to anon, authenticated
using (true);

create policy "guestbook_public_insert"
on public.guestbook
for insert
to anon, authenticated
with check (true);
```

### 이 코드의 의미

**select 허용**

→ 방명록 읽기

**insert 허용**

→ 새로운 방명록 저장

### 아직 허용하지 않음

update

delete

# 프롬프트 04

> 이제 Guestbook Form의 “방명록 등록” 버튼에 실제 저장 기능을 연결해줘.
>
> 사용자가 입력한 이름은 guestbook Table의 name Column에 저장하고,
>
> 방명록 내용은 message Column에 저장해줘.
>
> 등록 버튼을 클릭하면 Supabase의 guestbook Table에 새로운 Row가 insert 되도록 만들어줘.
>
> 이름이나 메시지가 비어있으면 저장하지 말고 사용자에게 입력이 필요하다는 안내를 보여줘.
>
> 저장에 성공하면 이름과 메시지 입력창을 비워줘.
>
> 그리고 저장 직후 방명록 목록을 다시 불러와 방금 작성한 글이 바로 화면에 나타나도록 만들어줘.
>
> 저장 중 오류가 발생하면 Console에 error를 출력하고 사용자에게도 간단한 오류 안내를 보여줘.
>
> 기존 디자인은 변경하지 마.
